## Why

Specrails' primary audience is **product builders — many without an engineering background**. For them, git must be *invisible*: they should only ever *describe → review → approve*, never see a branch, worktree, merge, rebase, or conflict. Today the platform fails that bar, and worse, its git behavior is **incoherent and self-contradictory** across the two repos and the three providers.

Concretely, as-built (verified against the code):

- **Isolation exists but points the wrong way.** Worktree rails (`SPECRAILS_RAIL_WORKTREES`, default-on) branch off the **implicit current HEAD** — there is no designated base branch anywhere (`CreateWorktreeInput.baseRef` is defined but no caller ever passes it). Merge-back then **auto-integrates each ticket branch into the locally checked-out branch** (`server/merge-manager.ts` `mergeBack` → `git merge --no-ff`). That is *auto-merge into your local main* — precisely what **no** competitor (Codex, Cursor, Antigravity) permits, and exactly wrong for a team whose engineers review PRs.
- **There is no app-owned PR.** No `gh pr create`, no Octokit, no push anywhere in desktop app code. A PR only appears if a user hand-adds a `{{cmd:pr}}` chip and the AI agent runs `gh pr create` at its own discretion.
- **Git ownership is split and per-provider-inconsistent.** `/specrails:implement` (in the separate **specrails-core** repo) is a **competing git owner under Claude** — Phase 4c "Ship" self-runs `git checkout -b feat/…` → commit → `git push -u` → `gh pr create` whenever `GIT_AUTO=true` (the shipped default). Under **Codex and Gemini the same pipeline does zero git** — it only archives the OpenSpec change and flips the ticket to `done`. Same logical command, opposite behavior.
- **The one guard is broken for the collision path.** `git_auto:false` is written **only** by the Jira sync manager, lives in gitignored `.specrails/` (so it is **absent in a fresh `git worktree add`**), and the env redirect (`SPECRAILS_BACKLOG_CONFIG_PATH`) is **not read** by `implement.md`. In a per-ticket worktree, Claude's implement therefore hijacks the branch (`checkout -b feat/…` off the `sr/<slug>/ticket-<id>` branch desktop created), pushes, and opens a rogue PR the app never tracks.

The net effect: no coherent, safe, teachable PR methodology; git is exposed and unsafe for the exact users we most want to protect.

## What Changes

This change establishes a **single, predefined platform methodology** for producing pull requests safely — the same for every loop (built-in and custom) and every provider — and makes git invisible to the product builder.

- **Platform law (predefined, not per-loop configurable).** Every **repo-mutating** loop runs in an isolated worktree, branched from the project's **designated integration branch**, and delivers its result as a **draft PR** from that branch. A loop that only reads (analysis) produces no branch and no PR. The mutating-vs-read-only axis is **derived from the loop's content**, not a user toggle. specrails **never** mutates the working tree, **never** commits to the integration branch directly, and **never** merges or opens a non-draft PR. The human owns the merge.
- **Single git owner = the desktop layer.** Version control and PR opening become a desktop-layer responsibility. specrails-core's `implement` becomes **git-agnostic** (write + verify only) whenever it runs under desktop — the local merge-back is retired; desktop does the commit → push → draft PR from *outside* the run.
- **Designated integration branch per project.** A per-project setting (default = the repo's default branch, e.g. `origin/HEAD`), resolved and **shown to the user before launch**. This is the "certainty of the correct base" the current implicit-HEAD behavior lacks.
- **Cross-repo contract with specrails-core.** Core honors a **provider-invariant suppression signal that travels with the invocation** — an explicit flag (`--no-ship` / equivalently a `SPECRAILS_GIT_AUTO=false` env) parsed in `implement.md` Phase 0 that short-circuits the Ship phase (4c/4d) exactly like `GIT_AUTO=false` — because a config file does not survive into a fresh worktree. Desktop passes this signal on **every** rail invocation, for all three providers. This converges Claude onto the already-git-agnostic Codex/Gemini shape.
- **Two-persona flow.** The **product builder** reviews a plain-language "what changed + proof" bundle and clicks **Approve** (promotes the draft PR to ready + notifies the reviewer). The **engineer** reviews and merges the PR in GitHub via the team's existing process. specrails plugs into the team's git flow rather than owning it.
- **Combined PR for multi-ticket batches.** A batch of N tickets produces **one** combined draft PR with per-ticket traceability (a checklist body + per-ticket commit history preserved). The AI merge-resolver is **repurposed** from "auto-merge into local main" to "combine the ticket branches into one clean integration branch for the PR" — a safe failure mode (fall back to N PRs or flag "needs a human to combine"; never corrupt the base).

Not breaking for the common single-provider, non-isolated user until the integration branch + draft-PR path is opted into per project; the legacy shared-cwd path stays byte-identical where the platform law does not yet apply. The relocation-overlay blocker (a relocated project under isolation loses its `.specrails/` layer) is closed as part of this change because the methodology depends on native `/specrails:*` commands working inside the worktree.

## Capabilities

### New Capabilities
- `safe-pr-workflow`: the predefined platform law (mutating loops isolate + draft PR; read-only loops don't; derived classification), the two-persona review/approve → engineer-merge flow, and the single-git-owner principle. specrails as PR producer, never merge authority.
- `loop-integration-branch`: the per-project designated integration branch — the setting, the resolution order (project setting → repo default → explicit), and the requirement to resolve and display it before launch; kills the implicit-HEAD base.
- `core-git-agnostic-contract`: the cross-repo contract making specrails-core's `implement` git-agnostic under desktop — the provider-invariant `--no-ship`/env signal core honors, desktop passing it on every invocation, converging all three providers, and the retirement of desktop's local merge-back in favor of push + draft PR.
- `combined-batch-pr`: the single combined draft PR for multi-ticket batches — the integration-branch assembly, per-ticket traceability (body checklist + preserved commit history), and the repurposed AI merge-resolver with its safe failure mode.

## Impact

- **specrails-desktop — server (new/modified)**: an app-owned git/PR primitive (branch off resolved base → commit → push → `gh pr create --draft`); `server/worktree-manager.ts` (branch off the designated integration branch, not `HEAD`); `server/rail-isolated-launch.ts` (pass the git-agnostic signal to every `{{cmd:implement}}`/provider spawn; run `{{cmd:implement}}` **per-ticket isolated** — today it is `ticketScope:'all'` and never enters a worktree); `server/rail-merge-orchestrator.ts` + `server/merge-manager.ts` (retire local merge-into-HEAD; repurpose the resolver to assemble the combined-PR integration branch); a per-project integration-branch **setting** (`ProjectSettings` + desktop-db migration); the relocation per-run **workspace overlay** (`server/workspace-manager.ts` — the documented-but-unimplemented follow-up); `server/loop-command-catalog.ts` (retire agent-discretion `{{cmd:push}}`/`{{cmd:pr}}` as the sanctioned path in favor of the app primitive); **hard git guardrails** (block force-push and direct commits to the integration branch — today only soft prompt etiquette).
- **specrails-core (cross-repo)**: `templates/commands/specrails/implement.md` Phase 0 parses `--no-ship` (and/or reads `SPECRAILS_GIT_AUTO`) and short-circuits Phase 4c/4d; reconcile the specialized `backend-developer.md`/`frontend-developer.md` self-commit behavior with the git-agnostic mode; document the signal as a first-class part of the desktop↔core integration contract. Codex/Gemini implement need no change (already git-agnostic).
- **Client**: a plain-language **"Review & Approve"** surface for the product builder (what-changed + verification bundle; Approve = draft→ready + notify reviewer; Discard = close PR + drop branch/worktree); the integration-branch picker in project settings (shown before launch); no raw git vocabulary anywhere in the builder-facing UI.
- **specrails-core coupling**: this change deliberately **is** a small, explicit cross-repo contract (the `--no-ship` signal) — replacing today's implicit, broken, per-provider-divergent behavior. It does not otherwise change how implement writes code.
- **Coverage**: integration-branch resolution, the mutating/read-only classifier, the git-agnostic-signal propagation, and the combined-PR assembly are pure/unit-testable to keep server ≥80% and client ≥80%.
