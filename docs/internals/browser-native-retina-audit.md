# Browser performance and Retina audit

Date: 2026-09-05. Implemented on `feat/codex-gpt-6-astra`.

## Cause

The mission browser opened `BrowserCaptureModal`, which displayed a headless Chromium screencast. Only links opened the existing native browser. Navigation in missions therefore encoded JPEG frames, transferred them through WebSocket, decoded them, and painted them on a canvas; every input went through the reverse path. The default stream had one physical pixel per CSS pixel, so Retina screens enlarged a low-resolution image.

Increasing JPEG quality or setting `deviceScaleFactor` alone does not solve this. The local Chromium experiment confirmed that a context at DPR 2 still emitted 1280×800 screencast frames for a 1280×800 CSS viewport. An ordinary screenshot and an actual native browser can retain the physical pixels.

The user then reproduced a development-browser regression: the streamed page occupied only the upper-left quarter of the pane. The initial Retina change enlarged the compositor surface with `Emulation.setVisibleSize`, but the actual JPEG content still occupied its original dimensions. Checking bitmap dimensions alone missed the white padding. Regression checks now inspect page markers at all four corners of actual screencast JPEG frames, as well as layout, input coordinates and screenshot crops.

## Implemented

- **Native mission browsing on macOS.** `AgentBrowserCapture` checks native capture support before mounting a browser. The supported route uses the real WKWebView; no Playwright session, frame stream, canvas repaint or input relay runs during navigation. The address bar accepts HTTP localhost development servers and remembers the last URL per project.
- **Capture the page the user is actually viewing.** Rust evaluates a fixed selector in WebKit's isolated client world and calls WKWebView's snapshot API. Screenshots preserve the display's backing resolution, including zoom and clipped visible element bounds. There is no second navigation or transfer to another cookie profile. Element selection suppresses page actions, including long presses. Custom application commands are rejected centrally for any webview other than the main app view; this also covers the native page and login popups. Tauri otherwise allowed custom commands without an app ACL manifest, so merely omitting remote capability origins was insufficient.
- **Keep annotations and retry failures.** The native pane is hidden while the shared image editor annotates the captured bitmap, then shown again without reloading when returning to the page. Flattening uses natural image dimensions. Image redaction is opaque in both preview and PNG, avoiding the unsupported canvas blur path in WebKit. Rendering/upload failures retain the editor and its changes instead of silently sending the original uncensored image. Both the native and advanced flows await the attachment destination before closing. Advanced captures run from the pointer event, outside React state updaters, so StrictMode does not execute each capture twice.
- **Scope pane operations to their owner.** Each mount has a distinct owner ID, propagated through commands and events. Open/close calls are serialized; stale cleanup cannot close another pane. Late listeners are released, changed URLs navigate the existing pane, geometry updates are deduplicated, and transient startup probe failures can recover.
- **Correct sizing for advanced capture and fallback.** Both fallback browser surfaces fit their actual containers. The interactive Chromium page keeps its normal CSS viewport and DPR 1. `Page.captureScreenshot` uses `clip.scale` to render PNGs at the host display density, bounded by a 3840×2400 raster budget and scale 2, without changing page state. Its live screencast remains CSS-sized: enlarging the surface with `setVisibleSize` caused the quarter-pane regression; an explicit viewport clip failed after scrolling; changing compositor scale or page DPR altered pointer/wheel semantics. Those approaches were removed. Viewport updates are retained before connection, deduplicated, and follow monitor density changes. Desktop native browsing supplies actual display-resolution rendering without that CDP limitation.
- **Recover the capture transport.** Failed screencast starts release the partial CDP state and can retry; permanently failed streams disconnect clearly. Stale popup frames are ignored. Chromium uses its default graphics path, with an explicit environment opt-out for incompatible drivers.

## Verification

Reproducible checks include:

- `scripts/smoke-browser-rendering.mjs`: isolated local Chromium fixture; full-page coverage at all four corners of real JPEG frames, CSS input and wheel events after resizing/scrolling, and Retina screenshot crops, including fractional density. Half-pixel patterns verify that the 2× PNG retains detail unavailable in an interpolated 1× bitmap. It checks image content as well as dimensions. No production profile or database is used.
- The macOS native browser smoke under `src-tauri`: actual WKWebView snapshots, same-page element selection, long-press suppression, zoom, isolated picker state and stale-owner cleanup. A 900×550 logical view produced a 1800×1100 PNG on the Mac's 2× display. `src-tauri/examples/native-browser-selector-smoke.mjs` uses real WebKit clicks to verify cross-origin iframe selection without activating page buttons, open Shadow DOM, long presses and restored browsing.
- `scripts/smoke-browser-annotations.mjs`: real client CSS and the shared editor in Chromium and WebKit; landscape/portrait Retina images fit the editor, controls remain visible, exported pixels preserve redactions, and encoding failures retain annotations for retry.
- A separate read-only check opened `https://specrails.dev/` with a fresh temporary Chromium profile, the production `PlaywrightPageHandle`, a 1984×1068 CSS viewport and requested capture density 2. The actual streamed JPEG was visually inspected: the page filled the surface and its hero was centered, reproducing the user's page without the quarter-frame padding.
- Frontend regression tests cover native/fallback routing, pane lifetime, deferred listeners, native capture/annotation, stable viewport synchronization, uploads and preservation of annotations after failures. Failed native selector polling releases its input shield; if native cleanup itself fails, the UI keeps the selector active with an error and allows cancellation to be retried.
- Full server/client coverage, TypeScript and production builds passed; coverage thresholds are retained.

Completed checks include full server coverage (282 files, 7,408 tests; 88.32% lines, 78.39% branches, 90.02% functions), full client coverage (354 files, 4,417 tests; 89.24% statements/lines, 83.04% branches, 74.60% functions), plus all 11 native-pane tests after the final selector cleanup fix; all 25 Rust tests and `cargo check --offline --all-targets`; global TypeScript; the production server/client/CLI build; and core compatibility. The Chromium rendering smoke passed all ten size/density/graphics combinations. Native snapshots and selector input were checked with actual macOS WebKit, and the annotation smoke passed in Chromium and WebKit.

The Chromium benchmark reports observed timing on a local synthetic page, not a controlled comparison with Cursor. The architectural change removes the continuous streaming path from native mission browsing; it does not establish identical performance on every website or machine. Native capture is currently macOS-specific; other runtimes keep the compatible Chromium path. This change does not replace the installed signed desktop application.
