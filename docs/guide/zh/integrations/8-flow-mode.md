# Flow：先构建，后写 spec {#flow-mode}

Flow 是在你还不确定自己想要什么时与智能体一起构建的方式。你在任务中与智能体对话，它会在专属的 Flow 分支（项目的独立副本）上编写并运行真实代码；当结果满意时，按 **交给 Rail**：Rail 接手你的更改，推导出 spec，并照常执行验证、评审和交付。

Implement 用于委派你已经能描述清楚的工作，Flow 用于发现它。

## Flow 如何开始

你无需点名要求 Flow。当你描述探索性或视觉性的需求（"我想试试……"、"我不知道它该长什么样"）时，任务会显示一张有两条路径的卡片：

- **Flow**：现在一起构建；spec 最后再写。
- **Spec + Implement**：先商定 spec，再委派给 Rail。

两条路径分量相同，且始终按同样的顺序出现：不推荐任何一条，由你选择。在 **智能体为何询问** 中，智能体用一句话说明它为何询问；无论你选择哪条路径或按 **暂不**，它都不会坚持。

选择 Flow 会打开确认：Specrails 会在专属的 Flow 分支上创建项目的独立副本，智能体可以在其中编写代码，你的主分支不会被改动。按 **开始 Flow**。看板上会出现一个带 **Flow 中** 标签的占位 spec（点击可回到任务）。

如果你的 Specrails Core 还不能运行 Flow，开始按钮会被禁用，卡片会列出缺少的内容。通常更新 Specrails Core 即可解决。

## 从已有规格开始 Flow

不只是新想法，任何规格都可以在 Flow 中构建。Flow 和 Implement 仍是处理规格的两种同等方式：

- 在看板上右键点击规格并选择 **在 Flow 中开始**（与拖到轨道并列）；在规格详情中，**在 Flow 中开始** 位于 **移到轨道** 旁边；
- 在任务中，如果你要求实现某个规格但没有指定轨道，代理会为该规格显示同样的双路径卡片：**Flow** 与你一起处理它，**Spec + Implement** 在轨道上启动它；
- 只包含一个规格的轨道启动卡片，也会在启动按钮旁提供 **在 Flow 中开始**。

规格本身会进入 **Flow 中**：不会创建占位规格，代理的第一轮会收到该规格（验收标准、Contract Layer、范围外事项和未处理的补充说明）。从看板开始时，Flow 会在该规格自己的任务中打开，或在以规格命名的新任务中打开。在有多个 Git 仓库的项目中，如果规格没有恰好指定其中一个，会先弹出一个小对话框询问 Flow 在哪里运行：只列出 Git 仓库，预选规格自己的仓库（否则为主仓库），可用方向键切换选择。当规格已在 Flow 中、已完成或已取消、位于轨道上，或 Flow 不可用时，**在 Flow 中开始** 会被禁用，悬停可看到原因。

**丢弃** 会把规格原样还给你，并恢复之前的状态：你的规格绝不会被删除。Flow 交付时，规格会根据所构建的内容重写；在此之前，原文会先保存为评论 **Original spec before Flow**，不会丢失任何内容。已关联 Jira 的规格会更新同一个问题，并将其移到映射为评审的状态；不会创建第二个问题。

## 在 Flow 中

Flow 模式会在你看的地方以专属的 Flow 颜色标示：输入框在自主度标签旁显示 **Flow** 标签，提示语为 *告诉智能体要在这个 Flow 中修改什么…*；任务标题和任务列表中的对应行都显示 **Flow 中**。对话会标出你进入和离开 Flow 的位置，智能体在 Flow 中写的回复在时间旁带有一个小小的 **Flow** 标记。

输入框正上方的条带用简短的一行显示 Flow：状态、**Flow · 7 个文件**、**暂停 Flow** 和主要操作 **交给 Rail**。当某个操作不可用（Flow 仍在保存、另一操作正在进行）时，悬停即可看到原因。像其他运行一样，用箭头展开这一行即可查看其余内容：

- **分支**（点击复制名称）、带增删行数的 **更改**（点击列出每个更改文件及其状态和 +/−），以及提供商计费的 **目前成本**。在某一轮有上报成本之前显示 `—`，从不显示估算；`*` 表示总额不含未计价的轮次，并附注说明数量；
- Flow 的应用运行时显示 **预览**（见下文）；
- 单独放置的 **丢弃** 会删除 Flow 的更改、其分支和占位 spec。确认框会列出你将失去的内容：带 +/− 的更改文件、分支和 spec。

**暂停 Flow** 会让智能体停下，并保留你的更改和 spec。该行随后显示 **恢复 Flow**。

智能体工作时你也可以输入：在 Flow 中，你的消息会 **打断** 当前步骤（发送按钮变成闪电），智能体会立即带着新信息继续。Flow 打开期间，输入框下方的 git 条会让开：Flow 的面板已经显示了它的分支。

## 试用应用

Flow 智能体会自行运行类型检查和测试来检验工作。有可试用的内容时，它会给出三个选项：**Start the app**、**Start and expose on the local network** 或 **Not now**。对外公开后，你可以在同一 Wi-Fi 或 VPN 的手机上打开应用，该网络中的任何人都能访问。

应用开始监听后，智能体会以链接形式给出地址，Flow 的面板会显示带绿点的 **预览**：在浏览器中打开应用。其菜单包含网络地址和 **停止应用**。应用从 Flow 的副本运行，而不是你的主检出；当你暂停、丢弃或交付 Flow 时，Specrails 会停止它。

## 交给 Rail {#flow-hand-off}

对结果满意时，按 **交给 Rail**。该行变为 **可以变成 PR 了**，并在上方只显示一行：*Rail 2 会把你更改的 7 个文件变成经过评审的 PR。即使失败，你的工作也不会丢失。* 按 **启动**，或按 **暂不** 回到 Flow；**Esc** 等同于 **暂不**；点击别处只会收起这一行，条带仍显示 **可以变成 PR 了** 和 **启动**。如果你对话所用的引擎无法在此设备上运行移交，该行正下方的提示会说明，并改用该 Rail 的默认引擎。

Rail、引擎、模型和推理强度已为你选好（一个空闲的 Rail 和你对话所用的引擎）。如需更改，打开 **更改方式**；那里还会显示更改内容。目前成本显示在主行上。如果你按 **暂不** 之后再次移交，之前的选择会保留。移交启动时，条带会无缝显示启动过程，随后逐步跟踪运行。如果达到评审上限或预算，该行会说明，且不会启动任何内容。如果 45 秒后运行仍未出现，条带会停止转动并显示 **仍在交给 Rail 2…** 和 **刷新**；**刷新** 只会重新检查，并继续等待运行出现。

Rail 会根据你构建的内容推导出 spec 及其 spec 变更，进行验证和评审，交付卡片会像其他运行一样出现在任务中。

如果运行因技术原因失败，工作会自动、完好地回到这个 Flow：卡片会用平实的语言说明失败原因（代码保留在 **技术细节** 中），智能体会收到错误并加以解释。如果评审要求修改，卡片会提供 **回到 Flow** 或 **重新运行**。交付完成后，任务会用一份摘要结束 Flow：PR、根据你构建的内容重写的 spec、已归档的 spec 变更，以及 Jira 工单（如有）。

## 须知

- Flow 只在自己的分支上写入。Flow 之外，任务保持只读。
- 每个任务同一时间只能有一个 Flow。暂停状态在应用重启后仍会保留。
- 如果 Flow 的项目副本消失，Flow 会被标记为 **需要检查**（仅供参考，无需决定），且不会删除任何内容。
- 条带从不切换你正在查看的运行。如果期间有其他运行需要你，它在条带切换器中的名称会显示 **需要你处理**。
- 在 Flow 中或丢弃 Flow 时，Jira 不会收到任何内容。
- Flow 成本会在分析中作为独立的 **Flow** 类别显示，并出现在智能体任务区块中。
