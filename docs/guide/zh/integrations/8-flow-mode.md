# Flow：先构建，后写 spec

当你还不确定自己到底想要什么时，可以用 Flow 和智能体一起构建。你在任务中与智能体对话，它会在隔离的 worktree 中编写并运行真实代码；当结果满意时，点击 **完成了**：轨道会接管该 worktree，推导出 spec，并执行常规的验证、审查和交付。

Implement 用于委派你已经能描述清楚的工作，Flow 用于把它探索出来。

## Flow 如何开始

你不需要点名要求 Flow。当你描述探索性或视觉性的需求（"我想试试……"、"我不知道它该长什么样"）时，任务中会出现一张卡片，提供两条路径：

- **Flow** —— 现在一起构建，spec 在最后生成。
- **Spec + Implement** —— 先确定 spec，再交给轨道执行。

两条路径分量相同，并且始终按同样的顺序出现：不推荐任何一条，由你来选。在 **智能体为何询问** 下，智能体会用一句话说明它为什么询问；无论你选择哪条路径或点击 **暂不**，智能体都不会再坚持。

选择 Flow 后会出现确认：Specrails 会创建一个隔离的 worktree，智能体可以在其中写代码，你的主分支不会被改动。点击 **开始 Flow**。看板上会出现一个带有 **Flow 中** 标签的临时 spec（点击即可回到任务）。

如果你的 Specrails Core 还不支持 Flow，按钮会被禁用，卡片会列出缺少的内容；通常更新 Specrails Core 即可解决。

## Flow 进行中

对话的外观会改变（边缘出现一条细的强调线），输入框上方会出现一个工具栏：

- worktree 的 **分支**、带有增删行数的 **已更改文件**，以及到目前为止 Flow 的 **实际费用**（以提供商计费为准）。在某一轮有报告费用之前显示 `—`，绝不显示估算值；
- 点击 **已更改文件** 可列出每个文件及其状态和 +/−，点击 **分支** 可复制其名称；
- **暂停** 会停止智能体，并保留 worktree 和 spec。之后任务中会显示 **恢复 Flow**；
- 单独放在左侧的 **丢弃** 会删除 worktree、其分支和临时 spec。确认框会列出你将失去的内容：已更改文件及其 +/−、分支和 spec；
- **完成了** —— 主要操作，见下文。当它不可用时（Flow 仍在保存，或有其他操作正在进行），悬停即可看到原因。

智能体工作时你也可以输入：在 Flow 中，你的消息会 **打断** 当前步骤（发送按钮变成闪电图标），智能体会立即根据新信息继续。工具栏显示期间，输入框下方的 git 栏会隐藏：Flow 工具栏已显示 worktree 的分支。

## 试用应用

Flow 智能体会自己运行类型检查和测试来验证工作。有可以试用的内容时，它会给出三个选项：**Start the app**、**Start and expose on the local network** 或 **Not now**。公开后，你可以在同一 Wi-Fi 或 VPN 的手机上打开应用，该网络中的任何人都能访问它。

应用开始监听后，智能体会以链接形式给出地址，Flow 栏会显示带绿点的 **预览**：点击即在浏览器中打开应用。其菜单中有网络地址和 **停止应用**。应用运行在 Flow 的 worktree 中，绝不在主检出目录中；暂停、丢弃或移交 Flow 时，Specrails 会停止它。

## 完成了

对结果满意后，点击 **完成了**。Flow 工具栏和视觉效果会消失，出现熟悉的轨道启动卡片，已预选 **Flow → Spec** 循环并为你选好一条空闲轨道。如有需要可调整引擎、模型或推理强度，然后点击 **启动**。如果已达到审查上限或预算，卡片会说明原因且不会启动。**暂不** 会让你回到 Flow。

轨道会根据你构建的内容推导出 Specrails spec 和 OpenSpec change，进行验证和审查，交付卡片会像其他运行一样出现在任务中。

启动卡片上方会用一行概括交给轨道的内容（文件和行数）以及 Flow 到目前为止的费用。如果运行因技术原因失败，工作会自动、完好地回到此 Flow：卡片会用简单的话说明失败原因（代码保留在 **技术细节** 中），智能体会收到并解释该错误。如果评审要求修改，卡片会提供 **回到 Flow** 或 **重新运行**。交付完成后，任务会用一份总结结束此 Flow：拉取请求、根据你构建的内容重写的 spec、已归档的 OpenSpec 变更，以及（如有）Jira 问题。

## 须知

- Flow 只在自己的 worktree 中写入。在 Flow 之外，任务仍然是只读的。
- 每个任务同一时间只能有一个 Flow。暂停状态在应用重启后依然保留。
- 如果 worktree 消失，Flow 会被标记为 **需要检查**，不会删除任何内容。
- 在 Flow 期间或丢弃 Flow 时，Jira 不会收到任何内容。
- Flow 的费用会在 Analytics 中作为独立的 **Flow** 类别显示，也会出现在智能体任务区块中。
