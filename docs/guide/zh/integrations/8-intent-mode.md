# Intent：说问题，不说方案 {#intent-mode}

写代码已不再是构建软件中慢的那一环。慢的是弄清该构建什么，以及确认它构建得对。Intent 就从这里出发。你写下 **intent**：问题、你想要的结果、如何判断它奏效了、影响谁和什么、约束，以及目前还没人知道的事。你不写方案。Specrails 根据你的 intent 推导出 spec，你只需评审 spec，而不是自己去写。

有了 intent，有两条同等的路径：

- **探索**：在隔离的 Intent 会话（专属分支，项目的独立副本）中与智能体一起构建。结果满意时，由 Rail 根据你构建的内容推导出 spec。
- **委派**：智能体根据 intent 写出 spec，你评审，再由 Rail 构建。

探索用于发现；委派用于构建已经清楚的内容。两者都不被推荐：由你选择。

## intent

一份 intent 有六个部分，没有一部分用来写方案：

| 部分 | 写什么 |
| --- | --- |
| **问题** | 现在哪里不对，对谁，在什么时候最难受。 |
| **期望结果** | 问题解决后什么成立。可选的**假设**写作 *我们相信……会带来……；当……时我们就知道了*。 |
| **如何判断** | 结果已出现的可观察信号（“新用户在 2 分钟内完成设置”）。它们会成为验收标准。 |
| **影响谁和什么** | 人、界面或系统。 |
| **约束** | 任何方案都必须遵守的限制。 |
| **待解决的问题** | 目前还没人知道的事。智能体会去调查，而不是猜测。 |

如果你给出了方案（“添加 Redis 缓存”），intent 会把它的目的（“API 在 200 毫秒内响应”）保留为期望结果，而你的方案则成为约束（你要求必须这样做）或待解决的问题（它只是一个选项）。

每个规格都可以带有 intent。它位于规格详情中描述的上方，你可以在那里编辑每个部分；没有 intent 的规格会显示一个简洁的 **添加 Intent** 操作。编辑时，**保存 Intent** 是主按钮，**Esc** 取消，**⌘/Ctrl+Enter** 保存。每个已回答的待解决问题都会在 **答案** 标签下显示其答案；当没有待解决问题时，标题变为 **问题 · 已回答 N 个**。intent 仍有待解决问题的规格，会在看板的每种视图（便签或行）中显示一个带数量的小指南针标记。intent 和**范围外**一样保留在 Specrails 中，永远不会写入 Jira。

## intent 从哪里来

- **在任务中（默认）。** 当你描述工作时，智能体会像分析师一样向你提问。它会询问用户、限制，以及你如何判断它奏效了，并显示一张 **Intent** 卡片，列出每个部分以及对你请求的两种理解。点击一种理解来回答，或用你自己的话回复。intent 尚未达成一致时，卡片上的每个待解决问题都是一个按钮，点击会把回复预填到输入框中，并有一个标签显示还有多少个待定（如 **N 个待定**）。达成一致后，标签变为 **已达成一致**，两种理解让位于 **理解已确认**，卡片在 **你想如何继续?** 下并排提供 **探索** 和 **委派**；这两条路径在你自己的后续消息之后仍留在卡片上，过长的 intent 会被折叠，可用 **显示完整 intent** 展开。任务首页的 **从一个问题开始** 芯片也会启动这场访谈。智能体据此写出的规格会自动带上 intent。若想在某个任务中跳过 intent 这一步，发送 `#noframe`；`#frame` 会重新开启。
- **在添加 Spec 中。** **Intent** 是第一个模式，默认打开（标有 **默认**）。描述问题，而不是方案；编辑器上方的三个芯片 **问题**、**影响对象** 和 **如何判断** 会插入一行供你填写（*问题：*、*影响对象：*、*我们将在以下情况确认有效：*）。按 **编写 Intent 和规格**：一次 AI 处理就会写出 intent，再写出由它推导的规格，供你评审。Quick、Explore 和 Raw 仍然可用。如果 intent 无法写出，你仍会得到规格（不带 intent），并有通知说明；如果生成失败，你的文字会留在编辑器中。**Raw** 规格现在不带 intent：你可以之后从规格中添加。

## intent 随工作一起传递

- 每个处理该规格的智能体都会先收到 intent，它被标记为*为什么*和*期望结果*的事实依据，绝不是*怎么做*的依据。这包括规划者、开发者、评审者和 Intent 会话智能体。评审者还会对照期望结果和信号来评判工作。
- 当 Rail 交付带有 intent 的规格时，Specrails 会把它作为 `intent.md` 写入该次运行的 OpenSpec 变更中，与提案、设计和任务放在一起。这样 intent 就与代码一起保存在 Git 中。（涵盖多个规格的批量运行不会写入。）

## 探索：开始 Intent 会话

在已达成一致的 intent 卡片上选择 **探索**。会打开一个确认 **与智能体一起探索**：Specrails 会在专属的 Intent 分支上创建项目的独立副本，智能体可以在其中编写代码，你的主分支不会被改动。按 **开始探索**。看板上会出现一个带有你的 intent 和 **Intent 中** 标签的占位规格（点击可回到任务），智能体的第一轮从 intent 开始。

## 从已有规格开始 Intent

不只是新想法，任何规格都可以在 Intent 中构建。Intent 和 Implement 仍是处理规格的两种同等方式：

- 在看板上右键点击规格并选择 **与智能体一起探索**（与拖到轨道并列）；在规格详情中，**与智能体一起探索** 位于 **放入 rail** 旁边；
- 在任务中，如果你要求实现某个规格但没有指定轨道，代理会在 **你想如何继续?** 下为该规格显示双路径卡片：**探索** 与你一起处理它，**委派** 在轨道上启动它；
- 只包含一个规格的轨道启动卡片，也会在启动按钮旁提供 **与智能体一起探索**。

三个入口都会先打开同一个确认：规格标题、intent 摘要、将要工作的引擎，以及仅在有多个 Git 仓库的项目中出现的 **仓库** 选择器（只列出 Git 仓库；预选规格自己的仓库，否则为主仓库；可用方向键切换选择）。在你按下 **开始探索** 之前什么都不会开始；**取消** 会让规格保持原样。从看板菜单进入时，会打开规格详情，并把该确认叠在上面。Intent 开始后，任务会来到前台，并弹出提示 **正在 <branch> 上探索规格 #N**，附带 **打开 Intent 任务**。Intent 分支以规格名称按完整单词命名，最长 48 个字符，绝不在单词中间截断（`feat/1-alta-sin-clave-de-api-proyecto`）。

规格本身会进入 **Intent 中**：不会创建占位规格，代理的第一轮会收到该规格（先是 intent，然后是验收标准、Contract Layer、范围外事项和未处理的补充说明）。从看板开始时，Intent 会在该规格自己的任务中打开，或在以规格命名的新任务中打开。已在 Intent 中的规格会改为提供 **打开 Intent 任务**，便签卡片不再提供 **放入 rail**。当规格已完成或已取消、位于轨道上，或 Intent 不可用时，**与智能体一起探索** 会被禁用，悬停可看到原因。

**丢弃** 会把规格原样还给你，并恢复之前的状态：你的规格绝不会被删除。Intent 交付时，规格会根据所构建的内容重写；在此之前，原文会先保存为评论 **Original spec before Intent**，不会丢失任何内容。intent 本身永远不会被重写：只有其中的待解决问题会补上这项工作所确定的答案。已关联 Jira 的规格会更新同一个问题，并将其移到映射为评审的状态；不会创建第二个问题。

## 在 Intent 中

Intent 模式会在你看的地方以专属的 Intent 颜色标示：输入框在自主度标签旁显示 **Intent** 标签，提示语为 *告诉智能体要在这个 Intent 中修改什么…*；任务标题和任务列表中的对应行都显示 **Intent 中**。对话会标出你进入和离开 Intent 的位置，智能体在 Intent 中写的回复在时间旁带有一个小小的 **Intent** 标记。

输入框正上方的条带用简短的一行显示 Intent：状态、**探索中 · 7 个文件**、**暂停** 和 **交给 Rail**。**交给 Rail** 始终存在，一旦 Intent 分支上有文件被修改，它就成为主要的实心操作；在此之前，rail 仍可以从你的对话中推导出规格。当某个操作不可用（Intent 仍在保存、另一操作正在进行）时，悬停即可看到原因。像其他运行一样，用箭头展开这一行即可查看其余内容：

- **分支**（点击复制名称）、带增删行数的 **更改**（点击列出每个更改文件及其状态和 +/−），以及提供商计费的 **目前成本**。在某一轮有上报成本之前显示 `—`，从不显示估算；`*` 表示总额不含未计价的轮次，并附注说明数量；
- Intent 的应用运行时显示 **预览**（见下文）；
- 单独放置的 **丢弃** 会删除 Intent 的更改、其分支和占位 spec。确认框会列出你将失去的内容：带 +/− 的更改文件、分支和 spec。

**暂停** 会让智能体停下，并保留你的更改和 spec。该行随后显示 **继续**。

智能体工作时你也可以输入：在 Intent 中，你的消息会 **打断** 当前步骤（发送按钮变成闪电），智能体会立即带着新信息继续。Intent 打开期间，输入框下方的 git 条会让开：Intent 的面板已经显示了它的分支。

## 试用应用

Intent 智能体会自行运行类型检查和测试来检验工作。有可试用的内容时，它会给出三个选项：**Start the app**、**Start and expose on the local network** 或 **Not now**。对外公开后，你可以在同一 Wi-Fi 或 VPN 的手机上打开应用，该网络中的任何人都能访问。

应用开始监听后，智能体会以链接形式给出地址，Intent 的面板会显示带绿点的 **预览**：在浏览器中打开应用。其菜单包含网络地址和 **停止应用**。应用从 Intent 的副本运行，而不是你的主检出；当你暂停、丢弃或交付 Intent 时，Specrails 会停止它。

## 交给 Rail {#intent-hand-off}

对结果满意时，按 **交给 Rail**。该行变为 **可以变成 PR 了**，并在上方只显示一行：*Rail 2 会把你更改的 7 个文件变成经过评审的 PR。即使失败，你的工作也不会丢失。* 按 **启动**，或按 **暂不** 回到 Intent；**Esc** 等同于 **暂不**；点击别处只会收起这一行，条带仍显示 **可以变成 PR 了** 和 **启动**。如果你对话所用的引擎无法在此设备上运行移交，该行正下方的提示会说明，并改用该 Rail 的默认引擎。

Rail、引擎、模型和推理强度已为你选好（一个空闲的 Rail 和你对话所用的引擎）。如需更改，打开 **更改方式**；那里还会显示更改内容。目前成本显示在主行上。如果你按 **暂不** 之后再次移交，之前的选择会保留。移交启动时，条带会无缝显示启动过程，随后逐步跟踪运行。如果达到评审上限或预算，该行会说明，且不会启动任何内容。如果 45 秒后运行仍未出现，条带会停止转动并显示 **仍在交给 Rail 2…** 和 **刷新**；**刷新** 只会重新检查，并继续等待运行出现。

Rail 会根据你构建的内容推导出 spec 及其 spec 变更，进行验证和评审，交付卡片会像其他运行一样出现在任务中。

如果运行因技术原因失败，工作会自动、完好地回到这个 Intent：卡片会用平实的语言说明失败原因（代码保留在 **技术细节** 中），智能体会收到错误并加以解释。如果评审要求修改，卡片会提供 **回到 Intent** 或 **重新运行**。交付完成后，任务会用一份摘要结束 Intent：PR、根据你构建的内容重写的 spec、已归档的 spec 变更，以及 Jira 工单（如有）。

## 须知

- Intent 只在自己的分支上写入。Intent 之外，任务保持只读。
- 每个任务同一时间只能有一个 Intent。暂停状态在应用重启后仍会保留。
- 如果 Intent 的项目副本消失，Intent 会被标记为 **需要检查**（仅供参考，无需决定），且不会删除任何内容。
- 条带从不切换你正在查看的运行。如果期间有其他运行需要你，它在条带切换器中的名称会显示 **需要你处理**。
- 在 Intent 中或丢弃 Intent 时，Jira 不会收到任何内容。
- Intent 成本会在分析中作为独立的 **Intent** 类别显示，并出现在智能体任务区块中。
