# 从任意 AI 操控 Specrails（MCP 服务器） {#mcp-server}

Specrails 可以把**自己**暴露给任何会说 [Model Context Protocol](https://modelcontextprotocol.io) 的 AI 助手——Claude Desktop、Claude Code、Cursor、Cline，或者你自己的 agent。打开这个功能，把你的助手指向 Specrails，你就能靠聊天来驱动整个应用：*「列出我的项目」「在 API 项目里为社交登录创建一份规格」「启动 rail 0，跑完了告诉我」「我这周花了多少钱？」*。你的助手会在幕后调用 Specrails 的工具，而不用你点来点去。

这和插件以及「My approved MCPs」功能的方向正好相反：那些功能是让 Specrails 去*使用*别的 MCP 服务器；而这个功能是让别的应用来使用 **Specrails**。

## 开箱即用

它**默认是开启的**——第一次打开应用时服务器就已经在运行，无需重启，也不用拨任何开关。打开 **Settings ▸ MCP** 可以复制客户端配置，或者在不需要时把它关掉。

通过一组权限层级，你可以始终掌控外部 AI 能透过它做*哪些*事：

| 层级 | 它允许什么 | 默认 |
|---|---|---|
| **Read** | 列出并查看项目、规格、任务、分析数据等等…… | 始终开启（在 MCP 启用时） |
| **Write** | 创建和编辑规格、修改设置与 rail 配置 | 开启——取消勾选即可限制 |
| **AI-spawn** | 会运行 AI 并**产生费用**的操作（启动一条 rail、生成一份规格、发送一次聊天） | 开启——取消勾选即可限制 |
| **Destructive** | 删除项目 / 规格 / 任务，停止正在运行的工作 | 开启——取消勾选即可限制 |

四个层级默认全部授予，所以接入的助手一开始就能驱动整个应用。把你想自己保留的层级取消勾选即可；之后如果助手试图做该层级涵盖的事，Specrails 会拒绝，并给出一条清晰的提示，告诉你该重新打开哪个层级。

## 一步连接 Claude Code 或 Codex

打开 **设置 ▸ MCP**，点击 Claude Code 或 Codex 旁边的 **连接**——或者在终端里运行一条命令：

```bash
specrails-desktop mcp connect --client claude   # 或 codex
```

Specrails 会把自己加入客户端自己的配置，先备份该文件，不在任何地方写入访问令牌，并立即检查连接（你会看到它找到了多少个工具）。重复运行也没有问题。之后开启新的 Claude Code 或 Codex 会话。如果你想自己运行，**复制命令** 会给出客户端自己的命令；其他助手请使用 **复制配置**。

如果有什么不正常，运行 `specrails-desktop mcp doctor`。它会一次性检查所有环节（应用、访问令牌文件、桥接程序及运行它的 Node、每个客户端的配置项，以及一次真实连接），并给出每个问题的解决办法。它只做检查，不会修改任何东西。升级 Node 之后（例如通过 Homebrew），如果助手找不到 Specrails 了，再点一次 **连接** 即可。

**花费前先询问**（同一面板，默认 0.50 美元）是一个金额：已连接的助手启动的付费工作超过它时，必须先询问你。合并、PR 和删除总是会先询问。你的助手会得到一组简洁的 15 个工具：附带现成的下一步，无需轮询即可等待，用你的语言回答，还有 *start-my-day*、*review-waiting*、*ship-milestone* 和 *why-stuck* 等提示词。如果你的旧脚本需要之前的工具，在同一面板关闭 **精简版 MCP 工具** 即可；Specrails 自己的任务不受影响。

每个决定都会以简短菜单的形式交给你：各个选项及选择后会发生什么，推荐项排在最前，最后一项是“其他——写下来”。你可以用键盘输入编号（或选项），也可以用自己的话回答。如果你的客户端能显示自己的表单，Specrails 会直接在那里询问你；会合并、打开 PR 或花钱的选项仍然需要你确认。

## 仅供 agent 阅读：连接你的客户端

当有人请 agent 连接时，请阅读 [MCP 连接手册](https://github.com/fjpulidop/specrails-desktop/blob/main/docs/agents/mcp.md)。它涵盖一条命令连接、在 Claude Code 和 Codex 中手动注册、验证和故障排查。仅完成注册并不能证明已连接：请完成 `initialize`、`tools/list` 和一次只读调用。

想快速了解全局，助手会调用 `specrails_overview`：一次调用就能看到正在运行什么、什么在等你处理、最近的失败、今天的花费以及本机的 CPU 和内存。`specrails_inbox` 读取并回复 **待处理** 收件箱，`specrails_missions` 列出你的任务并给它们发消息，`specrails_specs` 和 `specrails_rails` 显示某个项目的待办和轨道，`specrails_insights` 显示你的花费和限额，`specrails_wait` 会等待执行结束，而不是一遍遍地询问。失败的执行会附带诊断和日志末尾。

每个回答都以一段简短的大白话摘要和可行的下一步开头，并标出推荐的那一步；错误会说明出了什么问题，以及重试是否有用。在任何不可撤销的操作或超过你限额的付费工作之前，助手会先给你看预览并征求同意。你的同意只对那一个操作有效，期间情况一旦变化就会失效。

操作前，助手可以通过 `specrails_overview` 了解某个项目的当前状况：规格、执行任务和 Git 状态。无法获取的部分会明确标出，并不代表项目是空的。它还能搜索并逐行阅读你的源代码，而不会修改它。

每个外部 MCP 会话独立保存所选项目。在任务模式中，默认使用会话中固定的项目，需要在任务界面修改；MCP 的项目选择不能覆盖它。在调用中指明另一个项目，就是有意针对那个项目。

## 你能用它做些什么

连上助手后，这里有几个上手的小配方。一切默认开启；如果你暂时只想让它观察，就在 Settings ▸ MCP 里取消勾选 **Write** 或 **AI-spawn**。

**把你其他工具里的工作变成规格。** 如果你的助手还连着 GitHub、Jira、Gmail 或 Slack，它就能替你把这些工作搬进 Specrails：
> *「把本周打了 'bug' 标签的开放 GitHub issue 拿过来，在 API 项目里为每个创建一份规格，然后启动它们。」*
>
> *「读一下我最近的客户反馈邮件，按主题分组，每个主题创建一份规格。」*

**通宵自动驾驶。** 让应用待在托盘里跑着，回来时就能拿到一份报告：
> *「这里有 12 个点子。把每个变成一份规格，在 rail 上每次三个地启动它们，盯着每一个任务，明天给我一份总结：哪些完成了、哪些失败了、各花了多少钱。」*

取消勾选 **Destructive**，它就能跑一整夜而绝不会删掉任何东西。

**横跨你所有的项目。** 这是 dashboard 自己做不到的事：
> *「检查我所有的项目。告诉我哪些在 backlog 里有规格却没有 rail 在跑，并在每个项目里启动优先级最高的那一个。」*

**写代码时不用动手。** 从你的编辑器里或用语音来驱动 Specrails，无需切换窗口：
> *「用 Opus 在 rail 0 上为 spec #42 启动，跑完了告诉我。」*

**询问费用和历史。** 用大白话查你的分析数据：
> *「我这周在 AI 上花得最多的是哪里，按项目、按模型分别列出来？给我看最贵的五个规格。」*

**你的每日站会。**
> *「帮我写站会汇报：昨天哪些 rail 跑了、哪些完成了、哪些失败了、总花费多少——做成可以直接粘进 Slack 的要点列表。」*

**读懂代码。** 不需要编辑器：
> *「spec #38 改动了哪些文件？用一句话总结每个文件改了什么。」*

因为你的助手会先读那份内置指南，所以你很少需要点名具体的工具或规格——描述你想要的结果，它就能算出该调用哪些工具。

## 几点须知

- **Specrails 必须在运行。** MCP 服务器活在应用内部，所以只有在 Specrails 开着的时候，你的助手才能连上它。多亏了托盘，关掉窗口它仍会在后台运行——只有从托盘（Mac 菜单栏 / Windows 系统托盘）选择 **Exit**，才会真正把它停掉。
- **长任务会流式返回。** 启动一条 rail 或生成一份规格会立即返回，并在后台完成；你的助手可以「盯着」它，等它尘埃落定再回来报告。
- **安全。** MCP 使用它自己专属的访问令牌，与其他一切都分开，并且只监听你自己的机器（本地回环）。这个令牌无法通过提供层级、项目或会话请求头来冒充代理模式：内嵌的 agent 使用的是一种由服务器签发、私有且短期有效的能力凭证。你随时可以从面板里复制或重新生成这个限定范围的令牌。
- **未暴露的部分（v1）。** 出于安全考虑，外部 MCP 客户端不能执行原始的终端 shell 命令、使用内嵌浏览器、在应用内编辑文件，或安装系统先决条件。代理模式有一条单独的、经过身份验证的通道，用于在 Autonomous 权限下执行已确认的长时间后台命令；外部客户端无法通过启用 Destructive 来获得它。其余一切*管理* Specrails 的能力都开放可用。

你随时可以从同一个面板禁用 MCP——你的助手只是会失去访问权，其余一切照旧。
