# Spec 与 backlog {#specs-backlog}

**spec** 是 AI 流水线要实现的工作单元。你可以把它想象成一张工单：包含标题、一段对需求的描述、优先级，以及可选的标签。当你启动流水线时，AI agent 会读取这份 spec 并据此行动——所以一份清晰的 spec，是决定结果好坏的最重要输入。

在应用里，spec 有时也被称作 **工单**——这两个词指的是同一样东西。

## 看板

每个项目打开后都会停留在 **Dashboard** 上，那里展示的就是 **SpecsBoard**——项目里所有 spec 的列表。这就是你的 backlog。你可以在这里创建新的 spec、设置优先级、把它们拖到某条 rail 上去实现，并随着工作的推进看着它们的状态发生变化。

看板有两种视图模式，通过工具栏上的切换按钮选择，并会按项目分别记住你的选择：

- **便签视图**（默认）——卡片样式的方块，附带简短摘要。
- **列表视图**——紧凑的单行行式布局。

Spec 工具栏分为两行。第一行包含 **搜索** 框（按 `/` 即可跳到这里；可按标题、`#编号`、标签或 Jira 键搜索）、一个统一的 **筛选** 按钮、排序与视图控件，以及 **新建 Spec**。第二行是 **状态选择器**：每种状态都是带实时计数的独立分段，另加两个智能分组：**活跃**（默认视图：一切仍在推进中的内容，即草稿、待办、进行中和评审中）和 **全部**（所有内容，完成的固定在底部）。列较窄时，不常用的状态会收进 **更多** 菜单，而你选中的状态始终可见。你的选择会按项目记住并同步到 URL，刷新或分享链接都能还原完全相同的视图。**筛选** 会打开一个面板，每个维度一节：**标签**（多选），在连接了 Jira 的项目上还有 **史诗**、**冲刺** 和 **Jira 状态**（看板*真实*的工作流状态，例如 "Code Review"，按其映射到的状态分组，并与状态选择器叠加生效）。当搜索或筛选缩小了看板范围时，第三行会把每个条件显示为可移除的标签，显示“x / y”个 Spec，并提供 **全部清除**（保留你选中的状态）。排序可选 **默认**、**工单 #** 或 **优先级**，每一种都带有升序/降序切换。

### 选择多个规格

可以批量整理,而不必一个个处理。在获得焦点的卡片上按 `x`,按住 `Ctrl`/`⌘` 点击卡片,或按住 `Shift` 点击来选择一个范围(范围只在一列之内:进行中的规格或“已完成”分组)。`Ctrl`/`⌘`+`A` 选中你所在的整列,`Esc` 取消选择。鼠标悬停或获得焦点时,每张卡片会显示一个复选框,已选中的卡片边框会高亮。在搜索框中输入时,这些按键不会生效。

只要选中了一个规格,看板底部就会浮出一条操作栏,显示数量和可用操作:

- **移至**:更改状态。本地规格使用本地状态;来自 Jira 的规格使用 Jira 看板真实的工作流状态,并和单个移动一样经由同一个 Jira 队列。
- **标签**:为所选规格添加标签,或移除规格已有的标签。
- **优先级**:为全部规格设置同一个优先级。
- **加入轨道**:把所选规格放到某个轨道上。
- **全部启动**:为每个所选规格分配各自的空闲轨道并并行启动,事先经过与轨道上*全部启动*相同的确认和每日预算检查。暂时无法启动的规格(例如处于评审中但没有打开的 PR)或找不到空闲轨道的规格会被跳过,并在汇总中计数。
- **删除**:移入*最近删除*。
- **取消选择**(或 `Esc`):放弃选择。

删除以及状态、标签、优先级的更改可以一步撤销:一条*撤销*提示(或 `⌘Z`)即可恢复它改动的所有规格。如果部分失败,一条提示会说明成功和失败的数量。选择中只包含你能看到的规格:筛选条件若隐藏了某个已选规格,它就会从选择中移除。

### 已保存的视图

**筛选**旁边的**视图**按钮会保存看板当前的样子:状态选择、筛选、排序和密度(不含搜索文本)。选择**保存当前视图…**,为它命名(如“可以启动”“冲刺 42”“本周失败”),之后在同一个菜单里选用。**管理视图…**可以重命名视图、用当前看板更新它、复制它的链接或删除它。视图属于项目。复制的链接(`?view=…`)在本应用中打开时会应用该视图,命令面板(`⌘K`)也可以保存当前视图或切换到另一个视图。

## 状态

一份 spec 会在一小组状态之间流转。看板为每种状态都设计了统一的视觉标识，让你一眼就能读懂整个 backlog 的状态：

| 状态 | 含义 |
|--------|---------------|
| **草稿** | 从一次 Explore 对话中保存下来的、仍在打磨中的想法。还没准备好实现——你随时可以回来继续雕琢。会显示一个 `Draft` 标签。 |
| **待办** | 可以开工了。一份完成的 spec 创建后就落在这个状态。 |
| **进行中** | 流水线正在处理它（一个跳动的蓝点）。 |
| **评审中** | 已实现——每次运行结束后，spec 都会停在这里等你确认：合并草稿 PR，或自己把它移走（一个琥珀色标签）。 |
| **完成** | 已通过——PR 已合并，或你自己把它移到了这里（一个绿色对勾）。 |
| **已取消** | 已放弃（一个红色 X）。 |

草稿和待办的 spec 共处于同一个活跃区域里——并没有单独的列——但它们带有一圈淡淡的着色边框和一个 `Draft` 标签，所以很容易辨认。关于草稿的完整介绍，请参阅 [草稿与 Contract Layer](drafts-and-contract-layer.md)。

## 优先级

每一份非草稿的 spec 都有一个优先级：**紧急**、**高**、**中** 或 **低**。优先级纯粹是一个组织工具——它帮你决定接下来先实现哪一项，也让你可以据此为看板排序。你在创建 spec 时设置它，之后随时可以右键点击 spec 卡片、选择 **设置优先级** 来更改。

草稿是唯一的例外：草稿可以*完全没有*优先级，因为它还只是一个进行中的想法。当你把草稿提交为正式 spec 时，优先级才会被确定下来。

## 创建一份 spec

要创建 spec，点击 **新建 Spec**（SpecsBoard 工具栏上的加号按钮）。**添加 Spec** 对话框会打开，提供几种工作方式：

- **Quick 模式**——你描述需求，AI 一次性写出完整的 spec。参见 [添加 Spec — Quick 模式](add-spec-quick-mode.md)。
- **Explore 模式**——你与 AI 对话，它会一轮一轮地帮你打磨 spec。参见 [添加 Spec — Explore 模式](add-spec-explore-mode.md)。
- **Raw 模式**——你输入什么，就原样保存成 spec，全程不涉及 AI。当你手头已经写好了 spec 文本时，用它最合适。

具体选哪一种，取决于你的想法已经多清晰了。完全清楚自己要什么？用 Quick。还在琢磨？用 Explore。文本已经写好了？用 Raw。

## 附录：在现有规格上迭代

当一个规格已经有了成果（评审中的 PR、已合并的功能）而你还想要*更多*时，不要重写它的描述：那会让规格偏离原意（并把偏离同步到 Jira），还会迫使下一次运行重新规划一切。打开规格，改为添加一条**附录**：一条简短说明，带有类型（变更请求、评审反馈、澄清、约束）和你自己的话。待处理的附录会自动随该规格在任何循环上的下一次启动传递（Implement、SDD Quick、Freestyle），运行只改变你要求的内容，评审包会把每条附录报告为已应用、部分应用或受阻。如果运行失败或你丢弃了交付，它们会自动回到**待处理**。当你让任务智能体修改现有规格时，它可以替你添加附录。

## 审查交付：先看哪里

运行结束后，评审包会以 **需要关注的地方** 开头：这是 AI 评审者的简短摘要，先列出风险最高的位置（按高、中、低排序，每项都带文件和行号），然后是会变化的行为、此次改动所依赖的规则、没有任何测试覆盖的代码路径，以及只能由人完成的检查。同样的风险、未测试路径和检查也会以简短区块出现在拉取请求顶部，任务卡片会用一行显示首要风险。该摘要只是审查参考，不是验证结果，永远不会阻止“接受”。使用旧版 Specrails Core 的运行没有摘要，其评审包保持原样。

## 撤销与最近删除 {#recently-deleted}

删除规格、将其移到另一个状态、修改标签或把它从 Rail 上移除，都会立即生效——不会先问“确定吗？”。取而代之的是，一条提示会在大约八秒内提供**撤销**，在你没有在输入框中打字时，也可以按 **⌘Z**（Windows 和 Linux 上为 **Ctrl+Z**）。撤销以项目为单位：切换项目会关闭该时间窗口。

被删除的规格（以及被删除的任务）并没有消失。它会进入项目设置中的**设置 → 最近删除**，你可以在 30 天内**恢复**它，或**永久删除**（这一步会先确认）。30 天后将被彻底移除。放弃未推送的工作、强制关闭拉取请求以及移除项目仍会先确认，因为它们无法撤回。与 Jira 关联的规格仍然通过**移至**处理，而不是直接删除。
