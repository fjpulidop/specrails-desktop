# 分析与成本追踪

每当 Specrails 替你运行一次 AI CLI——无论是一个流水线任务、一个 Quick spec、一段 Explore 会话、一次 AI 编辑，还是一份文件摘要——它都会记录下发生了什么：用了哪个模型、输入和输出了多少 token、耗时多久、花了多少钱。**分析**（Analytics）板块把这一切汇总成一个统一的仪表盘，让你随时清楚自己的 AI 开销都花在了哪里。

从右侧边栏打开它（标签写作 **分析**）。你看到的所有内容都只针对当前所在的项目——切换项目，数字也会随之切换。

## 什么算作支出

项目中的每一次 AI 调用都会被计入：流水线 job 和循环步骤、spec 撰写、文件摘要、侧边聊天、失败诊断，以及当 agent 固定到该项目时你与它进行的任务（mission）和 Intent 回合。主页上的任务（未固定任何项目）不属于任何项目，不计入这里。

每次调用都会打上产生这笔支出的*来源*（surface）标签，而每个来源都属于五个**类别**之一，类别说明了这笔钱*为什么*花：

- **实现**——用轨道、循环和 job 构建 spec。
- **任务**——与 agent 对话以及 Intent 模式（任务回合、Intent 回合和 Intent 的 spec 重写）。
- **规格**——撰写和打磨 spec：Quick 和 Explore spec、优化、拆分、spec 启动器、提案和分诊。
- **代码**——解释代码：文件摘要和文件故事。
- **支持**——安装、诊断和侧边聊天：失败分析、安装、Agent Studio 和聊天侧边栏。

## 读懂仪表盘

整个页面自上而下的阅读顺序是：*花了多少 → 花在什么上、为什么 → 什么时候 → 用了哪些模型 → 每一次调用*。

### 花了多少（Hero）

顶部那个醒目的大数字，就是你在所选时间段内的总支出，旁边还带一个**较上期**的对比值，让你一眼就能看出相比上一个时间窗口是在涨还是在降。当所有引擎都使用订阅套餐时，这个数字会标注为*按 API 计价的等值估算*：即这些调用按 API 价格计算的费用，而不是实际扣费的金额。如果你才刚开始使用某个项目，空状态会告诉你追踪是从什么时候开始的。

### 钱花在了哪里

每个类别一行，显示它的成本、占总额的比例、调用次数和 token 数，以及一句话的原因说明。柱条中带斜线的部分是估算成本（来自不原生上报成本的引擎）。展开一个类别可以看到它由哪些来源组成，点击其中一个即可把整个页面筛选到该来源。任务类别还会列出你最花钱的那些对话。

### 每日时间线

一张按天展示支出的堆叠柱状图，并按来源拆分，任务使用自己专属的颜色。没有活动的日子会显示为零，而不是被跳过。要看清一批昂贵的运行*是什么时候*跑的，这是最快的方式。

### 预算

你的每日、每周、每月和单次运行上限、月末预测，以及“假设”重新计价（见下文）。

### 引擎和模型

按引擎划分的支出（仅在使用多个引擎的项目上显示），以及按支出排序的常用模型。点击任意模型，就能把整个仪表盘筛选到只看那一个模型。

### 热门规格

把*所有*来源合在一起后，最烧钱的十个 spec，所以一个在 Explore 里花了一点、在 job 里花了很多的 spec，会显示出它真正的总开销。任务回合不关联任何 spec，因此不会列在这里。

### 原始调用表

最底层的事实：一行对应一次调用。**原因**列显示来源及其类别；任务和 Intent 的行会显示它们所属的对话。这个区块有自己的二级筛选器，只作用于表格本身。

### 更多细分

默认折叠：做出决定和合并所需的时间、循环经济性、成本 vs 轮次散点图，以及 Quick vs Explore 对比。

## 筛选

顶部的吸顶标题栏带着主要筛选器——**时间段**、**类别**以及（在多引擎项目上的）**引擎**——而且它们都会被存进页面 URL，所以你可以把一个筛选后的视图收藏或分享出去（"最近 30 天，仅任务"）。把鼠标悬停在类别标签上可以查看它涵盖的内容。可以在*钱花在了哪里*卡片中（或通过 URL 中的 `?surface=`）选择单个来源；标题栏中会出现一个可移除的标签来显示它。原始表格的筛选器是独立的，只对那一个区块生效。

关于准确性的一点说明：失败和已中止的运行会被排除在*成本平均值*之外（否则它们会拉偏每次运行的数字），但它们仍会计入你的总运行次数和失败率。这样平均值保持干净，而可靠性的全貌也保持完整。

## 单个 spec 的成本

你不必非得来到分析页面才能看到一个 spec 花了多少钱。打开任意 spec，如果它附带了任何支出，你就会在标题正下方看到一行小结：

> $0.42 · 6 turns · 1m 12s active · breakdown

点一下它，你就会落到已经针对该 spec 筛选好的分析页面。从"这个功能花了我多少钱？"到完整明细，这是最快的路径。

## 所有项目 {#all-projects}

要查看跨所有项目的全貌，请从左侧边栏或命令面板打开**分析**。它显示总成本、job 数和成功率、成本随时间的变化，以及每个项目一行，并使用与项目页面相同的五个类别和颜色。任务和 Intent 回合计入每一个数字。不属于任何已加载项目的回合，例如主页上的任务以及 Blueprint 或 Builder 聊天，会归入同一行 **主页与 Blueprint**，按 agent 回合而不是 job 计数。估算成本以 `~` 标记，与项目页面一致。

## 导出你的数据

当你需要把这些数字拿到应用之外——做表格、写财务报告、或自己分析——就用 **Export** 下拉菜单。它提供四种格式：

- **摘要 CSV**——一个多区段文件，包含总计、每日时间线、按类别、按来源、按模型，以及热门规格。
- **摘要 JSON**——同样的摘要，结构化呈现。
- **原始 CSV**——每一行调用记录（最多 10,000 条；如果不得不截断会有注明）。
- **原始 JSON**——同样的原始记录，结构化呈现。

导出会遵循你当前应用的时间段、类别和来源筛选，文件命名也方便合理排序：`<project>-analytics-<period>-<date>.csv`。当没有任何东西可导出时按钮会被禁用，而如果下载失败，你会收到一条清晰的错误提示。

## 保持实时

你不用刷新。当项目中任何地方记录了一次新调用，正打开着的仪表盘会在稍后悄悄自我重新拉取一次，这样燃烧表就能跟上正在收尾的工作。

## 每日上限 {#daily-budget}

设置每日预算，限制一天最多能花多少。所有上限（每日、每周、每月和每次运行）都在同一处编辑：**分析 → 预算**。**设置 → 高级**和**项目设置 → 预算**只显示当前的每日上限，并提供**打开预算**按钮跳转到那里。

当当天记录的花费达到预算时，队列会自行暂停，轨道和循环运行会拒绝启动并提示*已达到每日预算*，正在进行的循环运行会在步骤之间停下，因预算而暂停。提高或清除预算，或等待每日重置，然后继续。仅因每日预算而暂停的循环运行会在每日重置时自动恢复（项目预算按本地午夜，全应用预算按 UTC 午夜），只要有空闲容量就会继续，并在其日志中注明；这也包括应用关闭期间跨过午夜而暂停的运行，它会在应用启动时恢复。你暂停的运行，或仍受其自身单次运行上限（或每周、每月上限）限制的运行，会继续等待你。可在**设置 → 高级 → 每日重置时恢复因每日上限而暂停的运行**中关闭此功能。

两种预算都按你的本地日期计算，并且都包含任务的花费：项目预算计入固定到该项目的回合，全应用预算计入所有回合。在应用中的任何地方——状态栏、分析和各项上限——“今天”都指你的本地日期。单个 job 的费用提醒是另一项独立设置。

**每周、每月和单次运行上限.** 更长周期的上限工作方式相同。打开**分析 → 预算**，可按项目或针对整个应用设置**每周**和**每月**上限，以及**单次运行软上限**（*达到 $X 时暂停并询问*）。每周从周一开始，每月从 1 日开始，按你的本地时间计算。每周或每月上限与每日预算完全一样：暂停队列、拒绝启动，并让正在运行的循环暂停；可在此调高或清除，也可等待重置。已经开始的步骤无法中途停止，因此单次运行上限会在**每个 AI 步骤之前**检查，依据是该步骤通常的花费：它在同一次运行中之前的花费；若没有，则取它在本项目中使用同一模型的近期运行的中位数；再没有，则按价目表估算同类步骤的典型花费。当下一步放不下时，运行会在该步骤之前暂停并说明原因（*已在 Developer 之前暂停：该步骤通常花费约 $0.45，单次运行上限 $0.40 还剩 $0.12*）；此时**恢复**会提供**仅运行这一步**（之后上限再次生效）、取消上限后继续或调高上限。自身上报的成本达到上限的运行也会以同样方式暂停。这些都是估算：花费远超平常的步骤仍可能突破上限。达到任何上限还会在收件箱中添加一条**调高上限**。

预算面板会把今天、本周和本月与各项上限对照显示。月末**预测**只是估算（最近 14 个完整日的平均值乘以剩余天数，再加上已花费金额），不会与已结算的花费相加。**假设**会按应用的价格表，用另一个模型重新计算最近 30 天记录的 token 用量；对没有价格的模型会显示*没有价格*。订阅套餐下每次使用没有美元成本，因此面板显示回合数和套餐额度，而不是美元。
