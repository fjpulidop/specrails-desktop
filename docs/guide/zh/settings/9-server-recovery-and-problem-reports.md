# 如果本地服务器停止运行 {#server-recovery}

Specrails 会在你的电脑上运行一个小型服务器，负责运行你的项目、rail、任务和终端。桌面应用会监控它，并在它停止时将其恢复。

## 服务器停止时会发生什么

- **Specrails 会自动重启它。** 服务器会在同一地址恢复，打开的窗口会自动重新连接；状态栏会显示几秒钟 **重新连接中…**。
- **横幅会说明发生了什么**：服务器何时停止以及原因（退出代码或信号）。当时正在运行的工作可能已被中断：请检查其状态，必要时重新运行。
- **每分钟最多重启三次。** 如果服务器持续停止，Specrails 会停止重启以免掩盖问题，并显示一个对话框。选择 **Try again** 立即启动它，或退出并重新打开 Specrails。已保存的项目仍保留在磁盘上。
- **下次启动时也会说明。** 如果在服务器停止期间关闭了 Specrails，下次打开时会显示横幅。

阅读后在横幅上选择 **关闭**；这些停止不会再次提示。

## 报告问题 {#report-a-problem}

**报告问题** 会在你的电脑上保存一个 ZIP，帮助他人了解出了什么问题。不会上传任何内容：是否分享、与谁分享由你决定。

打开方式：

- 横幅上的 **报告问题**，
- **设置 ▸ 关于 ▸ 报告问题**，
- 命令面板（**⌘K**）中输入 *报告问题*。

保存之前，窗口会列出报告中的每个文件并显示其内容。ZIP 中的内容与你看到的完全一致：

| 文件 | 内容 |
| --- | --- |
| `README.txt` | 报告说明以及每个文件的内容 |
| `system.json` | 应用和 Core 版本、操作系统、内存 |
| `settings.json` | 应用设置，不含令牌、密钥、密码、环境变量值和请求头 |
| `server.log` | 当前服务器自启动以来的输出 |
| `sidecar-stderr.log` | 服务器最近的错误输出，包括之前已停止的运行（桌面应用） |
| `desktop.log` | 服务器启动、停止和重启的时间（桌面应用） |
| `crashes.json` | 每次意外停止及其最后的错误行 |
| `stalls.json` | 服务器无响应的时刻 |

令牌、API 密钥、密码、私钥和 URL 中的凭据会被替换为 `***` 或 `[REDACTED]`，你的主文件夹显示为 `~`。尽管如此，分享前请阅读这些文件：其中可能出现你认为私密的项目名或文件名。

## 响应性 {#responsiveness}

状态栏中的 **应用资源** 弹出面板还会显示 **响应性**：发生了多少次延迟（应用在 200 ms 或更长时间内无法响应的时刻）、其中最长的一次，以及最近一次发生的时间。频繁的长时间延迟值得提交一份问题报告，其中包含技术细节。
