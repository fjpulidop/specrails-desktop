# 项目环境

有些项目在运行时需要凭据，例如私有 npm 包所需的 `NODE_AUTH_TOKEN`。在 **项目设置 → 环境** 中，添加你的 rail 和 loop 需要的变量**名称**。Specrails 只保存名称，从不保存值。

## 值从哪里来

运行开始时，Specrails 会从它启动时的环境中读取每个已配置的名称。如果你从 Dock 或 Finder 打开 Specrails，该环境不包含你的 shell 配置文件导出的内容，因此 Specrails 还会从你的登录 shell（例如 `~/.zprofile` 或 `~/.zshrc`）读取缺失的名称。请把真实凭据放在 shell 配置文件中，而不是仓库里。

检查会在项目打开时、你修改名称时以及之后定期在后台进行，因此较慢的配置文件不会拖慢你的运行。值只保存在该项目的内存中。

## 如何阅读状态标签

每个已保存的名称都会显示一个标签：

| 标签 | 含义 | 处理方式 |
|------|------|----------|
| **已继承** | Specrails 启动时就带有该变量。 | 无需处理。 |
| **来自登录 shell** | Specrails 从你的登录 shell 读取到了它。 | 无需处理。 |
| **未定义** | 你的登录 shell 没有导出它。 | 在 shell 配置文件中添加 `export`。 |
| **Shell 超时** | 你的登录 shell 启动时间过长。 | 精简配置文件，或调高 `SPECRAILS_LOGIN_SHELL_TIMEOUT_MS`（默认 10 秒）。 |
| **Shell 读取失败** | Specrails 无法读取你的登录 shell。 | 修复配置文件，或从终端启动 Specrails。 |

将鼠标悬停在标签上可查看说明。修复配置文件后，点击 **重新检查**，无需重启 Specrails。

如果运行开始时仍有名称未解析，其日志会显示一行 `[environment]`，写明变量和状态。运行仍会开始。值从不会出现在应用、日志或 MCP 工具中。

在 Windows 上，Specrails 只使用它启动时的环境。
