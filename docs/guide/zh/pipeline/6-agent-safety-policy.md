# 智能体安全策略 {#agent-safety-policy}

轨道、循环和任务中的智能体在执行每条命令前都不会询问你。这让它们很快，但有少数操作风险太大，不能交给智能体自行决定。Specrails 会在 **Claude** 智能体的每次工具调用执行之前，将其与一份简短的禁止清单对照，并阻止清单上的调用。

## 阻止什么，以及原因

| 阻止 | 原因 |
|---|---|
| **强制推送**（`--force`、`--force-with-lease`、`+branch`、`--mirror`） | 会改写共享的历史。 |
| **推送到集成分支**（项目的默认分支、`main` 或 `master`） | 工作只能通过由人合并的拉取请求进入该分支。 |
| **删除远程分支** | 分支随交付一起清理，而不是由智能体删除。 |
| **在运行分支之外执行 `git reset --hard`** | 在运行内的运行分支上允许；在其他地方可能毁掉别人的工作。 |
| **删除受保护的分支、运行自身的分支或运行之外的分支** | 同样的原因。 |
| **合并拉取请求**（`gh pr merge`） | 合并什么由你决定。 |
| **在运行之外递归删除**（`rm -rf`、`rimraf`、`find -delete`、`git clean -f`） | 只能清空运行的工作树和临时文件夹。目标无法确定的删除（`rm -rf "$DIR"`、`xargs rm -rf`）也会被阻止。 |
| **读取或写入凭据**：`~/.ssh`、`~/.aws`、`~/.gnupg`、钥匙串以及 Specrails 的密钥存储 | 智能体从不需要你的密钥。 |
| **修改策略自身的文件** | 防止智能体关闭策略。 |

其他一切照常运行。

## 你会看到什么

- 智能体会收到原因，并在不执行该操作的情况下继续，或说明它需要什么。
- 运行日志或任务中会显示一行 **已被 Specrails 策略阻止**，附带规则和原因。
- [智能体操作审计](3-reviewing-a-delivery.md)会在尝试的操作旁记录每次阻止（来源 `policy-hook`）。

## 适用范围

- 隔离的轨道、循环和 Intent 会话（各自在独立的工作树中运行）以及任务。
- **仅限 Claude。** Codex 没有 Specrails 可以在不更改你自己 Codex 配置的情况下安装的等效机制；对于 Codex 运行，Specrails 会在每个轮次后继续检查分支和交付。
- 直接在你的项目文件夹中工作（未隔离）的运行不在覆盖范围内：Specrails 从不写入你自己的检出目录。
- macOS 和 Linux。Windows 上暂不安装该策略。

## 须知

- 这是护栏，而不是沙箱。它能拦住常见的破坏性命令，但不能让恶意智能体变得安全。
- 如果检查本身失败，调用会继续执行，除非它看起来属于禁止清单：此时会被阻止。损坏的检查永远不会让所有智能体停下。
- 如需在紧急情况下关闭，请使用 `SPECRAILS_AGENT_POLICY_HOOK=false` 启动 Specrails。
