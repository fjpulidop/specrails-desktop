# Loop Builder

**一条 rail 运行的是一个 Loop。** 内置的那些 loop（`Implement`、`Batch`、`Freestyle`）覆盖了日常场景，但 **Loop Builder** 让你能设计自己的——一个可视化的、n8n 风格的编辑器，用来做那种"重复执行直到目标达成"的自动化。本页会讲清楚什么是 loop、怎么搭一个，以及怎么在 rail 上运行它。

## Loop 与 rail——它们的关系

一个 **loop** 是干活的*配方*；一条 **rail** 是拿这个配方去跑你那些 spec 的*通道*。

```
   Loop Builder (左侧栏)                   Rails (右)
   ───────────────────────────             ─────────────
   Implement   (内置)                       Rail 1
   Batch       (内置)          在此挑选 ►       Loop: Verify-until-green
   Freestyle   (内置)                          ▶ Play
   Verify-until-green (你的)
```

- loop 住在 **Loops** 区里（左侧栏，和你的项目并列）——它们是**全局**的，跨所有项目共享。
- 一条 rail 在它的头部（Loop 选择器）**挑一个 loop**，按下 Play 时就运行它。
- 是 **rail** 决定提供方、模型和推理强度——而*不是* loop 的步骤。同一个 loop 跑在 Claude、Codex 还是 Gemini 上，取决于这条 rail。

所以：一个 loop 只需搭一次，之后就能在任意项目的任意 rail 上挑来用。

## 打开 builder

点左侧栏的 **Loops**，就能看到这个库：三个内置 loop，再加上你自己的所有 loop。打开一个来查看，或者点 **New loop** 从一张空白画布开始。

你没法轻易地直接编辑内置 loop——而是要 **Fork** 它。这会给你一份可编辑的副本，从一个能跑通的图出发，这也是最容易上手的学习方式。

## 一个 loop 由什么组成

一个 loop 是一张由**边**（也就是那些箭头）连接起来的**节点**图。每个节点就是一个步骤：

| 节点 | 作用 |
|------|--------------|
| **Start** | 运行从这里开始。每个 loop 恰好一个。 |
| **AI Step** | 跑一个 AI 回合——你写的一段提示词，或者像 `{{cmd:implement}}`、`{{cmd:verify}}`、`{{cmd:fix}}` 这样的*魔法命令*。真正的活儿就发生在这里。 |
| **Shell** | 跑一个 shell 命令（例如 `npm test`），并把它的输出捕获下来供后续步骤使用。 |
| **Loop Decider** | loop 的大脑。每跑一遍，它都会读你写的一个**目标**，然后决定是 **continue**（绕回去再试一次）还是 **stop**（退出）。正是它驱动着 *verify → fix → verify 直到全绿* 这套流程。 |
| **End** | 一个终结节点。把这次运行标记为成功或失败。 |

边按顺序把各个步骤连起来。**Loop Decider** 有两个带标签的输出——**continue** 和 **stop**——所以你把"还没完"接回到活儿里去，把"完成了"接出去到一个 End。

### 编写步骤文本

在任意 AI Step 或 Decider 里，你都可以引用：

- **spec 数据**——`{{spec.title}}`、`{{spec.description}}`、`{{spec.ids}}`（这条 rail 的工单 ID）。运行时从 rail 上的 spec 里填入。
- **魔法命令**——`{{cmd:implement}}` 之类会展开成对应的流水线命令。
- **常量**——`{{const:NAME}}` 从全局**常量库**里取值（从调色板里拖进来）。像验证用的 PASS/FAIL 标记这样的内置哨兵始终可用；你也可以加自己的，并在每个 loop 里复用它们。

## 给 loop 设个边界

一个永不停止的 loop 会一直烧钱，所以每次运行都有三道护栏（在 builder 的工具栏里设置）：

| 护栏 | 作用 |
|-------|--------------|
| **Max iterations** | 不管 Decider 怎么裁决，它最多能绕回多少次的硬上限。 |
| **Timeout (min)** | 整次运行的挂钟时间上限。 |
| **Max cost ($)** | *可选。* 一旦累计成本越过你的预算就停掉 loop。它在**步骤之间**检查（一个步骤的成本只有等它结束才知道），所以可能会超出一个步骤。在 Claude 上成本是精确的；在 Codex 和 Gemini 上是估算值。留空就表示不设上限。 |

## 有把握地搭建

builder 会帮你在 loop 真正跑起来之前就把它弄对：

- **实时校验**——各种问题（没有 Start、孤立的步骤、空的提示词、分支缺失的 Decider）会在画布上和问题面板里被标出来。
- **Dry-run 预览**——解析出每个步骤的确切文本（spec 数据、常量、命令全都展开），但**不启动任何东西**，让你精确看到每个步骤会发送什么。
- **Auto-arrange**——把画布按垂直、水平或网格整理一下；你的选择会按 loop 分别保存。
- **复制 / 粘贴**——用 `Cmd/Ctrl + C` / `V` 在 loop 内部或跨 loop 复制步骤。
- **导入 / 导出**——把 loop 存成一个 `.json` 文件，再导回来（重名的会被跳过，其余的照常导入）。
- **重命名步骤**——给每个节点起一个自定义标签，让整张图读起来更清楚。

## 发布与运行

一个 loop 起初是一份 **Draft**。当图有效时，**Publish** 它——只有已发布的 loop 才会出现在 rail 的 Loop 选择器里。（Unpublish 可以把它撤出流通，但不删除它。）

要运行一个自定义 loop：

1. 打开一个项目，把一个 spec 拖到一条 rail 上。
2. 在 rail 头部打开 **Loop 选择器**，挑你那个已发布的 loop。
3. 按下 **▶ Play**。

这次运行会在 **Jobs** 视图里实时流式呈现，指标与成本追踪和任何 rail 任务一样——而它的日志则拥有一个专属的**步骤浏览器**：一张图的实时地图，每个步骤一个可折叠的盒子，并随 loop 推进跟随正在运行的步骤（见[任务详情视图](the-job-detail-view)）。在 Claude 上，每个 **AI 步骤**同样是一场实时会话：从任务详情的输入框给它发消息，在步骤进行中给它指方向（步骤之间输入框会短暂等待，**结算此步骤**则让 loop 带着该步骤的产出继续前进）。一个因为撞到迭代上限或成本上限而停下的 loop，会以那个结果来上报，而不是报成一个干脆的成功。

> **loop 运行时请留意。** 当某个 loop 的某次运行正在执行时，你没法编辑或删除这个 loop——先把那次运行停掉。
