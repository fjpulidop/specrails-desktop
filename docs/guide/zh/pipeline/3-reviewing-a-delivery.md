# 在应用中评审一次交付 {#review-a-delivery}

待评审的交付有两个视图：**概览**（结论、证据和决策按钮）和**变更**（交付实际改了什么）。从交付的**评审**按钮打开评审，然后选择**变更**。

## 阅读变更

左侧的文件列表显示每个变更文件的状态（新增、修改、删除、重命名）、`+` 和 `−` 的行数，以及你标记为已查看后出现的对勾。右侧的差异一次只加载一个文件，因此大型变更也保持流畅。可在**统一**和**分栏**布局之间切换，Specrails 会记住你的选择。特别大的文件会先显示开头的若干行，并提供**加载完整的文件差异**；二进制文件会标明为二进制。

变更从交付与基础分支分叉的位置开始计算，因此之后合入基础分支的内容不会出现。如果交付还没有合并后的分支，你可以选择读取哪个规格的分支。

## 评审员对代码的批注

评审员的发现、它标出的风险，以及本次运行要解决的评审评论，会显示在它们所指的那一行下面。没有指明文件或行的批注会列在文件列表上方，因此不会被隐藏。较早的交付，以及没有指明位置的评审员，会在该列表中显示其发现。

## 让智能体修改某处

点击行号选择行（按住 Shift 点击可扩大范围），选择**请智能体做出修改**并描述修改。Specrails 会把它作为评审反馈保存到规格中，附上文件、行范围和所选代码，并显示一条带有规格链接的消息。之后针对该规格的运行会收到它。若要立即开始运行，请使用概览中的**请求修改**。这里没有人与人之间的评论线程；请在 GitHub 上与团队讨论。

## 在你的编辑器中打开

**在编辑器中打开**会在 VS Code、Cursor 或 JetBrains IDE 中打开该文件并定位到所选行。请在**设置 → 代码 → 编辑器**中选择编辑器。文件从你本地的项目副本打开，评审分支可能没有在那里检出。

## 选择交付结果的去向 {#pr-decision}

完成的运行只会问你一件事：如何处理它的结果。卡片上有一个用于下一步的主按钮（创建 PR、发布或验证），旁边是 **审阅**，用于打开通俗易懂的审阅包。其余操作都收在 **更多操作** 中：

- **检出分支** 会把分支放进你的项目文件夹，方便你试用。
- **本地集成** 会在这台电脑上把结果合并到基础分支。无需 GitHub，且会先请你确认。
- **丢弃** 会删除结果及其分支，同样会先请你确认。

如果某个操作失败，通知会说明哪件事没能完成，并提供 **重试**。

## 键盘

| 按键 | 操作 |
| --- | --- |
| `j` / `k` | 下一个 / 上一个变更文件 |
| `n` / `p` | 下一条 / 上一条评审员批注 |
| `v` | 将文件标记为已查看 |

在输入框中输入时，这些按键会被忽略。“已查看”仅对你自己可见；如果文件在之后的修订中发生变化，它会显示**自你查看后已更改**，并重新算作未查看。
