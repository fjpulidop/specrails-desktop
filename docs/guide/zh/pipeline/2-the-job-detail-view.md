# 任务详情视图

在 **Jobs** 页面点击任意一张任务卡片，你就来到了这里：观察单次 rail 运行的"驾驶舱"。它围绕一个承诺打造——**你看到的实时数字都是真实的，绝不是猜出来的。** 本页会带你逐一了解各个阶段、实时指标、spec 卡片——以及那个让你**和运行中的任务对话**的输入框。

## 布局

紧凑的头部保留状态、耗时、阶段、操作和流水线标签。紧接其下的是**一行导航**，汇集了你可以查看的所有内容：

- **失败原因**——带有诊断的失败或取消运行会显示此项，并默认选中。可回答的待处理问题也会使其出现：点击头部的问题按钮即可跳转并作答，即使没有诊断。
- **执行图**和**日志详情**——用于 loop 运行，分别是工作流的图和逐步的日志。
- **日志**——用于普通任务，即流式日志。

标签旁只显示该运行确实具备的标签片：运行记录了验证证据时显示 **验证**（附检查数，使用其状态颜色），点击即可查看各项检查及其输出；有真实指标时显示 **详情** 按钮（柱状图图标）。两者都以弹出层打开，因此日志始终占满全部高度。你上次选择的日志区块会分别为页面和任务窗口记住；所选标签在每次访问时重置。

### 运行指令

在运行仍能读取指令时，日志底部固定着一个单行输入框：写下代理需要注意的事项，然后点击发送按钮或按 **⌘↵**（**Ctrl+Enter**）。**Enter** 换行。**ⓘ** 说明了规则：指令会在代理的下一个兼容回合应用，不会回答问题或授予批准。已发送的内容会以标签片显示在输入框旁——*1 条排队中*、*2 条已应用*——并列出每条消息及其状态。运行结束后输入框消失；收到过指令的历史运行会在标签旁保留只读的标签片。

在桌面应用中，从任务（mission）中打开的 job 会显示在**它自己的窗口**里，每个 job 一个窗口。按 **Escape** 或关闭窗口即可返回；浏览器版本则在弹窗中显示相同内容。

## 流水线阶段

对于 `Implement` 任务，整个运行会走过 slash 命令所定义的各个阶段——默认是：

```
Architect ──► Developer ──► Reviewer ──► Ship
```

每个阶段都是一个专门的 Agent，由 rail 的引擎在你的项目目录里调起：

| 阶段 | Agent | 作用 |
|-------|-------|--------------|
| **Architect** | `sr-architect` | 规划实现方案。 |
| **Developer** | `sr-developer` | 编写代码。 |
| **Reviewer** | `sr-reviewer` | 审查产出。 |
| **Ship** | （视情况而定） | 收尾：测试、提交、起草 PR。 |

每个阶段由哪个 Agent 来处理，是由项目的 **Agent Profile** 决定的。基线三人组（`sr-architect`、`sr-developer`、`sr-reviewer`）始终在场；Profile 里的路由规则可以添加 Agent，或替换某个阶段由谁来跑。只有当命令确实定义了阶段时，阶段进度条才会出现——绕过流水线的任务（例如图库中的 Freestyle loop）不会显示进度条。

## 实时指标——为诚实而设计

紧凑的头部显示状态、耗时、活动、步骤和操作。真实指标和继续执行的说明可从标签旁的 **详情** 按钮打开：

| 指标 | 何时能看到真实值 |
|--------|------------------------------|
| **时长** | **实时。** 任务运行时有一个 1 秒一跳的计时器在往上加——这是唯一一个货真价实的实时数字。 |
| **轮次** | 随着流式 assistant 事件陆续到达，逐步累加得出。 |
| **Token** | 从同一条流里逐步聚合（对缺少 usage 字段的事件也能容忍）。 |
| **成本** | 在任务结束前显示为 `—`，结束后揭晓为权威的 `total_cost_usd`。 |

设计原则是：**运行途中绝不给近似值或估算值。** 时长之所以真实，是因为它不过就是一个时钟。轮次和 token 是从真实的流式活动里累加出来的。成本则是故意*不*在运行时估算的——它显示为待定，只有当提供方在任务结束时上报后，才会落定为最终的、权威的数字。如果某个数字看起来像在等待，那是有意为之——给你看的是真相，而不是预测。

头部的标签和图标会映射到任务的状态，并且这个面板对 `running`、`completed` 和 `failed` 的任务一视同仁地渲染——所以一个已完成任务的详情视图，会把这些指标定格在它们的最终值上。

## spec 卡片

**spec 头部**坐落在状态头部和日志之间。这是一张高级感的身份卡片，为这个任务触及的每个 spec 显示一枚 chip——它们是从启动命令里匹配出来的，因此精确反映了本次运行究竟是关于哪些 spec 的。

- **2–3 个 spec**——以一列 chip 的形式显示。
- **4 个及以上**——折叠成一个紧凑的 `+ N more` 模式，带一个展开的箭头，让头部保持整洁。

点击某枚 chip，会在**任务页面之上**打开该 spec 的详情——你不会丢失当前位置，也不会跳转路由。这是在你观看任务运行的同时，快速重读一遍"这个任务应该交付什么"的便捷方式。（在平板宽度的屏幕上，你甚至可以把一个 spec 弹窗拖到一旁，把两个 spec 并排对比。）

## 流式日志

打开**日志**（普通任务）或**日志详情**（loop 运行）查看流式日志；启用叙述时也可选择 Story。原始输出通过 WebSocket 实时传输：

- **自动滚动**让最新的输出始终在视野内（往上滚就会暂停，方便你阅读）。
- **搜索**可以跳到某个短语。
- **复制**可以一把抓走整个日志。

这就是 AI 正在做什么的原始真相——每一次工具调用、每一次文件编辑、每一次测试运行。

## Loop 运行：执行图与步骤日志

对于 **loop 运行**（见 [Loop Builder](the-loop-builder)），有两个选项卡展示运行的证据。

**执行图**展示工作流实际的运行情况。它始终展开，并跟随正在运行的步骤，或失败的那一步：

- **走过的路径是实线。** 运行经过的步骤以实线绘制；从未到达的步骤以虚线淡化显示。打开**仅显示已走路径**可隐藏其余部分。图例直接显示在图中。
- **检查某个步骤。** 选中一个节点即可列出它的各次尝试及其状态和耗时。点击某次尝试，可在日志详情中打开它的日志。**从此处重复**位于每次已完成尝试的那一行，因此关联的运行会恰好从你选中的那次尝试开始。技术 id 位于**追踪**下。

**日志详情**包含步骤轨迹和日志，并在失败的那一步打开：

- 顶部的**步骤条**只按顺序列出运行到达过的步骤，右侧有迭代计数器（`迭代 3/10`）。芯片在等待时暗淡，运行时闪动，结束后打上对勾或叉号；决策器的芯片还会显示它据以路由的裁决。点击芯片即可跳到该步骤。
- **每个步骤一个可折叠的盒子。** 对某个节点的每一次执行都会成为独立的一节，带有步骤编号、名称、迭代徽章、完成后的耗时——还有它自己的复制按钮，让你恰好拿走这一步的输出。（工具栏上的复制仍然拿走整份日志。）在第一步之前打印的内容——运行横幅、worktree 提示——会收进一个**准备**小节。
- **跟随模式**默认开启：正在运行的步骤保持展开并自动滚动，之前的步骤则折叠让路。一旦你向上滚动或打开旧步骤，跟随会暂停以便阅读——浮动的**恢复跟随**胶囊把你带回实时画面。**全部展开 / 全部折叠**在工具栏里，而在搜索框输入会同时搜索所有步骤。
- **中断的步骤同样诚实。** 一个从未来得及报告结果的步骤——运行被取消，或应用在步骤中途退出——会以虚线边框标记为**已中断**，而不是假装它完成了。

启用叙述时，Story 位于日志详情之中。切换选项卡会保留执行图的探索状态和已暂停的日志滚动位置。

## 和运行中的任务对话

每个 Claude 任务默认都以**实时会话**的方式运行，所以本页底部——以及任务模式下的任务弹窗底部——都有一个聊天输入框。用它向运行中的 Agent 提问（"那个测试为什么挂了？"），或者在运行途中给它指方向（"跳过重构，专心修 bug"）。

几件值得知道的事：

- **消息会排队，不会打断。** 在 Agent 流式输出时发送，你的消息会等着轮到自己——作为下一个 prompt 执行，任务继续按它的计划推进。一个小计数器会显示有多少条消息在排队。
- **总计行是真实的。** 输入框会显示一条实时的 `N 轮 · $X` 摘要，由每个已完成轮次的真实用量累加而来——和本页"绝不猜数字"的承诺一致。
- **会话有两种结束方式。** 大多数任务**自己收尾**：一旦某轮结束且没有排队的消息，会话就自行落定、任务完成——你的消息是可选的引导，从来不是义务。一个低调的**立即收尾**操作可以提前结束它，保留到目前为止产出的一切。较早的 **Freestyle** 任务（来自 Freestyle 变为图库 loop 之前）是例外：它们在轮次之间待命，直到你点击 **Finalize**——这正是它的设计，一场由你来关闭的往返会话。
- **loop 运行中，消息会送到活跃的步骤。** 在内置或自定义 loop 上，你的消息会到达**此刻正在运行的 AI 步骤**。步骤之间（Loop Decider 思考时，或 shell 命令运行时）输入框会短暂显示*"等待下一步……"*状态——你草拟的文字会保留，下一个 AI 步骤启动时发送会重新可用。**结算此步骤**可以提前结束当前步骤，让 loop 带着它的产出继续前进。

## 诊断导出

如果该任务启用了[遥测](../settings/pipeline-telemetry-and-diagnostics)，头部会出现一个**导出诊断**按钮。它会下载一个 ZIP，里面包含：

- `job-metadata.json`——命令、状态、Profile、插件。
- `telemetry.ndjson`——未压缩的 OTLP/JSON 信号。
- `logs.txt`——完整的流式日志。
- `summary.md`——人类可读的要点摘要。
- `profile.json`、`plugins.json`——本次运行内容的精确快照（存在时）。

无论是和队友分享一次运行，还是提交一份精确的 bug 报告，都很顺手。

## 运行失败时

对于带有诊断的失败或取消任务，**失败原因**会以**诊断卡片**打开，说明原因，并在已知时解释为什么会发生。如果运行时记录了是哪一步失败的，卡片会写明：步骤、尝试、迭代和时间。可能的原因有：

- **测试失败**：经过修正轮次后，检查仍然失败。
- **提供商限额** — 已达到 AI 提供商的用量限额。提供商报告了确切时间时，卡片会按你的本地时间显示重置时间，否则使用提供商的原话。仍在限额处暂停的运行会显示自己的卡片：何时自动恢复、**立即恢复** 以及 **立即改用** 其他提供商 **继续**。参见 [用量限额](1-rails-and-jobs.md#usage-limits)。
- **环境**：机器无法运行检查（凭据、缺少的工具、失败的准备命令）。*修复环境*会准确显示要运行或修改的内容。
- **端口被占用**：运行自身的检查或服务器无法启动，因为另一个进程已占用其端口（`EADDRINUSE`）。这不算作测试失败。每个运行 worktree 都会通过 `PORT` 和 `SPECRAILS_RUN_PORT_RANGE_START`/`_END` 获得自己的端口；读取 `PORT` 的项目不会冲突。停止另一个进程，或让项目读取 `PORT`，然后**再次运行**。
- **被阻塞**、**超时**、**停止动作**和**意外停止**会指出让运行停下的上限或进程。
- **原因未知**：应用不会猜测，而是显示日志末尾，让你自己查看。

诊断下方最多有三个按优先级排列的补救办法，而且只列出在此处真正可行的：从停下的阶段**继续**、**再次运行**、**编辑规格并重新启动**（规格的补充说明会把你的修改带入下一次运行）、**修复环境**和**在失败处打开日志**。同一原因在[待处理列表](../getting-started/the-dashboard-tour)里显示为一行标签，任务的运行卡片展示同一张卡片。

### AI 分析 {#ai-failure-analysis}

在卡片下方，**AI 分析**会阅读日志并解释运行为什么停止：原因、**下一步**，以及它所依据的**日志摘录**（逐字引用）。它使用运行该 job 的同一个提供方和模型，因此你的账户总能运行它。它会自动开始，除非原因正是提供方的上限；这时请按**用 AI 分析**。分析结果会随 job 一起保存。如果之后日志发生变化，它会提示这一点并提供**重新分析**。

这份分析被标注为 AI 的解读，绝不会取代卡片：诊断、其原因和补救办法仍然是应用所记录的内容。在据此行动之前，请核对它引用的那些行。它的成本计入[分析](../insights/analytics-and-cost-tracking)中的**支持**类别。

## 工作流重启后

发生崩溃后，请使用原始配置和仓库恢复已保存的工作流。对于中断的写入，先检查工作树差异，再选择要恢复的具体尝试。已完成的步骤会保留。响应丢失的提供商调用仍计为中断，用量保持未知，绝不会显示为免费。如果已保存的记录无法证明原始交付关系，恢复会显示错误并保留工作树。

决策步骤因提问而暂停时，恢复执行会复用已保存的决策，并将人工回答传递给下一步骤，不会为同一次决策再次调用模型。暂停的提示步骤可能需要再次调用模型，才能根据你的回答继续处理。

## 历史保留

已保存的执行默认永久保留。在 **已保存的执行 → 历史保留** 中，项目可以改为保留 1 到 3650 天。后台不会自动删除任何内容：先保存策略，选择 **预览清理**，逐一查看每次执行及其原因，然后再选择 **删除过期历史**。只要执行仍在运行、正在等待你的回答或批准、有中断的写入、有未完成的交付或仍依赖它的分叉，它就会受到保护。只会删除项目 Specrails 存储中的运行历史；你的仓库、worktree、任务日志和成本记录都会保留。过期的执行显示为 **已过期**，不能再恢复或分叉。仍被保留执行使用的 Core 版本始终会保留。
