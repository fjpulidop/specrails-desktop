# Flow：まず作り、spec はあとで

Flow は、まだ何が欲しいのかはっきりしないときにエージェントと一緒に作る方法です。ミッションでエージェントと話すと、エージェントは専用の Flow ブランチ（プロジェクトの別コピー）で実際のコードを書いて実行します。結果に納得したら **引き渡す** を押します。レールが変更を引き継ぎ、spec を導出し、いつもの検証・レビュー・納品を実行します。

Implement はすでに説明できる作業を任すためのもの。Flow はそれを見つけるためのものです。

## Flow の始まり方

Flow を名前で頼む必要はありません。探索的なことや見た目に関わること（「試してみたい…」「どんな見た目にすべきかわからない」）を説明すると、ミッションに 2 つの道を示すカードが表示されます。

- **Flow**：今一緒に作る。spec は最後に。
- **Spec + Implement**：先に spec を決めてから、レールに任せる。

どちらの道も同じ重みで、常に同じ順番で表示されます。どちらも推奨されず、選ぶのはあなたです。**エージェントが尋ねた理由** では、エージェントが尋ねたきっかけを一文で説明し、どちらを選んでも、**今はしない** を押しても、しつこく勧めません。

Flow を選ぶと確認が開きます。Specrails はプロジェクトの別コピーを専用の Flow ブランチに作成し、エージェントはそこでコードを書けます。メインブランチには触れません。**Flow を開始** を押します。ボードに **Flow 中** ラベル付きの仮の spec が表示されます（クリックするとミッションに戻ります）。

Specrails Core がまだ Flow を実行できない場合、開始ボタンは無効になり、カードに足りないものが表示されます。たいていは Specrails Core を更新すれば解決します。

## Flow の間

Flow モードは、見る場所で専用の Flow カラーとともに示されます。コンポーザーには自律度チップの隣に **Flow** チップ、上端の細いライン、ヒント *この Flow で何を変えるかエージェントに伝えてください…* が表示され、ミッションのタイトルとミッション一覧の行には **Flow 中** と表示されます。会話には Flow に入った位置と出た位置が示され、Flow 中に書かれたエージェントの返信には時刻の横に小さな **Flow** マークが付きます。

コンポーザーのすぐ上のストリップには、Flow が短い 1 行で表示されます。状態、**Flow · 7 ファイル**、**一時停止**、そして主な操作の **引き渡す** です。操作が使えないとき（Flow がまだ保存中、別の操作を実行中）は、ホバーすると理由がわかります。ほかの実行と同じように矢印で行を開くと、残りが表示されます。

- **ブランチ**（クリックで名前をコピー）、追加・削除行数付きの **変更**（クリックで変更されたファイルを状態と +/− 付きで一覧）、プロバイダーが請求した **これまでのコスト**。コストが報告されたターンがあるまでは `—` を表示し、見積もりは表示しません。`*` は価格のないターンを除いた合計を示し、その数を注記で示します。
- Flow のアプリが動いている間の **プレビュー**（後述）。
- 離して置かれた **破棄** は、Flow の変更、そのブランチ、仮の spec を削除します。確認では失われるもの（+/− 付きの変更ファイル、ブランチ、spec）が一覧されます。

**一時停止** はエージェントを止め、変更と spec を保持します。行には **Flow を再開** が表示されます。

エージェントの作業中も書き込めます。Flow ではメッセージが現在のステップを **中断** し（送信ボタンが稲妻に変わります）、エージェントは新しい情報ですぐに続けます。Flow が開いている間、コンポーザー下の git ストリップは表示されません。Flow のパネルにブランチが表示されているためです。

## アプリを試す

Flow のエージェントは作業を確認するため、typecheck とテストを自分で実行します。試せるものがあると、**Start the app**、**Start and expose on the local network**、**Not now** の 3 つの選択肢で尋ねます。公開すると同じ Wi-Fi や VPN のスマートフォンからアプリを開けますが、そのネットワーク上の誰でもアクセスできます。

アプリが待ち受けを始めると、エージェントがアドレスをリンクで示し、Flow のパネルに緑の点付きの **プレビュー** が表示されます。ブラウザーでアプリを開きます。メニューにはネットワークアドレスと **アプリを停止** があります。アプリはメインのチェックアウトではなく Flow のコピーから動き、Flow を一時停止・破棄・引き渡すと Specrails が停止します。

## 引き渡す

結果に満足したら **引き渡す** を押します。行は **PR にする準備ができました** に変わり、その上に 1 行だけ表示されます：*レール 2 が変更した 7 個のファイルをレビュー済みの PR にします。失敗しても作業は失われません。* **起動** を押すか、**まだ** で Flow に戻ります。

レール、エンジン、モデル、労力はすでに選ばれています（空いているレールと会話のエンジン）。変更するには **方法を変更** を開きます。そこでは変更内容とこれまでのコストも確認できます。引き渡しの開始中、ストリップは途切れなく起動中を示し、その後は実行をステップごとに追います。レビュー上限や予算に達した場合は行にそう表示され、何も起動しません。ストリップ自体の **起動** は単独では起動しません。フォーカスを起動に置いて行を再表示するので、確認は常にそこで行います。

レールは作ったものから spec とその spec の変更を導出し、検証・レビューを行い、ほかの実行と同様に納品カードがミッションに表示されます。

技術的な理由で実行が失敗した場合、作業はそのまま自動的にこの Flow に戻ります。カードは何が失敗したかを平易な言葉で示し（コードは **技術的な詳細** に残ります）、エージェントがエラーを受け取って説明します。レビューで変更を求められた場合、カードは **Flow に戻る** または **再実行** を示します。納品が確定すると、ミッションは要約で Flow を閉じます。プルリクエスト、作ったものから書き直された spec、アーカイブされた spec の変更、そして Jira の課題（ある場合）です。

## 知っておくと便利なこと

- Flow は自分のブランチにのみ書き込みます。Flow の外ではミッションは読み取り専用のままです。
- 1 つのミッションで同時に使える Flow は 1 つです。一時停止はアプリを再起動しても保持されます。
- Flow のプロジェクトのコピーが消えた場合、Flow は **確認が必要** と表示され（お知らせのみで、決めることはありません）、何も削除されません。
- ストリップは、見ている実行を勝手に切り替えません。その間に別の実行があなたを必要とすると、ストリップの切り替えにあるその名前に **対応待ち** と表示されます。
- Flow 中や破棄した場合、Jira には何も送られません。
- Flow のコストは分析画面で独自のサーフェス **Flow** として、またエージェントのミッションのブロック内に表示されます。
