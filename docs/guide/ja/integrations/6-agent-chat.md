# チャットで Specrails を操作する（Agent Chat）

**Agent Chat** は Specrails の*内部*に住むコパイロットで、アプリ全体をあなたの代わりに動かせます。プロジェクト、スペック、レール、分析画面をクリックで渡り歩く代わりに、ただ頼むだけです。*「今週は成功したジョブがいくつ？」*、*「API プロジェクトにソーシャルログインのスペックを作って」*、*「優先度が最も高い 3 件のチケットを起動して、終わったら教えて」*。それは Specrails 自身のツール——[MCP サーバー](./5-mcp-server.md)が公開しているのと同じもの——を呼び出して作業を進め、その裏でダッシュボードがライブに更新されていく様子をあなたは見ていられます。

> **パイプラインのエージェントと混同しないでください。** *エージェント*セクション（Architect → Developer → Reviewer）は*レールがどのようにスペックを実装するか*の話です。**Agent Chat** は*アプリそのものを操作する*単一のアシスタントです。別物ですが、同じ言葉です。

## 開き方

ウィンドウ下部に浮かぶ**バブル**があります——クリックするとパネルが開きます。あるいはどこからでも **⌘⇧A**（Windows/Linux では **Ctrl+Shift+A**）を押してください。パネルは移動・リサイズ・最大化ができ、バブルへ戻せる本物のウィンドウで、最後に置いた場所を覚えています。

これは**意図的に非モーダル**です。背後のダッシュボードは生きたままなので、エージェントがレールを起動したりスペックを作成したりすると、それがリアルタイムで現れるのが見えます——固まった画面を眺めているわけではありません。

## 前提条件：MCP サーバー

Agent Chat は組み込みの **Specrails MCP サーバー**を通じてアプリを操作するため、それがオンになっている必要があります。オンでない場合、パネルはワンクリックの **Specrails MCP を有効化** バナー付きで開きます——押せば準備完了です（再起動不要）。詳細は[任意の AI から Specrails を操作する](./5-mcp-server.md)を参照してください。何もインストールされず、すべてはあなたのマシン内でローカルに動きます。

## 何に対して作業するかを選ぶ

ヘッダーには**プロジェクトセレクター**（Cursor のようなもの）があります。プロジェクトを選ぶと、頼んだことはすべてそれに限定されます——*「優先度の高いものを起動して」*はそのプロジェクトに対して解決されます。**ホーム**のままにしておくと、エージェントはあなたの環境全体にまたがって作業します。プロジェクトを一覧表示したり作成したりでき、全体に及ぶ質問にも答えられます。ホームにいながらプロジェクト固有のことを頼むと、推測ではなくどのプロジェクトかを尋ねてきます（あるいは新規作成を提案します）。

ここでプロジェクトを選んでも、あなたのダッシュボードは**動きません**——エージェントの対象と、あなたが見ているものは互いに独立しています。

## プロバイダーとモデル

メッセージ欄のすぐ上で、**プロバイダー**（Claude、Codex、Gemini）とその**モデル**を選びます。各プロバイダーには独自のモデル一覧があり、プロバイダーを切り替えるとそのプロバイダーの既定モデルで新しいセッションが始まります——ですから、たとえば Claude でアプリを操作しつつ、別の会話では Codex に切り替える、といったことが何も混ざらずにできます。

## 権限レベル——手綱はあなたが握る

エージェントはアプリ全体に触れられるので、どこまで自由を与えるかはあなたが決めます。**Shift+Tab** を押してその場で切り替える**レベル**でコントロールします（Claude Code が使うのと同じ循環です）。各レベルはその下のすべてを含みます。

| レベル | できること |
|---|---|
| 👀 **観察** | 読み取り専用——プロジェクト、スペック、ジョブ、分析の一覧表示と確認。何も変わりません。 |
| ✍️ **編集** | 上記 **+** 作成と編集（スペック、設定、レール構成）——元に戻せる変更。 |
| ⚡ **操作** | 上記 **+** **料金が発生する** AI 作業の起動（レール、スペック生成）。 |
| 🔥 **自律** | 上記 **+** 削除や停止——取り消せない操作。 |

**観察**から始め、エージェントに動いてほしいときだけレベルを上げてください。現在のレベルを超えることを試みると、エージェントは止まり、どのレベルに切り替えればよいかを正確に伝えます——制限を回避することは決してありません。これは*外部*アシスタントを統制する 設定 ▸ MCP のティアとは別物で、ここのレベルはこのアプリ内エージェント専用です。

## 頼めることの例

**操作**にしたら、試してみてください。

> *「API プロジェクトの todo スペックをすべて一覧表示して、それから優先度が最も高い 3 件を別々のレールで起動して見守って。」*
>
> *「今週いくら使った？プロジェクトごとに内訳を出して。」*
>
> *「web プロジェクトにダークモード切り替えのスペックを、Contract Layer 付きで作って。」*
>
> *「直近のバッチで何かが失敗した——失敗したジョブを見つけて、原因をまとめて。」*

返信は滑らかにストリーミングされ、整形済みで届き（見出し、表、リスト）、それぞれに小さな**コピー**ボタンが付きます。下部のステータスチップが、エージェントが今まさに何をしているか——*考え中…*、*MCP · jobs*、*Terminal*——を示すので、その状態が常に分かります。

## 気の利いた工夫

- **会話からスーパースペックを。** 一発生成ではなく、エージェントと一緒にスペックを*磨き上げて*みてください。まず実際のコードを読み、手短に質問し、進化していく下書きを会話内のライブカードとして表示します。あなたが承認するとスペックを作成し、デフォルトでバックグラウンドの **Contract Layer**（正確なファイルパス、データ形状、不変条件）で充実させるため、実装エージェントが即興に頼ることがなくなります。「contract layer なし」と言えば省略できます。
- **言及されたものをクリック。** プロジェクトに固定されたミッションでは、エージェントの返信内のスペック番号（`#12`）やジョブ／実行の id はクリック可能なチップです——スペックはボードの詳細モーダルを、ジョブ id はライブのジョブビューを開きます。参照がもう存在しない場合は、控えめな「見つかりません」の通知が表示されます。
- **実装カードは常に見える位置に。** エージェントがスペックを実装すると、ライブカードが作業を追跡します——あなたの判断（PR の作成、公開、再試行、破棄）を待っている間、カードは会話がどれだけスクロールしても**メッセージ欄のすぐ上にピン留め**されたままです。履歴上の元の位置には「上部にピン留め中」の控えめなマーカーが表示されます。複数のカードがアクティブな場合は小さなチップとして積み重なり（クリックで前面に表示）、シェブロンでカードを細いバーに最小化できます。PR が公開されるか、作業がマージまたは破棄されると、カードは会話履歴の元の位置に戻ります。
- **プロンプト履歴。** 入力欄が空のとき、**↑**/**↓** を押すと以前に頼んだ内容をたどれます（スクロール中は薄く表示されます）。入力を始めれば編集でき、Enter で送信できます。
- **キューを編集。** エージェントが作業中にさらに送信しましたか？メッセージがキューにある間、**↑**/**↓** は*それら*の間を移動します——入力欄に選択したメッセージが表示され、その場で編集でき、**Enter でキューへ保存し直せます**（Esc でキャンセル。未送信の下書きはそのまま戻ってきます）。
- **最小化しても失わない。** ✕ をクリックするとパネルはバブルへ戻ります——会話はそのまま動き続けます。開き直すと最新のメッセージに着地します。何も打ち直す必要はありません。
- **新しい会話。** **+** ボタンでまっさらなスレッドを始めます。履歴はアプリ全体にわたって存在し、個々のプロジェクトの上位にあります。
- **ミッションの切り替え。** プロジェクトセレクターの隣にあるミッションセレクターは、会話を新しい順に一覧表示します — 点滅するドットはエージェントがまだ作業中の会話を示し、小さなバッジはキュー内のメッセージ数を表します。リストが 8 件を超えると検索欄が現れます。各行のゴミ箱アイコンは、行内のクイック確認のあとにミッションを削除します — 実行中のものでも可能です（先に警告し、その後エージェントを停止します）。

## 知っておくとよいこと

- **操作と自律は料金が発生します**。AI を実行するからです。エージェントは料金の発生する操作を実行する前に前面に示します。眺めて整理したいだけなら、レベルは観察か編集にしておいてください。
- **エージェントはアプリ全体のもの**であり、開いているプロジェクトに縛られません——だからこそ独自のセレクターを持ち、その履歴はプロジェクト単位ではないのです。
- **その能力は MCP が許す範囲までです。** ある領域が丸ごと使えないように見える場合は、MCP サーバーが有効になっているか確認してください。
