# チャットで Specrails を操作する（Agent Chat）

**Agent Chat** は Specrails の*内部*に住むコパイロットで、アプリ全体をあなたの代わりに動かせます。プロジェクト、スペック、レール、分析画面をクリックで渡り歩く代わりに、ただ頼むだけです。*「今週は成功したジョブがいくつ？」*、*「API プロジェクトにソーシャルログインのスペックを作って」*、*「優先度が最も高い 3 件のチケットを起動して、終わったら教えて」*。それは Specrails 自身のツール——[MCP サーバー](mcp-server)が公開しているのと同じもの——を呼び出して作業を進め、その裏でダッシュボードがライブに更新されていく様子をあなたは見ていられます。

> **パイプラインのエージェントと混同しないでください。** *エージェント*セクション（Architect → Developer → Reviewer）は*レールがどのようにスペックを実装するか*の話です。**Agent Chat** は*アプリそのものを操作する*単一のアシスタントです。別物ですが、同じ言葉です。

## 開き方

ウィンドウ下部に浮かぶ**バブル**があります——クリックするとパネルが開きます。あるいはどこからでも **⌘⇧A**（Windows/Linux では **Ctrl+Shift+A**）を押してください。パネルは移動・リサイズ・最大化ができ、バブルへ戻せる本物のウィンドウで、最後に置いた場所を覚えています。

これは**意図的に非モーダル**です。背後のダッシュボードは生きたままなので、エージェントがレールを起動したりスペックを作成したりすると、それがリアルタイムで現れるのが見えます——固まった画面を眺めているわけではありません。

## 選択したテキストを再利用する

ミッションの会話でテキストを選択すると、そのコンテキストメニューが開きます。

**これについて質問**は、選択部分についてのサイド会話を開きます。ちょっとした「ところで」の質問のようなものです。質問を入力するか、入力欄が空のまま Enter を押すと、このミッションの文脈でそのテキストを説明してもらえます。回答にはミッションのこれまでの会話が使われ、続けて質問することもできます。何も保存されません。ミッション、その入力欄、エージェントのセッションには手を加えず、ウィンドウを閉じるとサイド会話は破棄されます。フッターには回答したモデルが表示されます。

**ミッションに追加**は、それを同じミッションに送ります。ミッションが処理中なら通常のキューを使い、書きかけの入力欄の下書きはそのまま残します。

**別のミッションを開始**には、**最初から**（選択部分のみ）と、**コンテキスト付き · Fork**（選択範囲に含まれる最後のメッセージまでの履歴とその添付ファイルを含む）があります。どちらも分割ペインを追加し、既存のペインは残したまま、選択したテキストを新しい入力欄に入れて編集できるようにします。準備ができたら Enter を押してください。ミッションを開いただけでは何も送信されません。Fork は独自のエージェントセッションとファイルのコピーを使い、元のミッションのタイトルを表示します。引き継がれたカードは読み取り専用の記録で、その操作が繰り返されることはありません。

選択部分を右クリックするか、**Shift+F10** を押しても開けます。矢印キーでメニュー内を移動し、**Escape** で閉じます。確定済みのメッセージを選択してください。ストリーミング中やキューで待機中のテキストはまだ使えません。

## 複数のミッションを並べて表示 {#split-view}

サイドバーのミッションを右クリック（または **Shift+F10**）し、**分割表示**、**右に開く**、**下に開く** のいずれかを選びます。分割表示は、両方が収まるときは今いるミッションの横に、収まらないときは下に開きます。

- **サイズ変更:** 2 つのミッションの間の線をドラッグします。中央に吸着し、ダブルクリックでその領域を均等に分けます。線にフォーカスがあるときは矢印キーで動かし（Shift で大きく）、Home で中央に戻します。
- **レイアウトメニュー**（各ミッションのヘッダーにある列ボタン）: 別のミッションを右または下に開く、ミッションを左右上下に移動、他のミッションと入れ替え、最大化、すべてのミッションを均等化、閉じる。ミッションが小さくなりすぎる（約 360 × 240 px 未満）操作は無効になります。
- **ショートカット:** **⌥⌘]** / **⌥⌘[** 次 / 前のミッション、**⌘⇧↵** 最大化 / 元に戻す、**⌥⌘=** 均等化、**⌥⌘W** 今いるミッションを閉じる（Windows/Linux では ⌥⌘ の代わりに Ctrl+Alt、Ctrl+Shift+Enter）。
- **小さいウィンドウ:** ミッションが収まらなくなると重ねて表示され、上部のタブで表示するものを選びます。ほかのミッションも動き続けます。

レイアウトとサイズはこのウィンドウで再起動後も保持されます。アーカイブまたは削除されたミッションは除外されます。ペインを閉じてもミッションが止まったり削除されたりすることはありません。

## コンテキストの使用量 {#context-ring}

メッセージ入力欄の横にある小さなリングは、プロバイダーのセッションがミッションのコンテキストウィンドウをどれだけ使ったかを、プロバイダーの報告どおりに示します。クリックすると、使用トークン数、ウィンドウのサイズ、モデルが表示されます。プロバイダーがウィンドウを報告しない場合や、コンテキストを圧縮した直後は、リングは空のままで、何が不明かを示します。コンテキストがいっぱいになると、プロバイダーが自動的に圧縮します。

**要約して新しく始める。** リングのポップオーバー（コンテキストが 75 % に達するとメインのボタンになります）から、Specrails がミッションの要約（目的、決定事項、現在の状態、次のステップ）を作成します。次のメッセージから、その要約だけを知る新しいプロバイダーセッションが始まります。会話は履歴に残り、折りたたまれた **セッションを更新 · 要約** の行に、新しいセッションが知っていることが表示されます。実行前に確認を求められます。ターンの実行中や、ミッションが Intent 中（Intent は専用のセッションで動作します）のときは利用できません。

## 前提条件：MCP サーバー

Agent Chat は組み込みの **Specrails MCP サーバー**を通じてアプリを操作するため、それがオンになっている必要があります。オンでない場合、パネルはワンクリックの **Specrails MCP を有効化** バナー付きで開きます——押せば準備完了です（再起動不要）。詳細は[任意の AI から Specrails を操作する](mcp-server)を参照してください。何もインストールされず、すべてはあなたのマシン内でローカルに動きます。

## 何に対して作業するかを選ぶ

ヘッダーには**プロジェクトセレクター**があります。プロジェクトを選ぶと、頼んだことはすべてそれに限定されます——*「優先度の高いものを起動して」*はそのプロジェクトに対して解決されます。**ホーム**のままにしておくと、エージェントはあなたの環境全体にまたがって作業します。プロジェクトを一覧表示したり作成したりでき、全体に及ぶ質問にも答えられます。ホームにいながらプロジェクト固有のことを頼むと、推測ではなくどのプロジェクトかを尋ねてきます（あるいは新規作成を提案します）。

ここでプロジェクトを選んでも、あなたのダッシュボードは**動きません**——エージェントの対象と、あなたが見ているものは互いに独立しています。

## 権限レベル——手綱はあなたが握る

エージェントはアプリ全体に触れられるので、どこまで自由を与えるかはあなたが決めます。**Shift+Tab** を押してその場で切り替える**レベル**でコントロールします（Claude Code が使うのと同じ循環です）。各レベルはその下のすべてを含みます。

| レベル | できること |
|---|---|
| 👀 **観察** | 読み取り専用——プロジェクト、スペック、ジョブ、分析の一覧表示と確認。何も変わりません。 |
| ✍️ **編集** | 上記 **+** 作成と編集（スペック、設定、レール構成）——元に戻せる変更。 |
| ⚡ **操作** | 上記 **+** **料金が発生する** AI 作業の起動（レール、スペック生成）。 |
| 🔥 **自律** | 上記 **+** 削除や停止——取り消せない操作。 |

**観察**から始め、エージェントに動いてほしいときだけレベルを上げてください。現在のレベルを超えることを試みると、エージェントは止まり、どのレベルに切り替えればよいかを正確に伝えます——制限を回避することは決してありません。これは*外部*アシスタントを統制する 設定 ▸ MCP のティアとは別物で、ここのレベルはこのアプリ内エージェント専用です。

**自律**への引き上げはキー操作だけでは行われません。「操作」から Shift+Tab を押すと **自律に切り替える** の通知が表示され、もう一度 Shift+Tab を押すと代わりに「観察」に戻ります。レベルを下げる操作は常に即時です。

## 頼めることの例

**操作**にしたら、試してみてください。

> *「API プロジェクトの todo スペックをすべて一覧表示して、それから優先度が最も高い 3 件を別々のレールで起動して見守って。」*
>
> *「今週いくら使った？プロジェクトごとに内訳を出して。」*
>
> *「web プロジェクトにダークモード切り替えのスペックを、Contract Layer 付きで作って。」*
>
> *「直近のバッチで何かが失敗した——失敗したジョブを見つけて、原因をまとめて。」*

返信は滑らかにストリーミングされ、整形済みで届き（見出し、表、リスト）、それぞれに小さな**コピー**ボタンが付きます。下部のステータスチップが、エージェントが今まさに何をしているか——*考え中…*、*MCP · jobs*、*Terminal*——を示すので、その状態が常に分かります。

コードブロックには言語名と専用の**コピー**ボタンが表示されます。エージェントの書き込み中に上へスクロールすると、入力欄の上に **新しいメッセージ** のピルが現れ、クリックすると最新の返信に戻れます。

## 気の利いた工夫

- **言及されたものをクリック。** プロジェクトに固定されたミッションでは、エージェントの返信内のスペック番号（`#12`）やジョブ／実行の id はクリック可能なチップです——スペックはボードの詳細モーダルを、ジョブ id はライブのジョブビューを開きます。参照がもう存在しない場合は、控えめな「見つかりません」の通知が表示されます。
- **実行はひとつのストリップに。** エージェントが作業を起動すると、メッセージ欄のすぐ上の 1 本のストリップがそれを追います。実行が今していることをわかりやすい言葉で（「変更から spec を作成中」）、完了した実行の数、経過時間、これまでの実コスト（プロバイダーが請求するまでは `—`）。実行があなたを必要とするとき（PR の作成、再試行、Intent に戻る）は、ストリップがアイコンと言葉で伝え、その 1 つの操作を表示します。ストリップをクリックすると、実行の完全なカードがすぐ上に開きます（Esc で閉じます）。複数の実行があるときは、あなたを必要としているものを先に表示し、小さな切り替え（「Rail 1 · Rail 2 · +1」）を添えます。会話には起きたことだけが残ります（「Rail 1 で起動しました」「Rail 1 が失敗：…」「納品済み：PR #812」）。各行はその実行を開きます。あなたの判断を待っているミッションには、ミッション一覧にドットが表示されます。新しい有料の実行を始める操作（**再起動**、**復旧して再試行**）や他の人に見える操作（PR の作成、公開）は、ストリップからは実行されません。そのボタンにフォーカスを置いてカードを開くので、確認はそこで行います。
- **キーボードでストリップを操作。** **⌥R**（Windows/Linux では **Alt+R**）でメッセージ欄から、いま開いているミッションのストリップへ移動します。もう一度押すと実行の詳細を表示 / 非表示にでき、**Esc** で元の場所に戻ります。テキスト入力欄の外では **⌥[** と **⌥]** で実行を切り替えます。ストリップにフォーカスがある間は、**P** で Intent を一時停止 / 再開し、**H** で引き渡します。これらの文字キーはほかの場所では何もしません。一覧は **?** で表示できます。
- **プロンプト履歴。** 入力欄が空のとき、**↑**/**↓** を押すと以前に頼んだ内容をたどれます（スクロール中は薄く表示されます）。入力を始めれば編集でき、Enter で送信できます。
- **キューを編集。** エージェントが作業中にさらに送信しましたか？メッセージがキューにある間、**↑**/**↓** は*それら*の間を移動します——入力欄に選択したメッセージが表示され、その場で編集でき、**Enter でキューへ保存し直せます**（Esc でキャンセル。未送信の下書きはそのまま戻ってきます）。
- **キーで回答。** エージェントが選択肢を出したとき、各チップには番号が付きます。入力欄が空の状態で **⌥1**…**⌥9**（Windows/Linux では **Alt+1**…**Alt+9**）を押すと選べます。
- **削除したキューのメッセージを元に戻す。** キューのメッセージを削除すると数秒間 **元に戻す** が表示され、メッセージをキューに戻せます。
- **最小化しても失わない。** ✕ をクリックするとパネルはバブルへ戻ります——会話はそのまま動き続けます。開き直すと最新のメッセージに着地します。何も打ち直す必要はありません。
- **新しい会話。** **+** ボタンでまっさらなスレッドを始めます。履歴はアプリ全体にわたって存在し、個々のプロジェクトの上位にあります。
- **ミッションの切り替えとアーカイブ。** プロジェクトの隣のセレクターは会話を新しい順に並べ、作業中のエージェントとキュー内のメッセージを示します。9 件以上で検索できます。**アーカイブ**はミッションと履歴を無期限に保存します。作業中は完了を待ってください。アーカイブ済みミッションは読み取り専用で開けます。**復元**すると送信を再開できます。**削除**はアーカイブ済みのみで、確認後に **最近削除した項目**へ移動し、30 日間保持されます。**元に戻す**（または **⌘Z**）でアーカイブ済みに戻ります。

展開したミッションのサイドバーでは、**プロジェクト**の隣で **未アーカイブ**（既定）、**アーカイブ済み**、**すべて**を選べます。お気に入り、未割り当て、全プロジェクトに適用され、再読み込み後も選択を保持します。実行中のみのフィルターと独立して組み合わせられ、互いをリセットしません。アーカイブ済みの行は薄く表示され、すべて表示では印が付きます。

- **どこからでもミッションを探す。** **⌘K**（またはエージェントモードのサイドバーの **検索** ボタン）を押して、覚えている断片を入力してください——タイトルの単語でも、*中で話された内容* でも構いません。ミッションはまずメモリからタイトルで即座に一致し、一拍おいて内容による一致がハイライト付きで届き、固定されたプロジェクトと最終アクティビティも表示されます。エージェントモードではミッションが最初のグループ、ボードではプロジェクトの直後に並びます。Enter でミッションを開きます。

## 起動カードと実行カード

- **エージェントが提案し、あなたが Play を押す。** spec を rail に載せるよう頼むと（「#12 と #14 を rail に準備して」）、文章で説明する代わりに**起動カード**を渡してきます。rail（または新規 rail）、spec、エンジン、モデル、推論の深さ、プロファイル、loop、任意の対象 PR とベースブランチが、推奨値で事前入力され、すべて編集できます。好きに変えて **Play** を押してください。「今すぐ起動して」と言えば直接起動します。
- **1 枚のカードが実行を追いかける。** Play の後、提案は「起動済み → Rail N」として固定され、**実行カード**が引き継ぎます。状態、経過時間、パイプラインが今していること、ログボタン、停止。作業がレビュー可能になると、同じカードがおなじみの PR カード（PR 作成、ローカル統合、破棄）になります。
- **失敗は黙らない。** 実行が失敗または停止すると、カードが理由を平文で示し、本当に取れる選択肢——再開、復旧、承認、再起動、破棄——を提示し、エージェントは何が起きたか・何を勧めるかを短く報告します。勝手に再開や再起動はしません。決めるのはカード上のあなたです。
- **git がなければ PR フェーズもない。** git リポジトリ（またはコミット）のないプロジェクトにも実行カードはあります——進捗、ログ、失敗と復旧——ただしブランチも PR ステップもありません。カードにそう書かれます。
- **`@rail-N`。** `@` を入力して rail を選ぶと、その spec と状態（空き・使用中・決定待ち）付きでメッセージから参照できます。

## サブエージェント

一部のプロバイダーは、タスクの一部を**サブエージェント**に任せられます。サブエージェントは並行して動き、エージェントが返信した後も作業を続けるヘルパーです。サブエージェントは**既定でオン**です。1 回の依頼のコストが大きく増えるため、コストを抑えたい場合はプロジェクトごとにオフにできます。

- **プロジェクトごとにオフにする。** プロジェクトの**設定 → サブエージェント**を開き、**このプロジェクトでサブエージェントを許可**をオフにします。そのプロジェクトのミッション、探索、リファインに適用され、Implement パイプラインには一切影響しません。プロジェクトのないミッションは**設定 → AI プロバイダー → プロジェクトのないミッションでサブエージェントを許可**に従います。
- **実行するプロバイダーを選ぶ。** **サブエージェントの実行環境** の既定値 **ミッションのエージェントと同じ** では、ミッション自身の CLI がネイティブに起動します。最も速く、プロンプトキャッシュも共有されます。代わりにプロバイダー・モデル・エフォートを選ぶと、たとえば Codex のミッションで Claude のサブエージェントを使うなど、プロバイダーを組み合わせられます。すでにそのプロバイダーを使うミッションはそのモデルでネイティブのまま、別のプロバイダーでは Specrails が各サブエージェントを自ら起動します。コールドスタートでコストが増えることがありますが、より細かく制御でき、それぞれの実コストも表示されます。切り替え前に確認が表示され、これらのサブエージェントにはミッション内でプロバイダーのバッジが付きます。
- **作業を見守る。** 返信が起動したエージェントは、その返信の下に 1 行のコンパクトな表示で現れます。作業中は開いたままで、すべて完了すると合計時間とトークンをまとめた 1 行に折りたたまれます。行を展開すると、結果とコストを読んだり、アクティビティをライブで追ったりできます。各起動は会話のその位置に残るため、後の起動が前のものと混ざることはありません。実行中のエージェントは行から停止でき、まとめての停止は要約行から行えます。
- **エージェントは自分で続ける。** バックグラウンドのエージェントが終わると、エージェントは作業を続けて結果を投稿します。その投稿には「バックグラウンドエージェントの後に続行」と表示されます。
- **設定の変更は安全。** エージェントが動作中のミッションは、それらの完了後に変更を適用します。その旨が表示され、**エージェントを停止して今すぐ適用**も選べます。
- **勝手に再起動しない。** 再起動で中断されたエージェントは中断済みとして残ります。**再起動**は、その作業のやり直しをエージェントに頼むメッセージを下書きするだけです。

## ミッションのコネクタ {#connectors}

ミッションでは、各プロバイダーで設定済みのコネクタと MCP サーバーを使えます。Claude で動くミッションでは **claude.ai のアカウントコネクタ**（Google Drive、Gmail など）と `~/.claude.json` のサーバー、Codex では `~/.codex/config.toml` のサーバー、Gemini では Gemini のサーバーです。**設定 → AI プロバイダー → ミッションのコネクタ** を開くと、プロバイダーごとに一覧できます。

- **最初はすべてオンです。** 後から追加したコネクタもオンになります。ミッションに不要なものはオフにしてください。1 つでリクエストごとに数千トークン増えることがあります。
- **サイズ。** **サイズを測定** はローカルの各 MCP サーバーを一度起動し、ツールの数と定義のおおよそのトークン数を表示します。Claude はリクエストごとに定義をすべて送ります。Codex はエージェントがツールを検索したときだけ読み込むため、Codex では使うまでほとんどコストがかかりません。
- **Specrails の MCP は二重に読み込まれません。** プロバイダーの設定にも Specrails サーバーがある場合、常に除外されると表示されます。ミッションには既に専用のものがあります。
- **切り替えられない行もあります。** プロバイダー自身の設定でオフのサーバーはオフのままです。**外部 MCP サーバー** で追加したサーバーはその設定に従います。Kimi は自分でサーバーを読み込みます。
- **自分の Claude MCP サーバーはツール検索を待ちます。** Claude のミッションはまだ `~/.claude.json` のサーバーを読み込みません。必要に応じたツール読み込みがないと、大きなサーバー（数百のツールを持つものもあります）でコンテキストが埋まってしまうためです。Claude がツールを必要に応じて検索できるようになると読み込まれます。
- **変更は次のターンから適用されます。** そのターンではプロバイダーのプロンプトキャッシュが一度作り直されるため、少し費用が増えます。**更新** でプロバイダーの設定を読み直します。

## 知っておくとよいこと

- **操作と自律は料金が発生します**。AI を実行するからです。エージェントは料金の発生する操作を実行する前に前面に示します。眺めて整理したいだけなら、レベルは観察か編集にしておいてください。
- **エージェントはアプリ全体のもの**であり、開いているプロジェクトに縛られません——だからこそ独自のセレクターを持ち、その履歴はプロジェクト単位ではないのです。
- **その能力は MCP が許す範囲までです。** ある領域が丸ごと使えないように見える場合は、MCP サーバーが有効になっているか確認してください。
