# Intent：解決策ではなく、課題を書く {#intent-mode}

ソフトウェア開発で遅いのは、もうコードを書くことではありません。何を作るべきかを知ることと、正しく作れたかを確かめることです。Intent はそこから始まります。書くのは **intent** です。課題、望む結果、うまくいったことをどう確かめるか、誰と何に影響するか、制約、そしてまだ誰も知らないこと。解決策は書きません。Specrails が intent から spec を導出し、あなたは spec を書く代わりにレビューします。

intent からは、対等な 2 つの進み方があります。

- **探索する**：隔離された Intent セッション（専用のブランチ、プロジェクトの別コピー）で、エージェントと一緒に作ります。結果に納得したら、レールが作ったものから spec を導出します。
- **委任する**：エージェントが intent から spec を書き、あなたがレビューし、レールが作ります。

探索するは見つけるためのもの、委任するはすでにはっきりしていることを作るためのものです。どちらも推奨されず、選ぶのはあなたです。

## intent

intent は 6 つの部分でできていて、解決策のための部分はありません。

| 部分 | 書く内容 |
| --- | --- |
| **課題** | 今、何が問題か。誰にとって、どんなときにつらいか。 |
| **目指す結果** | 解決したとき、何が成り立っているか。任意の**仮説**は *私たちは……が……を生むと考えている。……となったときにわかる* の形で書きます。 |
| **達成の確かめ方** | 結果が出たことを示す観察できるサイン（「新規ユーザーが 2 分以内にセットアップを終える」）。受け入れ基準になります。 |
| **影響を受ける人と対象** | 人、画面、システム。 |
| **制約** | どんな解決策でも守るべき限界。 |
| **未解決の問い** | まだ誰も知らないこと。エージェントは推測せず、調べます。 |

解決策を書いた場合（「Redis キャッシュを追加する」）、intent はその目的（「API が 200 ms 未満で応答する」）を目指す結果として残し、あなたの解決策は制約（必須とする場合）か未解決の問い（選択肢の 1 つである場合）になります。

どのスペックにも intent を持たせられます。intent はスペック詳細の説明文の上にあり、各部分を編集できます。回答済みの未解決の問いには回答が表示されます。intent にまだ未解決の問いがあるスペックは、ボード上に件数付きの小さなコンパスのマークが表示されます。intent は**対象外**と同じく Specrails 内に残り、Jira には書き込まれません。

## intent の出どころ

- **ミッション内（デフォルト）。** 作業を説明すると、エージェントがアナリストのようにヒアリングします。ユーザー、制約、うまくいったことの確かめ方を尋ね、すべての部分とあなたの依頼の 2 通りの解釈を載せた **Intent** カードを表示します。解釈をクリックして答えるか、自分の言葉で返信します。intent が確定すると、カードに **探索する** と **委任する** が並んで表示されます。そこからエージェントが書いたスペックには、intent が自動的に付きます。ミッションで intent のステップを省くには `#noframe` を送ります。`#frame` で再び有効になります。
- **スペックを追加。** **Intent** は最初のモードで、デフォルトで開きます。解決策ではなく課題を書き、**Intent とスペックを生成** を押します。1 回の AI の処理で intent と、そこから導出したスペックが書かれ、レビューできる状態になります。クイック、Explore、Raw も引き続き使えます。intent を書けなかった場合も、intent なしのスペックは手に入り、その旨の通知が表示されます。

## intent は作業とともに渡る

- スペックに取り組むすべてのエージェントは、まず intent を受け取ります。intent は*なぜ*と*どんな結果か*の拠り所として示され、*どうやるか*の拠り所ではありません。プランナー、開発者、レビュアー、Intent セッションのエージェントも対象です。レビュアーは、目指す結果とサインに照らしても作業を判断します。
- intent を持つスペックをレールが納品すると、Specrails はそれを `intent.md` として、実行の OpenSpec の変更に、提案・設計・タスクと並べて書き込みます。こうして intent はコードと一緒に Git に残ります。（複数のスペックをまとめたバッチ実行では書き込まれません。）

## 探索する：Intent セッションを始める

確定した intent のカードで **探索する** を選びます。確認が開きます。Specrails はプロジェクトの別コピーを専用の Intent ブランチに作成し、エージェントはそこでコードを書けます。メインブランチには触れません。**Intent を開始** を押します。あなたの intent を持つ仮のスペックが **Intent 中** ラベル付きでボードに表示され（クリックするとミッションに戻ります）、エージェントの最初のターンは intent から始まります。

## 既存のスペックから Intent を始める

新しいアイデアだけでなく、どのスペックも Intent で作れます。Intent と Implement は、スペックに取り組む対等な 2 つの方法のままです。

- ボードでスペックを右クリックし、**Intent で開始** を選びます（レールへのドラッグと並ぶ選択肢です）。スペックの詳細では、**Intent で開始** が **レールへ移動** の隣にあります。
- ミッションでレールを指定せずにスペックの実装を頼むと、エージェントはそのスペックについて2 つの道のカードを表示します。**Intent** はあなたと一緒に作業し、**Spec + Implement** はレールで実行します。
- スペックが 1 つだけのレール起動カードにも、起動の隣に **Intent で開始** があります。

スペック自体が **Intent 中** になります。仮のスペックは作られず、エージェントの最初のターンにはそのスペック（まず intent、続いて受け入れ基準、Contract Layer、対象外の項目、未対応のアデンダ）が渡されます。ボードから始めると、Intent はスペック自身のミッション、またはスペック名の新しいミッションで開きます。複数の Git リポジトリを持つプロジェクトで、スペックがそのうちの 1 つだけを指定していない場合は、先に小さなダイアログで Intent の実行先を尋ねます。表示されるのは Git リポジトリだけで、スペックのリポジトリ（なければプライマリ）があらかじめ選ばれ、矢印キーで選択を変えられます。スペックがすでに Intent 中、完了またはキャンセル済み、レール上にある、または Intent を使えないときは、**Intent で開始** は無効になり、理由がツールチップに表示されます。

**破棄** すると、スペックは以前のステータスのまま元どおりに戻ります。あなたのスペックが削除されることはありません。Intent が納品されると、スペックは作ったものから書き直されます。その前に元の本文がコメント **Original spec before Intent** として保存されるので、何も失われません。intent 自体は書き換えられません。作業で決着した未解決の問いに、回答が加わるだけです。すでに Jira と連携しているスペックは同じ課題を更新し、レビューに対応するステータスへ移します。2 つ目の課題は作られません。

## Intent の間

Intent モード中であることは、目に入る場所に専用の Intent カラーで示されます。コンポーザーには自律度チップの隣に **Intent** チップとヒント *この Intent で何を変えるかエージェントに伝えてください…* が表示され、ミッションのタイトルとミッション一覧の行には **Intent 中** と表示されます。会話には Intent に入った位置と出た位置が示され、Intent 中に書かれたエージェントの返信には時刻の横に小さな **Intent** マークが付きます。

コンポーザーのすぐ上のストリップには、Intent が短い 1 行で表示されます。状態、**Intent · 7 ファイル**、**Intent を一時停止**、そして主な操作の **引き渡す** です。操作が使えないとき（Intent がまだ保存中、別の操作を実行中）は、ホバーすると理由がわかります。ほかの実行と同じように矢印で行を開くと、残りが表示されます。

- **ブランチ**（クリックで名前をコピー）、追加・削除行数付きの **変更**（クリックで変更されたファイルを状態と +/− 付きで一覧）、プロバイダーが請求した **これまでのコスト**。コストが報告されたターンがあるまでは `—` を表示し、見積もりは表示しません。`*` は価格のないターンを除いた合計を示し、その数を注記で示します。
- Intent のアプリが動いている間の **プレビュー**（後述）。
- 少し離して配置された **破棄** は、Intent の変更、そのブランチ、仮の spec を削除します。確認では失われるもの（+/− 付きの変更ファイル、ブランチ、spec）が一覧されます。

**Intent を一時停止** はエージェントを止め、変更と spec を保持します。行には **Intent を再開** が表示されます。

エージェントの作業中も書き込めます。Intent ではメッセージが現在のステップを **中断** し（送信ボタンが稲妻に変わります）、エージェントは新しい情報ですぐに続けます。Intent が開いている間、コンポーザー下の git ストリップは表示されません。Intent のパネルにブランチが表示されているためです。

## アプリを試す

Intent のエージェントは作業を確認するため、typecheck とテストを自分で実行します。試せるものがあると、**Start the app**、**Start and expose on the local network**、**Not now** の 3 つの選択肢で尋ねます。公開すると同じ Wi-Fi や VPN のスマートフォンからアプリを開けますが、そのネットワーク上の誰でもアクセスできます。

アプリが待ち受けを始めると、エージェントがアドレスをリンクで示し、Intent のパネルに緑の点付きの **プレビュー** が表示されます。ブラウザーでアプリを開きます。メニューにはネットワークアドレスと **アプリを停止** があります。アプリはメインのチェックアウトではなく Intent のコピーから動き、Intent を一時停止・破棄・引き渡すと Specrails が停止します。

## 引き渡す {#intent-hand-off}

結果に満足したら **引き渡す** を押します。行は **PR にする準備ができました** に変わり、その上に 1 行だけ表示されます：*レール 2 が、あなたが変更した 7 個のファイルをレビュー済みの PR にします。失敗しても作業は失われません。* **起動** を押すか、**まだ** で Intent に戻ります。**Esc** は **まだ** と同じです。外側をクリックすると行がたたまれるだけで、ストリップは **起動** 付きの **PR にする準備ができました** のままです。会話のエンジンがこのマシンで引き渡しを実行できない場合は、行のすぐ下の注記にそう表示され、レールのデフォルトエンジンが使われます。

レール、エンジン、モデル、エフォートはすでに選ばれています（空いているレールと会話のエンジン）。変更するには **方法を変更** を開きます。そこでは変更内容も確認できます。これまでのコストはメインの行に表示されます。**まだ** を押して後で引き渡し直しても、選んだ内容は保持されます。引き渡しの開始中、ストリップは途切れなく起動中を示し、その後は実行をステップごとに追います。レビュー上限や予算に達した場合は行にそう表示され、何も起動しません。45 秒たっても実行が表示されない場合、ストリップは回転を止め、**まだ Rail 2 に引き渡しています…** と **更新** を表示します。**更新** は再確認するだけで、実行が表示されるまで待ち続けます。

レールは作ったものから spec とその spec の変更を導出し、検証・レビューを行い、ほかの実行と同様に納品カードがミッションに表示されます。

技術的な理由で実行が失敗した場合、作業はそのまま自動的にこの Intent に戻ります。カードは何が失敗したかを平易な言葉で示し（コードは **技術的な詳細** に残ります）、エージェントがエラーを受け取って説明します。レビューで変更を求められた場合、カードは **Intent に戻る** または **再実行** を示します。納品が確定すると、ミッションは要約で Intent を閉じます。プルリクエスト、作ったものから書き直された spec、アーカイブされた spec の変更、そして Jira の課題（ある場合）です。

## 知っておくと便利なこと

- Intent は自分のブランチにのみ書き込みます。Intent の外ではミッションは読み取り専用のままです。
- 1 つのミッションで同時に使える Intent は 1 つです。一時停止はアプリを再起動しても保持されます。
- Intent のプロジェクトのコピーが消えた場合、Intent は **確認が必要** と表示され（お知らせのみで、決めることはありません）、何も削除されません。
- ストリップは、見ている実行を勝手に切り替えません。その間に別の実行があなたを必要とすると、ストリップの切り替えにあるその名前に **対応待ち** と表示されます。
- Intent 中や破棄した場合、Jira には何も送られません。
- Intent のコストは分析画面で独自のサーフェス **Intent** として、またエージェントのミッションのブロック内に表示されます。
