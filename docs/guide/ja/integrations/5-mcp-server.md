# 任意の AI から Specrails を操作する（MCP サーバー） {#mcp-server}

Specrails は、[Model Context Protocol](https://modelcontextprotocol.io) を話す任意の AI アシスタント（Claude Desktop、Claude Code、Cursor、Cline、あるいは自作のエージェント）に対して、**自分自身**を公開できます。これをオンにしてアシスタントを Specrails に向ければ、チャットするだけでアプリ全体を操作できます。たとえば *「プロジェクト一覧を見せて」「API プロジェクトにソーシャルログインのスペックを作って」「レール 0 を起動して、終わったら教えて」「今週はいくら使った？」* といった具合です。あなたがあちこちクリックする代わりに、アシスタントが裏側で Specrails のツールを呼び出します。

これは、プラグインや「My approved MCPs」機能とは逆方向の働きをします。それらは Specrails が*ほかの* MCP サーバーを*使う*ためのものですが、こちらは他のアプリに **Specrails** を使わせるためのものです。

## 最初からオン

これは**デフォルトでオン**です — 初めてアプリを開いた時点でサーバーはすでに動いており、再起動も切り替えも不要です。**Settings ▸ MCP** を開けばクライアント設定をコピーでき、不要ならそこでオフにできます。

外部の AI がどんな操作をできるかは、一連の権限ティアで*あなた*がコントロールできます。

| ティア | 許可される内容 | デフォルト |
|---|---|---|
| **Read**（読み取り） | プロジェクト、スペック、ジョブ、アナリティクスなどの一覧表示と確認 | 常時オン（MCP が有効なとき） |
| **Write**（書き込み） | スペックの作成・編集、設定やレール構成の変更 | オン — 制限するならチェックを外す |
| **AI-spawn**（AI 起動） | AI を走らせて**お金がかかる**操作（レールの起動、スペックの生成、チャットターンの送信） | オン — 制限するならチェックを外す |
| **Destructive**（破壊的操作） | プロジェクト／スペック／ジョブの削除、実行中の作業の停止 | オン — 制限するならチェックを外す |

4 つのティアはすべて最初から付与されているので、接続したアシスタントはすぐにアプリ全体を操作できます。自分だけに留めておきたいティアはチェックを外してください。その後アシスタントがそのティアに該当する操作を試みると、Specrails は拒否し、どのティアを再びオンにすればよいかを明確なメッセージで知らせます。

## Claude Code または Codex をワンステップで接続

**設定 ▸ MCP** を開き、Claude Code または Codex の横にある **接続** をクリックします。ターミナルでコマンドを 1 つ実行しても構いません。

```bash
specrails-desktop mcp connect --client claude   # または codex
```

Specrails はクライアント自身の設定に自分を追加し、ファイルのバックアップを残し、アクセストークンはどこにも書き込まず、すぐに接続を確認します（見つかったツールの数が表示されます）。何度実行しても問題ありません。そのあと新しい Claude Code または Codex セッションを開始してください。自分で実行したい場合は **コマンドをコピー** でクライアント自身のコマンドを確認できます。ほかのアシスタントには **設定をコピー** を使います。

うまく動かないときは `specrails-desktop mcp doctor` を実行してください。アプリ、アクセストークンのファイル、ブリッジとそれを動かす Node、各クライアントの設定、実際の接続をまとめて確認し、問題ごとに直し方を示します。確認するだけで、何も変更しません。Node を更新した後（Homebrew など）にアシスタントが Specrails を見つけられなくなったら、もう一度 **接続** を実行してください。

**支出の前に確認**（同じパネル、既定は 0.50 ドル）は、接続したアシスタントが有料の作業を始める前に確認しなければならない金額です。マージ、PR、削除は常に確認します。アシスタントには、次の一手が用意された 15 個のシンプルなツール、ポーリング不要の待機、あなたの言語での回答、*start-my-day*、*review-waiting*、*ship-milestone*、*why-stuck* などのプロンプトが提供されます。古いスクリプトが以前のツールを必要とする場合は、同じパネルで **シンプルな MCP ツール** をオフにしてください。Specrails 自身のミッションには影響しません。

すべての判断は短いメニューで届きます。各選択肢と選んだときに起きること、推奨が先頭、最後に「その他（書いてください）」。キーボードで番号（または選択肢）を入力するか、自分の言葉で答えてください。クライアントが独自のフォームを表示できる場合、Specrails はそこで直接たずねます。マージ、PR の作成、費用のかかる選択肢は、引き続きあなたの承認を求めます。

## エージェント向け: クライアントを接続する

接続を頼まれたら、[MCP 接続ランブック](https://github.com/fjpulidop/specrails-desktop/blob/main/docs/agents/mcp.md) を読んでください。コマンド 1 つでの接続、Claude Code と Codex への手動登録、確認、トラブルシューティングを扱っています。登録だけでは接続の証明になりません。`initialize`、`tools/list`、読み取り専用の呼び出しまで完了してください。

全体をすばやく把握するには、アシスタントは `specrails_overview` を呼び出します。実行中のもの、あなたを待っているもの、最近の失敗、今日の支出、マシンの CPU とメモリが 1 回の呼び出しでわかります。`specrails_inbox` は **対応待ち** の受信箱を読んで回答し、`specrails_missions` はミッションの一覧表示とメッセージ送信、`specrails_specs` と `specrails_rails` はプロジェクトのバックログとレール、`specrails_insights` は支出と上限を示し、`specrails_wait` は何度も問い合わせる代わりに実行の完了を待ちます。失敗した実行には診断とログの末尾が付きます。

すべての回答は短い平易な要約と、推奨の印が付いた次に取れる手順から始まります。エラーは何が問題だったか、再試行が役に立つかどうかを伝えます。取り消せない操作や上限を超える有料の作業の前には、アシスタントがプレビューを見せて先に確認します。あなたの同意はその操作だけに有効で、途中で状況が変わると失効します。

操作の前に、アシスタントは `specrails_overview` で 1 つのプロジェクトの現在の状況（スペック、実行、Git の状態）を確認できます。取得できないセクションは明示的に報告され、プロジェクトが空という意味ではありません。ソースコードを変更せずに検索し、行単位で読むこともできます。

外部 MCP セッションごとに、選択中のプロジェクトは独立しています。ミッションモードでは、会話に固定されたプロジェクトが既定になり、ミッションの画面で変更します。MCP の選択でそれを上書きすることはできません。呼び出しで別のプロジェクトを指定すると、意図的にそのプロジェクトが対象になります。

## これで何ができるか

アシスタントを接続したあとの、いくつかのレシピを紹介します。すべてデフォルトでオンです。当面は観察だけさせたい場合は、Settings ▸ MCP で **Write**（書き込み）や **AI-spawn**（AI 起動）のチェックを外してください。

**ほかのツールにある作業をスペックに変える。** アシスタントが GitHub、Jira、Gmail、Slack にも接続されていれば、その作業をあなたの代わりに Specrails へ持ち込めます。
> *「今週の 'bug' ラベルの付いた未解決の GitHub Issue を取り込んで、API プロジェクトにそれぞれスペックを作って、起動して。」*
>
> *「最新の顧客フィードバックのメールを読んで、テーマごとにまとめて、テーマごとにスペックを 1 つずつ作って。」*

**夜通しのオートパイロット。** アプリをトレイに置いたまま走らせておけば、戻ってきたときにはレポートができています。
> *「アイデアが 12 個あります。それぞれをスペックにして、レールで 3 つずつ起動して、すべてのジョブを見守って、明日になったら何が完了して、何が失敗して、いくらかかったかをまとめて教えて。」*

**Destructive**（破壊的操作）のチェックを外しておけば、何ひとつ削除することなく一晩中ビルドを続けられます。

**すべてのプロジェクトをまたいで。** ダッシュボードだけではできないことです。
> *「すべてのプロジェクトを確認して。バックログにスペックがあるのにレールが走っていないプロジェクトを教えて、それぞれで優先度が一番高いものを起動して。」*

**コーディング中もハンズフリー。** ウィンドウを切り替えずに、エディタや音声から Specrails を操作できます。
> *「スペック #42 のためにレール 0 を Opus で起動して、終わったら教えて。」*

**コストと履歴を尋ねる。** アナリティクスを平易な言葉で。
> *「今週、AI に一番お金を使ったのはどこ？ プロジェクト別とモデル別で。一番高かったスペックを 5 つ見せて。」*

**毎日のスタンドアップ。**
> *「スタンドアップを書いて。昨日どのレールが走って、何が完了して、何が失敗して、合計コストはいくらか — Slack にそのまま貼れる箇条書きで。」*

**コードを理解する。** エディタは不要です。
> *「スペック #38 がどのファイルに触れたか教えて。それぞれ何が変わったかを 1 行で要約して。」*

アシスタントはまず組み込みのガイドを読むので、ツールやスペックの名前をあなたが指定する必要はめったにありません — 望む結果を伝えれば、アシスタントが呼び出しを組み立ててくれます。

## 知っておきたいこと

- **Specrails が起動している必要があります。** MCP サーバーはアプリの内部に存在するため、アシスタントが到達できるのは Specrails が開いている間だけです。トレイのおかげで、ウィンドウを閉じてもバックグラウンドで動き続けます — 実際に停止させるには、トレイ（Mac のメニューバー／Windows のシステムトレイ）から **Exit** を選ぶ必要があります。
- **長い操作はストリームされます。** レールの起動やスペックの生成はすぐに戻り、バックグラウンドで完了します。アシスタントはそれを「見守り」、決着したときに報告してくれます。
- **セキュリティ。** MCP は他のすべてとは分離された専用のアクセストークンを使い、あなた自身のマシン上（ループバック）でのみ待ち受けます。このトークンは、ティア・プロジェクト・会話のヘッダーを指定してエージェントモードになりすますことはできません。組み込みのエージェントは、サーバーが発行する非公開で短命なケイパビリティを使います。スコープ付きのトークンはパネルからいつでもコピー、または再生成できます。
- **公開されていないもの（v1）。** 安全のため、外部の MCP クライアントは、生のターミナルのシェルコマンドの実行、組み込みブラウザの使用、アプリ内でのファイル編集、システム前提条件のインストールができません。エージェントモードには、Autonomous 権限で確認済みの長時間バックグラウンドコマンドを実行するための、認証された別の経路があります。外部クライアントは Destructive を有効にしてもそれを得られません。Specrails を*管理する*ものはそれ以外すべて利用できます。

MCP は同じパネルからいつでも無効にできます — アシスタントはアクセスを失うだけで、それ以外は何も変わりません。
