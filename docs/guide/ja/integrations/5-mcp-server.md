# 任意の AI から Specrails を操作する（MCP サーバー）

Specrails は、[Model Context Protocol](https://modelcontextprotocol.io) を話す任意の AI アシスタント（Claude Desktop、Claude Code、Cursor、Cline、あるいは自作のエージェント）に対して、**自分自身**を公開できます。これをオンにしてアシスタントを Specrails に向ければ、チャットするだけでアプリ全体を操作できます。たとえば *「プロジェクト一覧を見せて」「API プロジェクトにソーシャルログインのスペックを作って」「レール 0 を起動して、終わったら教えて」「今週はいくら使った？」* といった具合です。あなたがあちこちクリックする代わりに、アシスタントが裏側で Specrails のツールを呼び出します。

これは、プラグインや「My approved MCPs」機能とは逆方向の働きをします。それらは Specrails が*ほかの* MCP サーバーを*使う*ためのものですが、こちらは他のアプリに **Specrails** を使わせるためのものです。

## オンにする

これは**デフォルトでオフ**です。**Settings ▸ MCP** を開いて **Enable MCP** を切り替えてください。それだけです — サーバーは即座に起動し、再起動は不要です。

外部の AI がどんな操作をできるかは、一連の権限ティアで*あなた*がコントロールできます。

| ティア | 許可される内容 | デフォルト |
|---|---|---|
| **Read**（読み取り） | プロジェクト、スペック、ジョブ、アナリティクスなどの一覧表示と確認 | 常時オン（MCP が有効なとき） |
| **Write**（書き込み） | スペックの作成・編集、設定やレール構成の変更 | オフ — 任意で有効化 |
| **AI-spawn**（AI 起動） | AI を走らせて**お金がかかる**操作（レールの起動、スペックの生成、チャットターンの送信） | オフ — 任意で有効化 |
| **Destructive**（破壊的操作） | プロジェクト／スペック／ジョブの削除、実行中の作業の停止 | オフ — 任意で有効化 |

無効なティアに該当する操作をアシスタントが試みると、Specrails はそれを拒否し、どのティアをオンにすればよいかを明確なメッセージで知らせます。ですから、まずは読み取り専用から始め、必要なものだけをぴったり開放できます。

## アシスタントを接続する

パネルには、そのまま貼り付けられる構成ブロックが表示されます。最もシンプルで汎用的な方法は、同梱の**ブリッジ**（`specrails-mcp`）を使うことです。アシスタントがこれを実行し、ブリッジがあなたに代わって Specrails に中継します。ブリッジはアクセストークンをローカルで読み取るので、**トークンがアシスタントの設定に現れることはありません**。

Claude Desktop や Cursor のようなクライアントでは、設定は次のようになります。

```json
{ "mcpServers": { "specrails": { "command": "specrails-mcp" } } }
```

リモートの HTTP MCP サーバーに対応しているクライアントなら、代わりにパネルのトークンを使って `http://127.0.0.1:4200/api/mcp` を直接指すこともできます。

### ターミナルから: Claude Code、Gemini CLI、Codex CLI

**設定 ▸ MCP ▸ トークンをコピー** からトークンをコピーして、次を実行します:

```bash
# Claude Code
claude mcp add --transport http specrails http://localhost:4200/api/mcp \
  --header "X-Desktop-Token: <あなたのトークン>"

# Gemini CLI
gemini mcp add --transport http specrails http://localhost:4200/api/mcp \
  --header "X-Desktop-Token: <あなたのトークン>"

# Codex CLI (stdio — 設定 ▸ MCP に表示されるブリッジコマンドを登録)
codex mcp add specrails -- <設定 ▸ MCP のブリッジコマンド>
```

`Authorization: Bearer <token>` ヘッダーも使えます。アプリのポートを変更している場合は `4200` を置き換えてください。

接続が完了すると、アシスタントにはアプリ全体をカバーする約 **18 個のツール**が見えるようになります — プロジェクト、スペック、レールとジョブ、チャット／Explore、エージェント、プラグイン、Jira、ループ、コードエクスプローラー、アナリティクス、設定など。さらに、最初に読み込む組み込みの**ガイド**ツールも含まれているので、あなたが何も説明しなくても、アシスタントは Specrails の仕組みを理解できます。

## これで何ができるか

アシスタントを接続したあとの、いくつかのレシピを紹介します。まずは **Read**（読み取り）をオンにして始め、実際に作業を作成・起動させたくなったら **Write**（書き込み）と **AI-spawn**（AI 起動）をオンにしてください。

**ほかのツールにある作業をスペックに変える。** アシスタントが GitHub、Jira、Gmail、Slack にも接続されていれば、その作業をあなたの代わりに Specrails へ持ち込めます。
> *「今週の 'bug' ラベルの付いた未解決の GitHub Issue を取り込んで、API プロジェクトにそれぞれスペックを作って、起動して。」*
>
> *「最新の顧客フィードバックのメールを読んで、テーマごとにまとめて、テーマごとにスペックを 1 つずつ作って。」*

**夜通しのオートパイロット。** アプリをトレイに置いたまま走らせておけば、戻ってきたときにはレポートができています。
> *「アイデアが 12 個あります。それぞれをスペックにして、レールで 3 つずつ起動して、すべてのジョブを見守って、明日になったら何が完了して、何が失敗して、いくらかかったかをまとめて教えて。」*

**Destructive**（破壊的操作）をオフにしておけば、何ひとつ削除することなく一晩中ビルドを続けられます。

**すべてのプロジェクトをまたいで。** ダッシュボードだけでは単独でできないことです。
> *「私のプロジェクトを全部チェックして。バックログにスペックがあるのにレールが 1 つも動いていないものを教えて、それぞれで最も優先度の高いものを 1 つ起動して。」*

**コーディング中も手を止めずに。** エディタからでも音声でも、ウィンドウを切り替えずに Specrails を操作できます。
> *「チケット #42 のためにレール 0 を Opus で Freestyle モードで起動して、終わったら教えて。」*

**コストと履歴について尋ねる。** あなたのアナリティクスを、普通の言葉で。
> *「今週、AI に一番お金を使ったのはどこ？ プロジェクト別とモデル別で。最もコストのかかったチケットを 5 つ見せて。」*

**毎日のスタンドアップ。**
> *「私のスタンドアップを書いて。昨日どのレールが走って、何が完了して、何が失敗して、合計コストはいくらか — Slack にそのまま貼れる箇条書きで。」*

**コードを理解する。** エディタは不要です。
> *「チケット #38 がどのファイルに触れたか教えて。それぞれ何が変わったかを 1 行で要約して。」*

アシスタントはまず組み込みのガイドを読むので、ツールやスペックの名前をあなたが指定する必要はめったにありません — 望む結果を伝えれば、アシスタントが呼び出しを組み立ててくれます。

## 知っておきたいこと

- **Specrails が起動している必要があります。** MCP サーバーはアプリの内部に存在するため、アシスタントが到達できるのは Specrails が開いている間だけです。トレイのおかげで、ウィンドウを閉じてもバックグラウンドで動き続けます — 実際に停止させるには、トレイ（Mac のメニューバー／Windows のシステムトレイ）から **Exit** を選ぶ必要があります。
- **長い操作はストリームされます。** レールの起動やスペックの生成はすぐに戻り、バックグラウンドで完了します。アシスタントはそれを「見守り」、決着したときに報告してくれます。
- **セキュリティ。** MCP は他のすべてとは分離された専用のアクセストークンを使い、あなた自身のマシン上（ループバック）でのみ待ち受けます。このトークンはパネルからいつでもコピー、または再生成できます。
- **公開されていないもの（v1）。** 安全のため、いくつかの高リスクな機能は意図的に除外されています。ターミナルでのシェルコマンド実行、組み込みブラウザ、アプリ内でのファイル編集、システム前提条件のインストールなどです。Specrails を*管理する*ものはすべて利用できますが、マシンへの生のアクセスはできません。

MCP は同じパネルからいつでも無効にできます — アシスタントはアクセスを失うだけで、それ以外は何も変わりません。
