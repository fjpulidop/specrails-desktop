# ローカル AI エンジン

自分でホストしたモデル（Ollama、llama.cpp、LM Studio、vLLM、または OpenAI chat-completions API を話す任意のサーバー）で Specrails を動かせます。接続すると、ローカルエンドポイントは他と同じエンジンになります。レールのヘッダー、スペック追加（Quick と Explore）、サイドバーチャット、エージェントミッションに表示されます。

## エンドポイントを接続する

1. **設定 ▸ Specrails エージェント ▸ プロバイダー接続** を開き、**ローカルエンジンを追加** を選びます。
2. id、ベース URL（例 `http://127.0.0.1:11434/v1`）を入力し、サーバーがキーを必要とする場合はキーを保持する**環境変数名**を入力します。キー自体は保存されません。Specrails は実行開始時にアプリの環境から読み取ります。
3. **接続をテスト** を押します。サーバーが応答するとピルが緑になり、提供モデルが一覧表示されます。デフォルトモデルを選びます。
4. **保存**。エンジンはすぐに使えます。再起動は不要です。

> Finder、Dock、スタートメニューからアプリを起動すると、シェルの export は引き継がれません。カードに変数が*アプリプロセスに設定されていない*と表示される場合は、システム全体で設定するか、その変数を持つターミナルからアプリを起動してください。キー不要のサーバーには何も必要ありません。

各接続には **エージェントループ** の設定もあります。**コンパクト**（既定）は小さなモデルを短い構造化ステップで導き、7–14B のモデルでも implement を完走させます。**フリー** は強力なモデル（約 30B 以上）向けの従来型の単一エージェントループです。**コンテキストウィンドウ** はサーバーの実際のサイズに合わせてください。サーバーがリクエストを拒否する前に Specrails が圧縮します。

## できること

- レール（implement、batch、freestyle、カスタムループ）、Explore と Quick スペック、チャット、ミッションがローカルモデルで動作します。
- ミッションは Specrails ツールと外部 MCP サーバーをそのまま使えます。
- セッションはターンをまたいで再開でき、インタラクティブジョブも動作します。
- コストは正直です。トークンは記録され、レートを入力しない限りコストは*不明*のまま（入力すると*推定*と表示）。

ローカルエンジンで利用不可：エージェントプロファイルとカスタムロール、SMASH / Contract Layer の拡充、Project Builder 生成、添付ファイル、パイプラインテレメトリ。

> ミッションにはサーバー側に**大きなコンテキストウィンドウ**（64k トークン以上）が必要です。オペレータープロンプトと Specrails ツールのスキーマは大きいためです。チャットと Explore は 32k で十分です。ターンが *exceeds the available context size* で失敗する場合は、ウィンドウを拡大してください（Ollama `OLLAMA_CONTEXT_LENGTH`、llama.cpp `-c`、LM Studio *Context Length*）。

## モデルの選び方

品質は Specrails ではなくモデル次第です。レールには 30B パラメータ以上のツール呼び出し対応コーダーモデルを使ってください。小さな instruct モデルはチャット、Explore、Quick スペックには十分です。新しいモデルに implement レール全体を任せる前に、**Freestyle** か Explore セッションで試してください。

## 無効化

アプリ環境で `SPECRAILS_LOCAL_ENGINES=false` を設定すると、ローカルエンジンはすべての場所から消えます。保存済みの接続は保持され、プログラマティックランタイムのロール別プロバイダーとしては引き続き有効です。
