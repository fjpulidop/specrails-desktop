# スペックとバックログ

**スペック**は、AI パイプラインが実装する作業の単位です。チケットのようなものだと考えてください。タイトル、やってほしいことの説明、優先度、そして任意のラベルで構成されます。パイプラインを起動すると、AI エージェントたちがこのスペックを読んでそれに沿って動きます。つまり、わかりやすいスペックこそが、よい結果を生むための一番大切な入力なのです。

アプリ内ではスペックを**チケット**と呼ぶこともありますが、どちらも同じものを指しています。

## ボード

どのプロジェクトも、開くとまず**ダッシュボード**が表示され、そこに**SpecsBoard**（プロジェクトのすべてのスペックの一覧）が並びます。これがあなたのバックログです。ここから新しいスペックを作成したり、優先度を設定したり、スペックをレールにドラッグして実装したり、作業が進むにつれて変わっていくステータスを眺めたりできます。

ボードには 2 つの表示モードがあり、ツールバーのトグルで切り替えられます。設定はプロジェクトごとに記憶されます。

- **付箋表示**（デフォルト）— 短い概要が添えられたカード形式のタイル。
- **リスト表示** — 1 行ずつのコンパクトな表示。

スペックのツールバーは 2 段構成です。1 段目には**検索**フィールド（`/` キーで移動。タイトル・`#番号`・ラベル・Jira キーで検索）、ひとつにまとまった**フィルター**ボタン、並べ替えと表示の切り替え、そして**新規スペック**があります。2 段目は**ステータスセレクター**です。各ステータスがライブカウント付きの独立したセグメントとして並び、さらに 2 つのスマートグループがあります：**アクティブ**（デフォルト。下書き・Todo・進行中・レビュー中など、まだ動いているものすべて）と**すべて**（全部を表示し、完了は一番下に固定）。列が狭いときは使用頻度の低いステータスが**その他**メニューにまとまり、選んだステータスは常に表示されたままです。選択はプロジェクトごとに記憶され URL にも反映されるため、リロードや共有リンクでもまったく同じビューが復元されます。**フィルター**を開くと、項目ごとのセクションを持つパネルがひとつ表示されます：**ラベル**（複数選択）と、Jira に接続したプロジェクトでは**エピック**・**スプリント**・**Jira ステータス**（ボードの*実際の*ワークフローステータス。例：「Code Review」。対応する状態ごとにグループ化され、ステータスセレクターと組み合わせて使えます）。検索やフィルターでボードを絞り込んでいる間は、3 段目に各条件が解除可能なチップとして並び、「y 件中 x 件」の表示と**すべてクリア**（選んだステータスは維持）が出ます。並べ替えは**デフォルト**・**チケット #**・**優先度**から選べ、それぞれ昇順／降順を切り替えられます。

## ステータス

スペックは、いくつかのステータスの間を移っていきます。ボードはそれぞれに一貫した視覚的な目印を付けてくれるので、バックログの状態をひと目で把握できます。

| ステータス | 意味 |
|--------|---------------|
| **下書き** | Explore の会話から保存した、作りかけのアイデア。まだ実装の準備はできていません。あとから戻ってきて、引き続き形にしていけます。`Draft` のピルが表示されます。 |
| **Todo** | これから着手できる状態。スペックを作り終えると、ここに着地します。 |
| **進行中** | パイプラインが現在作業中です（青い点が点滅します）。 |
| **レビュー中** | 実装済み — 実行が終わるとスペックはここで承認待ちになります。ドラフト PR をマージするか、自分で先へ移動してください（琥珀色のピル）。 |
| **完了** | 承認済み — PR がマージされたか、自分でここへ移動しました（緑のチェックマーク）。 |
| **キャンセル** | 取りやめになりました（赤い X）。 |

下書きは Todo のスペックと同じアクティブな枠に並びます（専用の列はありません）が、ほんのり色づいたボーダーと `Draft` ピルが付いているので、すぐに見分けられます。下書きについての詳しい話は[下書きと Contract Layer](drafts-and-contract-layer.md)をご覧ください。

## 優先度

下書き以外のすべてのスペックには、**クリティカル**・**高**・**中**・**低**のいずれかの優先度が付きます。優先度はあくまで整理のための道具で、次に何を実装するか決めたり、ボードを並べ替えたりするのに役立ちます。スペックを作成するときに設定でき、あとからでもスペックカードを右クリックして**優先度を設定**を選べばいつでも変更できます。

下書きだけは例外で、優先度をまったく持たないことができます。まだ作りかけのアイデアだからです。優先度は、下書きを本物のスペックとしてコミットしたときに確定します。

## スペックを作成する

スペックを作成するには、**新規スペック**（SpecsBoard ツールバーのプラスボタン）をクリックします。**スペックを追加**ダイアログが開き、いくつかの方法から選べます。

- **クイックモード** — やりたいことを記述すると、AI が一発でスペック全文を書き上げます。[スペックを追加 — クイックモード](add-spec-quick-mode.md)を参照。
- **Explore モード** — AI と対話しながら、ターンを重ねてスペックを形にしていきます。[スペックを追加 — Explore モード](add-spec-explore-mode.md)を参照。
- **Raw モード** — 入力した内容がそのままスペックとして保存されます。AI は一切関与しません。すでにスペックの文章が手元にあるときに使ってください。

どれを選ぶかは、アイデアがどれだけ固まっているかによります。やりたいことがはっきり見えているならクイック、まだ考えをまとめている途中なら Explore、すでに文章があるなら Raw です。

## 補足 — 既存のスペックを反復する

スペックにすでに成果物（レビュー中の PR、マージ済みの機能）があり、*さらに*何かを求めるときは、説明文を書き直さないでください。スペックの本来の意図がぶれ（そのぶれが Jira にも同期され）、次回の実行がすべてを再計画してしまいます。代わりにスペックを開いて**補足**を追加します。種類（変更依頼、レビューフィードバック、明確化、制約）とあなた自身の言葉による短いメモです。未処理の補足は、Implement・SDD Quick・Freestyle などどのループでも、そのスペックの次回起動に自動的に同行し、実行はあなたが求めたことだけを変更します。レビューパケットは各補足を「適用済み / 一部適用 / ブロック」として報告します。実行が失敗したり納品を破棄したりすると、補足は自動的に**未処理**に戻ります。既存スペックの変更をミッションエージェントに頼めば、エージェントが補足を追加してくれます。

## 納品物をレビューする — 最初に確認すべき点

実行が終わると、レビューパケットは **確認すべき点** から始まります。AI レビュアーによる短い概要で、最もリスクの高い箇所を先に（高・中・低の順に、それぞれファイルと行付きで）挙げ、変わる動作、変更が依存するルール、どのテストも通らないコードパス、人にしかできない確認を示します。同じリスク、テストされていないパス、確認項目はプルリクエストの冒頭にも短くまとめられ、ミッションカードには最大のリスクが 1 行で表示されます。概要はレビューの手がかりであり検証結果ではないため、承認をブロックすることはありません。古い Specrails Core で実行したものには概要がなく、パケットはこれまでどおり表示されます。

## 元に戻す、そして最近削除した項目

スペックの削除、ステータスの移動、ラベルの変更、レールからの取り外しは、すぐに反映されます。事前に「よろしいですか？」と尋ねることはありません。代わりに、約 8 秒間、トーストに **元に戻す** が表示され、フィールドに入力していなければ **⌘Z**（Windows と Linux では **Ctrl+Z**）でも同じ操作ができます。元に戻す操作はプロジェクトごとです。プロジェクトを切り替えると、その時間枠は閉じます。

削除したスペック（とミッション）は消えません。プロジェクト設定の **設定 → 最近削除した項目** に移り、30 日間は **復元** または **完全に削除**（こちらは確認があります）ができます。30 日を過ぎると完全に削除されます。未プッシュの作業の破棄、プルリクエストの強制クローズ、プロジェクトの削除は元に戻せないため、引き続き確認が出ます。Jira に紐づくスペックは、削除ではなく従来どおり **移動先** で扱います。
