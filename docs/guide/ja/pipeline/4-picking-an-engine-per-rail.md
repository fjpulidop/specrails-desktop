# プロバイダーとその機能を選ぶ {#provider-capabilities}

実行設定は、選んだプロバイダーに属します。見慣れたモデル名だからといって、すべてのプロバイダーが同じ推論、構造化出力、承認の制御に対応しているとは限りません。

## まず利用可能かを確認する

プロバイダーの CLI を認証し、Specrails でそのステータスを確認します。モデルと推論の強さは、そのプロバイダーのコントロールが提示するものから選んでください。CLI がインストール済みでも、セッション、クォータ、リモートサービスが利用できないために失敗することがあります。

Claude と Codex はアダプターが異なります。サポートされていない組み合わせは、Loop が始まる前に失敗するべきです。たとえば、ツールなしの構造化レスポンスを必要とするステップが、すべてのプロバイダーで動くとは想定できません。

## 適切なレベルの制御を使う

レールのプロバイダー／モデルの選択が、その実行を決めます。ギャラリーの Freestyle Loop はすべての CLI プロバイダーとローカルエンジンで動きますが、ジョブ内の対話型チャットが加わるのは Claude だけです。ロールのプロファイルとエージェントごとのルーティングは、プロバイダーと、Desktop がプロジェクトにインストールした Core ワークフローによって決まります。プロファイルがすべての呼び出しを変えると思い込まず、実際に有効な設定を確認してください。

実行を比較するときは、同じスペック、同じリポジトリのリビジョン、同じ検証基準を保ってください。報告されたコスト、推定コスト、取得できないコストは区別して扱います。[プロファイル](../agents/profiles-and-the-balanced-default)と[使用量](../insights/analytics-and-cost-tracking)を参照してください。

ミッションからの起動では、Loop のステップはミッションのプロバイダー、モデル、推論の強さを引き継ぎます。ただし、Loop エディターでエージェントが明示的に上書きした場合は別です。一般設定ではプロバイダーとの接続を管理します。以前の「プロバイダーの既定値」ブロックと「ロール」セレクターは、もう提供されていません。
