# エージェントの安全ポリシー {#agent-safety-policy}

レール、ループ、ミッションのエージェントは、コマンドごとに確認を求めずに作業します。そのため高速ですが、エージェントに任せるには危険すぎる操作がいくつかあります。Specrails は **Claude** エージェントのすべてのツール呼び出しを実行前に短い禁止リストと照合し、リストに該当するものをブロックします。

## ブロックされるものとその理由

| ブロック対象 | 理由 |
|---|---|
| **強制プッシュ**（`--force`、`--force-with-lease`、`+branch`、`--mirror`） | 共有の履歴を書き換えるため。 |
| **統合ブランチへのプッシュ**（プロジェクトのデフォルトブランチ、`main`、`master`） | 作業は人がマージするプルリクエストを通じてのみ届くため。 |
| **リモートブランチの削除** | ブランチは配信と一緒に片付けられ、エージェントが削除するものではないため。 |
| **実行ブランチ以外での `git reset --hard`** | 実行内の実行ブランチでは許可されます。それ以外では他人の作業を壊すおそれがあります。 |
| **保護されたブランチ、実行自身のブランチ、実行外のブランチの削除** | 同じ理由です。 |
| **プルリクエストのマージ**（`gh pr merge`） | 何をマージするかはあなたが決めます。 |
| **実行外での再帰的な削除**（`rm -rf`、`rimraf`、`find -delete`、`git clean -f`） | 消去してよいのは実行のワークツリーと一時フォルダーだけです。対象が分からない削除（`rm -rf "$DIR"`、`xargs rm -rf`）もブロックされます。 |
| **認証情報の読み書き**：`~/.ssh`、`~/.aws`、`~/.gnupg`、キーチェーン、Specrails のシークレットストア | エージェントがあなたの鍵を必要とすることはありません。 |
| **ポリシー自身のファイルの変更** | エージェントがポリシーを無効にできないようにするため。 |

それ以外はこれまでどおり動作します。

## 表示されるもの

- エージェントは理由を受け取り、その操作なしで作業を続けるか、必要なものを説明します。
- 実行ログまたはミッションに、ルールと理由を添えた **Specrails のポリシーによりブロックされました** の行が表示されます。
- [エージェント操作の監査](3-reviewing-a-delivery.md)は、試みた操作の隣に各ブロックを記録します（ソース `policy-hook`）。

## 適用範囲

- 分離されたレール、ループ、Intent セッション（それぞれ専用のワークツリーで実行）とミッション。
- **Claude のみ。** Codex には、あなた自身の Codex 設定を変えずに Specrails がインストールできる同等の仕組みがありません。Codex の実行では、Specrails は各ターンの後にブランチと配信を引き続き確認します。
- プロジェクトフォルダーで直接作業する（分離されていない）実行は対象外です。Specrails はあなた自身のチェックアウトに書き込みません。
- macOS と Linux。Windows ではまだインストールされません。

## 知っておくと便利なこと

- これはガードレールであり、サンドボックスではありません。よくある破壊的なコマンドを止めますが、悪意のあるエージェントを安全にするものではありません。
- チェック自体が失敗した場合、呼び出しはそのまま実行されます。ただし禁止リストに該当しそうな場合はブロックされます。壊れたチェックがすべてのエージェントを止めることはありません。
- 緊急時に無効にするには、`SPECRAILS_AGENT_POLICY_HOOK=false` を指定して Specrails を起動します。
