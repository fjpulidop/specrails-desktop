# ジョブ詳細ビュー

**ジョブ** ページでどれかのジョブカードをクリックすると、ここにたどり着きます。1 回のレール実行のためのコックピットです。このビューはたった 1 つの約束を軸に作られています — **あなたが目にするライブの数値は本物であり、決して推測ではありません。** このページでは、フェーズ、ライブメトリクス、チケットカード、そして**実行中のジョブと会話できる**コンポーザーをひととおり見ていきます。

## レイアウト

ストリーミングログ全体の上に 2 つのパネルが並び、実行中の Claude ジョブではその下にチャットコンポーザーが表示されます。

```
┌─────────────────────────────────────────────┐
│  ステータスヘッダー  (アイコン · ライブ所要時間 · …)  │
├─────────────────────────────────────────────┤
│  チケットヘッダー  ( #12  #14  #15 )           │
├─────────────────────────────────────────────┤
│                                             │
│  ストリーミングログ  (自動スクロール · 検索 · …)  │
│                                             │
├─────────────────────────────────────────────┤
│  コンポーザー  (ジョブにメッセージを送る · …)   │
└─────────────────────────────────────────────┘
```

## パイプラインのフェーズ

`Implement` と `Batch` のジョブでは、スラッシュコマンドが定義するフェーズに沿って実行が進みます — デフォルトでは次のとおりです。

```
Architect ──► Developer ──► Reviewer ──► Ship
```

各フェーズは、レールのエンジンがあなたのプロジェクトディレクトリ内で呼び出す専用エージェントです。

| フェーズ | エージェント | 役割 |
|-------|-------|--------------|
| **Architect** | `sr-architect` | 実装を設計します。 |
| **Developer** | `sr-developer` | コードを書きます。 |
| **Reviewer** | `sr-reviewer` | 出力をレビューします。 |
| **Ship** | （状況による） | 最終仕上げ: テスト、コミット、PR ドラフト。 |

どのフェーズをどのエージェントが担当するかは、プロジェクトの **エージェントプロファイル** で決まります。基本の 3 つ（`sr-architect`、`sr-developer`、`sr-reviewer`）は常に存在し、プロファイル内のルーティングルールでエージェントを追加したり、あるフェーズを担当するエージェントを差し替えたりできます。フェーズの進捗バーは、コマンドが実際にフェーズを定義しているときだけ表示されます — パイプラインをバイパスする Freestyle ジョブでは表示されません。

## ライブメトリクス — 設計からして誠実

ステータスヘッダーが主役です。ステータスアイコン、ジョブが*いままさに*何をしているかを表すアクティビティ行、踏んだステップ数、そしてメトリクスの一行が表示されます。

| メトリクス | 本物の値が見えるタイミング |
|--------|------------------------------|
| **所要時間** | **ライブ。** ジョブの実行中、1 秒ごとのティッカーがカウントアップします — これが唯一、純粋にライブな数値です。 |
| **ターン数** | 届いたストリーミングのアシスタントイベントから逐次的に算出されます。 |
| **トークン** | 同じストリームから逐次的に集計されます（usage フィールドが欠けているイベントにも耐えます）。 |
| **コスト** | ジョブが終了するまで `—` と表示され、終了時に信頼できる `total_cost_usd` として明かされます。 |

設計思想はこうです — **実行中に概算値や推定値を出さない。** 所要時間が本物なのは、それがただの時計だからです。ターン数とトークンは、実際にストリーミングされたアクティビティから積み上げられます。コストは実行中はあえて推定しません — 保留として表示し、ジョブ終了時にプロバイダーが報告して初めて、最終的で信頼できる数値に確定します。数値が待機しているように見えるなら、それは意図したものです — あなたに見せているのは予測ではなく真実なのです。

ヘッダーのラベルとアイコンはジョブのステータスに対応し、このパネルは `running`、`completed`、`failed` のいずれのジョブでも描画されます — つまり、終わったジョブの詳細ビューでも、最終値で固定された同じメトリクスが見られます。

## チケットカード

**チケットヘッダー** は、ステータスヘッダーとログの間にあります。これはプレミアムな識別カードで、ジョブが触れたすべてのスペックのチップを表示します — 起動したコマンドから照合されるので、この実行がどのチケットに関するものだったかを正確に反映します。

- **2〜3 件のチケット** — チップのリストとして表示されます。
- **4 件以上** — コンパクトな `+ N more` 表示に折りたたまれ、展開用のシェブロンが付くので、ヘッダーがすっきりと保たれます。

チップをクリックすると、そのスペックの詳細が **ジョブページの上に重ねて** 開きます — 自分の居場所を見失うことも、ルートが変わることもありません。ジョブが何を届けるはずなのかを、作業を見守りながらサッと読み返すのに便利です。（タブレット幅の画面では、チケットモーダルを横にドラッグして 2 つのスペックを並べて比較することもできます。）

## ストリーミングログ

パネルの下には、WebSocket 越しにリアルタイムでストリーミングされる実行の全ログがあります。

- **自動スクロール** で最新の出力を視界に保ちます（上にスクロールすると一時停止するので、じっくり読めます）。
- **検索** でフレーズへジャンプできます。
- **コピー** でログ全体をつかめます。

これは AI が何をしているかの生の真実です — すべてのツール呼び出し、すべてのファイル編集、すべてのテスト実行が映ります。

## Loop の実行: ステップエクスプローラー

ジョブが **Loop の実行**（[Loop Builder](the-loop-builder) を参照）の場合、フラットなログの代わりに、Loop の実際の形をなぞる**ステップエクスプローラー**が表示されます。

- 上部の**オーバービューストリップ**は Loop のライブマップです — ノードごとにひとつのチップ（AI ステップ、シェル、ループ判定…）が、グラフの流れる順に並びます。チップは実行の進行に合わせて灯っていきます: 待機中は薄く、実行中は脈動し、終わればチェックかバツが付きます。判定ノードのチップには実際に採った裁定 — ループに戻るか、先へ進むか — も表示され、右側の反復カウンター（`反復 3/10`）が回数を刻みます。チップをクリックすると、そのノードの最新のステップへ直接ジャンプします。
- **ステップごとに折りたたみ可能なボックス。** ノードを通るたびにそれぞれ独立したセクションになり、ステップ番号、名前、反復バッジ、完了後の所要時間 — さらに専用のコピーボタンが付くので、ひとつのステップの出力だけを正確に持ち出せます。（ツールバーのコピーは従来どおりログ全体を対象にします。）最初のステップより前に出力されたもの — 実行バナーや worktree の通知 — は**セットアップ**セクションにまとめられます。
- **追従モード**はデフォルトでオンです: 実行中のステップは開いたまま自動スクロールし、前のステップは折りたたまれて道を空けます。上へスクロールしたり古いステップを開いたりした瞬間、読めるように追従は一時停止します — フローティングの**追従を再開**ピルでライブに戻れます。**すべて展開 / すべて折りたたむ**はツールバーにあり、検索ボックスに入力するとすべてのステップを横断して検索します。
- **中断されたステップも誠実です。** 結果を報告できないまま終わったステップ — 実行がキャンセルされた、あるいはステップの途中でアプリが落ちた — は、終わったふりをせず、破線の枠で**中断**と印付けされます。

このページのそれ以外はすべて、Loop の実行でもまったく同じに動きます — ライブメトリクス、チケットカード、コンポーザー。Loop ではないジョブは、上の従来のストリーミングログのままです。

## 実行中のジョブと会話する

すべての Claude ジョブはデフォルトで**ライブセッション**として実行されるため、このページの下部 — そしてミッションモードのジョブモーダルの下部 — にチャットコンポーザーが表示されます。実行中のエージェントに質問したり（「あのテストはなぜ失敗した？」）、実行の途中で方向を示したり（「リファクタは飛ばして、修正に集中して」）するのに使えます。

知っておくと便利なポイント:

- **メッセージはキューに入り、割り込みません。** エージェントがストリーミング中に送信しても、メッセージは順番を待ちます — 次のプロンプトとして実行され、ジョブは自分の計画を進め続けます。小さなカウンターが、待機中のメッセージ数を表示します。
- **合計の行は本物です。** コンポーザーはライブの `N ターン · $X` サマリーを表示します。完了した各ターンの実際の使用量を合算したもので、このページの「推測しない」という約束と一貫しています。
- **セッションの終わり方は 2 通り。** ほとんどのジョブは**自分で締めくくります**。キューにメッセージが残っていない状態でターンが終わった瞬間、セッションは自ら落ち着き、ジョブは完了します — あなたのメッセージは任意の舵取りであって、義務ではありません。控えめな**今すぐ締めくくる**アクションで、それまでの成果を保ったまま早めに終わらせることもできます。**Freestyle** ジョブだけは例外です。ターンの合間で待機し、あなたが **Finalize** をクリックするまで開き続けます — あなたが閉じる往復のセッション、それが Freestyle の設計です。
- **Loop 実行では、メッセージはアクティブなステップに届きます。** 組み込みでもカスタムでも、Loop 上ではメッセージは**いままさに実行中の AI ステップ**に届きます。ステップの合間（Loop Decider が考えている間や、シェルコマンドの実行中）には、コンポーザーは*「次のステップを待っています…」*という短い待機状態を表示します — 下書きのテキストは保持され、次の AI ステップが始まると送信が再び有効になります。**このステップを確定**すると現在のステップを早めに終わらせ、その成果とともに Loop を先へ進められます。
- **今のところ Claude のみ。** Codex と Gemini のジョブは従来どおりワンショットで実行されます — コンポーザーは表示されません。（サーバー運用者は `SPECRAILS_INTERACTIVE_JOBS=false` で機能全体を無効化できます。）

## 診断のエクスポート

そのジョブで [テレメトリ](../settings/customizing) が有効になっていた場合、ヘッダーに **診断をエクスポート** ボタンが表示されます。クリックすると次のものを含む ZIP がダウンロードされます。

- `job-metadata.json` — コマンド、ステータス、プロファイル、プラグイン。
- `telemetry.ndjson` — 非圧縮の OTLP/JSON シグナル。
- `logs.txt` — ストリーミングログの全文。
- `summary.md` — 人が読みやすいハイライト。
- `profile.json`、`plugins.json` — 実際に動いたものの正確なスナップショット（存在する場合）。

実行内容を仲間と共有したり、正確なバグレポートを提出したりするのに便利です。
