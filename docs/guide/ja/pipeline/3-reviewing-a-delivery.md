# アプリ内で納品をレビューする {#review-a-delivery}

レビュー待ちの納品には 2 つの表示があります。**概要**（結論、根拠、判断ボタン）と**変更**（納品が実際に何を変えたか）です。納品の**レビュー**ボタンからレビューを開き、**変更**を選びます。

## 変更を読む

左のファイル一覧には、変更された各ファイルの状態（追加、変更、削除、名前変更）、`+` と `−` の行数、確認済みにしたときのチェックが表示されます。右の差分は 1 ファイルずつ読み込まれるため、大きな変更でも軽快です。**統合**と**並べて表示**のレイアウトを切り替えられ、Specrails は選択を記憶します。非常に大きなファイルは先頭の行を表示し、**ファイル全体の差分を読み込む**で続きを読み込めます。バイナリファイルはバイナリとして表示されます。

変更は、納品がベースブランチから分岐した地点から測定されるため、その後ベースに入った内容は表示されません。納品にまとめたブランチがまだない場合は、どのスペックのブランチを読むか選べます。

## コードに対するレビュアーのメモ

レビュアーの指摘、示されたリスク、実行が解決するために起動されたレビューコメントは、対象の行の下に表示されます。ファイルも行も示していないメモはファイル一覧の上に並ぶため、何も隠れません。古い納品や、場所を示さなかったレビュアーの指摘は、この一覧に表示されます。

## エージェントに変更を依頼する

行番号をクリックして行を選び（Shift クリックで範囲を広げます）、**エージェントに変更を依頼**を選んで変更内容を書きます。Specrails はファイル、行範囲、選択したコードとともに、レビューフィードバックとしてスペックに保存し、スペックへのリンク付きのメッセージを表示します。そのスペックの次回の実行に反映されます。すぐ実行するには、概要の**変更を依頼**を使います。ここには人同士のコメントスレッドはありません。チームとの議論は GitHub で行ってください。

## エディターで開く

**エディターで開く**は、選択した行でファイルを VS Code、Cursor、または JetBrains IDE で開きます。エディターは**設定 → コード → エディター**で選べます。ファイルはお使いのプロジェクトのチェックアウトから開かれ、レビュー対象のブランチがそこでチェックアウトされていない場合があります。

## キーボード

| キー | 操作 |
| --- | --- |
| `j` / `k` | 次 / 前の変更ファイル |
| `n` / `p` | 次 / 前のレビュアーのメモ |
| `v` | ファイルを確認済みにする |

入力欄に入力している間、これらのキーは無視されます。確認済みの印はあなただけのものです。後のリビジョンでファイルが変わると**確認後に変更されました**と表示され、再び未確認として数えられます。
