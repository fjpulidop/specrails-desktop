# ダッシュボードツアー

プロジェクトを追加したあなたが今見ているのが、**プロジェクトダッシュボード** — スペックを出荷済みのコードへと変えていくための拠点です。それでは、画面の見方を案内しましょう。

## 全体像

ウィンドウは 3 つのゾーンに分かれています。

- **左サイドバー** — プロジェクトの一覧です。どのプロジェクトをクリックしても瞬時に切り替わり、ウィンドウのほかの部分もそれに合わせて更新されます。**プロジェクトを追加** ボタンもここにあります。
- **メインエリア** — アクティブなプロジェクトのダッシュボードです。スペックと、それを実行するパイプラインが表示されます。
- **右サイドバー** — 現在のプロジェクトの各セクション間を移動するためのナビゲーションです。

## メインダッシュボード

ここが作業の中心です。ダッシュボードには次のものが表示されます。

- **スペック** — あなたが作成したスペックが、ステータス（Backlog/Todo から完了まで）ごとに整理されています。リスト、グリッド、付箋カードのいずれか、お好みの表示で見られます。
- **スペックの追加手段** — 新しい作業を始めます。クイックなスペックを直接書くことも、会話を通して形を整え、スペックの下書きまで仕上げてくれるガイド付きの **Explore** チャットを開くこともできます。
- **レール** — スペックが実装されるレーンです。レールにスペックを置いて起動すると、Architect → Developer → Reviewer → Ship パイプラインに送られます。複数のレールを同時に走らせられるので、いくつもの作業を並行して進められます。

スペックが実行中のときは、そのパイプラインの進捗とライブログ — 設計・実装・レビューをしている AI のリアルタイム出力 — が表示されます。

## 右サイドバー: プロジェクトのセクション

右サイドバーは、現在のプロジェクトの切り替えスイッチです。ホバーすると展開し、開いたままピン留めもできます。表示されるセクションは次のとおりです。

- **ダッシュボード** — スペックボードとレール（さきほどまでいた場所）です。
- **ジョブ** — このプロジェクトのすべてのパイプライン実行を、過去・現在を問わず一覧表示します。ステータス・所要時間が分かり、任意の実行の詳細やログを掘り下げられます。
- **インテグレーション** — 任意のアドオンです。スペックを **Jira** ボードに接続したり、AI 向けの追加ツールを有効にしたりできます。
- **設定** — プロジェクトごとのオプション（テレメトリ、予算、プロバイダー設定など）です。

## ステータスバー

ウィンドウのいちばん下に、細い帯が走っています。ミッションモードでもボードモードでも同じ見た目で、控えめです。伝えることがないときは、その場所は単に空のままです。

- **接続**（左） — すべて正常なあいだは空です。アプリがローカルサーバーを見失ったときだけ *再接続中…*（黄色）または *オフライン*（赤）と表示し、再接続した直後に少しのあいだ *同期中…* と表示します。
- **アップデート**（右） — 新しいバージョンの準備ができ、アプリが約30秒操作されていないときに表示されます。クリックするとアップデートカードが開きます（[アップデート](../settings/6-updates.md) を参照）。
- **プラン使用量**（右） — 上限にいちばん近いプロバイダーを示す1つのメーターです。80% まではニュートラルな色のままで、80% からはプロバイダー名つきで黄色、90% からは赤になり、プロバイダーがリクエストを拒否しているときは *上限 · 15:00 にリセット* と表示します。ホバーまたはクリックすると、各プロバイダーのウィンドウと、このプロジェクトでの今日の支出が表示されます。
- **アプリのリソース**（右） — 作業が実行中のときだけ、アイコンとプロセス数を表示します。クリックすると、CPU とメモリ、メモリの推移、ソース別の内訳（ミッションとチャット、レール・ループ・ジョブ、バックグラウンドプロセス、ターミナル、エージェント CLI、MCP とランナー、Git、そして Specrails サーバー自体）が表示されます。ソースを展開すると、そのプロセスが見られます。ソースの下の**実行 worktree のポート**には、各レールの開発サーバーやテストサーバーが使っているポート（レール、スペック、プロジェクト、プロセス）が表示され、別のプロセスがレールに割り当てられたポートを使っていると警告します。デスクトップアプリでは **コンピューターをスリープさせない** もここにあります。オンのあいだは、ステータスバーのカップのアイコンがそれを示します（クリックすると再びスリープを許可します）。
- **ターミナル切り替え**（いちばん右） — 内蔵のターミナルパネルを開きます。**Cmd+J**（macOS）または **Ctrl+J**（Windows/Linux）でいつでも開閉できます。プロジェクトフォルダで開く、本格的なシェルです。

## 独立したウィンドウ

デスクトップアプリでは、一部の画面がメインウィンドウ内のパネルではなく、本物のウィンドウとして開きます。**設定**、ミッションから開いたジョブの詳細、そしてミッションモードの **Loops** と **プラグイン** です。これらは別の画面に移動させ、メインウィンドウで作業を続けられます。どのウィンドウもシステム標準のウィンドウコントロールを使い、設定とジョブのウィンドウは **Escape** でも閉じられます。テーマや言語など、そこで行った変更はすぐにメインウィンドウに反映されます。ブラウザ版では、これらの画面はパネルとして開きます。

## あなたを待っていることの通知 {#attention}

Specrails は、あなたを待っていることがあると知らせます：質問やミッションの返信、判断待ちのレビュー、失敗・ブロック・停止した実行、支出の上限、完了したジョブ。知らせ方はあなたの居場所によって変わります。

- **アプリから離れているとき** — プロジェクト名と原因を含むシステム通知。デスクトップアプリではクリックできないため、戻ったときにトーストがまとめて知らせ（**3 件があなたを待っています**）、その項目を開きます。複数あるときは **対応待ち** を開きます。**中断したところから再開** やプラットフォームツアーが開いているあいだに届いたトーストは、それを閉じるまで待ち、閉じたあとにまとめて 1 つとして届きます。
- **アプリの別の場所にいるとき** — **開く** 付きの小さなトースト。
- **すでに見ているとき** — 何もしません。見ているミッションは自分の返信を通知しません。止まった実行だけは例外で、常に知らせます。

受信トレイの項目の新しい状態は一度だけ知らせます。再起動しても古いものを再び知らせることはありません。受信トレイでは、まだ見ていない項目に点が付きます。**未読にする** と **既読にする** で切り替えられます。デスクトップアプリでは、Dock のアイコン（Linux ではランチャー）に、まだ見ていない項目数が表示されます。

何を知らせるかは **設定 ▸ 通知** で選べます：すべてオフにする、カテゴリ（質問と返信、レビュー、失敗、支出の上限、完了したジョブ）を選ぶ、サウンドを鳴らす、Dock バッジを隠す、プロジェクトをオフにする。受信トレイでプロジェクト名の横にあるベルでもミュートできます。その項目は受信トレイに残ります。

## ライブボード {#live-board}

**ライブボード**は、すべてのプロジェクトのすべての実行（レール、ループ、Intent セッション、ジョブ）を 1 か所に表示します。左サイドバーの**ライブボード**、**Cmd+Shift+B**（Windows と Linux では **Ctrl+Shift+B**）、またはコマンドパレットの**ライブボードを開く**で開きます。リンク（`?live=1`）でもあるので、**戻る**で閉じます。

ヘッダーの切り替えで表示を選べます（選択は記憶されます）。

- **状態別**：4 つの列。**あなたの対応待ち**は受信トレイの一覧（質問、失敗、ブロックされた実行、支出上限、Jira 更新）そのもので、古い順に並びます。**進行中**には実行中のもの、続いてキュー待ちのものが入ります。**判断待ち**にはレビューできる作業が入ります。**今日完了**には今日完了、マージ、停止したものが入り、深夜 0 時にクリアされます。1 つの実行が複数の列に出ることはありません。
- **ミッション別**：ミッションごとに 1 行で、そのミッションが開始したすべての実行、プロジェクト、エンジン、実行数、今日の支出を表示します。対応が必要なミッションが先頭に来て、どのミッションからも開始されていない実行は最後の**ミッション外**にまとまります。

各カードには、実行の状態、プロジェクト、レールまたは種類、タイトル、現在の作業、ステップ（ある場合）、エンジン、実行中または待機中の時間、わかっている場合はコストが表示されます。質問はその本文を表示します。カードのボタンはアプリの他の場所と同じ操作です：**回答**、**レビューを開く**、**再開**、**再試行**、**上限を引き上げる**、または実行を開始したミッションか実行そのものを開く**開く**。プロジェクト、種類（レール、ループ、Intent、ジョブ）、エンジンで絞り込めます。ヘッダーには対応待ちの数、進行中の数、今日の支出がまとめて表示されます。

デスクトップアプリでは、ボードは常に専用ウィンドウで開き、2 台目の画面に置けます。どの方法で開いてもそのウィンドウが前面に出て、**Cmd+Shift+B** で表示・非表示を切り替えます。そのボタンはメインウィンドウで動作し、メインウィンドウが前面に出ます。

## 便利なショートカット {#shortcuts}

- **Cmd/Ctrl+B** — 左サイドバーをピン留め／折りたたみます。**Option+Cmd+B**（**Ctrl+Alt+B**）は右サイドバーに同じ操作をします。
- **Cmd/Ctrl+J** — ターミナルパネルを開閉します。
- **Cmd/Ctrl+K** — コマンドパレット。ミッション、プロジェクト、ジョブを検索し、**アクションを実行**できます。動詞（「新規」「起動」「移動」「切り替え」など）を入力するか、**>** で始めるとアクションが一覧表示されます。新しい Spec（探索モードも可）、Spec の起動・移動、そのレビューを開く、Intent の引き継ぎ・一時停止、新しいミッション、テーマの切り替え、ミッションモードとボードモードの切り替え、アプリ設定・プロジェクト設定を特定のセクションで開く、ループの実行、サイドバーの切り替え、戻る・進む、直前の変更を元に戻す、最近削除した項目、などです。選択が必要なアクション（Rail、ステータス、テーマ、セクション）は 2 ページ目を開きます。検索欄が空のときに **Backspace** を押すと戻ります。各アクションにはキーボードショートカットが表示されるので、パレットがキーを教えてくれます。今いる場所で使えるものだけが表示され、ボタンと同じルールに従います（起動できない Spec は表示されません）。検索欄が空のときは、**最近のアクション**と**最近の場所**が表示されます。
- **Cmd+[ / Cmd+]**（Windows/Linux では **Alt+← / Alt+→**）、タイトルバーの **←  →** ボタン、またはマウスの戻る/進むボタン — 訪れた場所（スペック、ミッション、ジョブ、プロジェクト、全画面パネル）を戻ったり進んだりします。ボタンを右クリック（または長押し）すると最近の場所が表示されます。
- **Cmd+Shift+I**（Windows と Linux では **Ctrl+Alt+I**）またはタイトルバーの**対応待ち**ボタン — **対応待ち**リスト：すべてのプロジェクトであなたを待っているものを、プロジェクトごとにまとめた 1 つのリストで表示します。判断できるレビュー、エージェントが待っている質問、失敗またはブロックされた実行、1 日の予算で一時停止した実行、同期できなかった Jira の更新を集めます。各行にはその場で使える主な操作（**レビューを開く**、**回答**、**再開**、**再試行**）に加え、**後で通知**（1 時間または明日まで）と**完了**があります。後回しにした項目や完了した項目は、状態が変わると自動的に戻ります。ボタンには待機中の件数が表示され、プロバイダーの上限通知からもリストを開けます。このリストはリンク（`?inbox=1`）でもあり、コマンドパレットの操作でもあります。
- **M** — ボード上でスペックカードにフォーカスしているときに、ステータスやレールへ移動する選択画面を開きます。ドラッグ&ドロップのキーボード版で、複数選択にも使え、パレットでは**フォーカス中のスペックを移動…**として表示されます。
- **?** — ショートカットの一覧。検索ボックスに入力すると、ショートカットを絞り込めるほか、このガイドの該当するページやセクションも見つかり、画面を離れずにガイドで開けます。設定、レール、Intent、コンテキストスライダー、予算の横にある小さな **ⓘ** アイコンや**詳しく見る**リンクも、同じ方法で対応するセクションを開きます。

## 次に向かう先

これで全体像はつかめました。ここからの自然な第一歩は、**スペックを追加** してレールで起動し、パイプラインが最初から最後まで走る様子を眺め、それから **分析** でコストを確認してみることです。ようこそ、specrails へ。
