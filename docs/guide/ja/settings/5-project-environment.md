# プロジェクト環境

プロジェクトによっては、プライベート npm パッケージ用の `NODE_AUTH_TOKEN` のように、実行時に認証情報が必要です。**プロジェクト設定 → 環境** で、rail と loop が必要とする変数の**名前**を追加します。Specrails が保存するのは名前だけで、値は保存しません。

## 値の取得元

実行の開始時に、Specrails は起動時の環境から設定済みの各名前を読み取ります。Dock や Finder から Specrails を開いた場合、その環境にはシェルのプロファイルが export する内容が含まれません。そのため Specrails は、不足している名前をログインシェル（例: `~/.zprofile` や `~/.zshrc`）からも読み取ります。実際の認証情報はリポジトリではなく、シェルのプロファイルに置いてください。

確認はプロジェクトを開いたとき、名前を変更したとき、その後も定期的にバックグラウンドで行われるため、プロファイルが遅くても実行は遅れません。値はそのプロジェクトのメモリ内にのみ保持されます。

## ステータスチップの見方

保存した各名前にチップが表示されます。

| チップ | 意味 | 対処 |
|--------|------|------|
| **継承** | Specrails はその変数を持って起動しました。 | 不要です。 |
| **ログインシェルから取得** | Specrails がログインシェルから読み取りました。 | 不要です。 |
| **未定義** | ログインシェルがその変数を export していません。 | シェルのプロファイルに `export` を追加します。 |
| **シェルがタイムアウト** | ログインシェルの起動に時間がかかりすぎました。 | プロファイルを軽くするか、`SPECRAILS_LOGIN_SHELL_TIMEOUT_MS`（既定は 10 秒）を増やします。 |
| **シェルの読み取りに失敗** | Specrails がログインシェルを読み取れませんでした。 | プロファイルを修正するか、ターミナルから Specrails を起動します。 |

チップにカーソルを合わせると説明が表示されます。プロファイルを修正したら **再確認** をクリックしてください。Specrails の再起動は不要です。

名前が未解決のまま実行が始まると、そのログに変数名とステータスを示す `[environment]` 行が 1 行表示されます。実行はそのまま開始されます。値がアプリ、ログ、MCP ツールに表示されることはありません。

Windows では、Specrails は起動時の環境のみを使用します。
