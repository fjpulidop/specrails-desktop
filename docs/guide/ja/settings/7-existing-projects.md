# 既存プロジェクトでの作業

これらの機能は、既存プロジェクトを実行が尊重するのを助けます。スペックが対象外とすること、計画前のアーキテクトの質問、テストが実際に実証する要件、変更前に既存コードを記述する方法、そしてチームが既に書き留めているルールです。各機能には対応する specrails-core のバージョンが必要です。それまでは、Core の更新を促す注記付きでスイッチがグレー表示されます。

## 対象外

各スペックには、意図的に変更**しない**ことを列挙できます。Quick と Explore が自動で記入します。スペックのウィンドウでは説明の下に **対象外** として 1 行に 1 項目で表示され、他の項目と同様に編集できます。エージェントは起動のたびにスペックとともにこれを受け取ります。

## Jira でのアーキテクトの質問

**設定 ▸ 既存プロジェクトへの定着** で **アーキテクトの確認事項を Jira に投稿** をオンにします。アーキテクトの回答待ちで実行が止まったとき、または前提を置いて続行したとき、Specrails はそれらをリンクされた Jira 課題に 1 件のコメントとして投稿します。Jira でそのコメントに返信すると、返信は確認事項としてスペックに追加され、次回の実行で読み込まれます。一時停止した実行にはアプリからも回答できます。

## 実証済みの要件

テストが実証する要件をタイトルで示すと（`[spec:<ケイパビリティ>/<要件>]`）、レビューページに **実証済みの要件 X/Y** が表示されます。成功したテストが実証する要件、まだテストがない要件、変更自体が触れた要件がわかります。分析画面ではループごとに同じ情報を表示します。変更された要件にテストがない場合に CI を失敗させるには、テストの後に `specrails-core pipeline trace --check --tests-passed` を追加します。

ループライブラリには **ドリフト検査** もあります。各スペックの記述とコードの動作を比較し、矛盾をすべて一覧表示する読み取り専用のループで、何も変更しません。

## 変更時のベースライン

**変更時のベースライン** をオンにすると、どのスペックにも記述されていないコードに変更が及ぶ場合、まずそのコードを記述します。変更前のコードで実証した現在の動作のテストと、既存部分の短いスペックです。レビューページには、モジュール、要件、テストとともに **作業が触れた箇所にスペックを作成** が表示され、そのコストは変更とは別に示されます。変更前のコードでそれらのテストが失敗した場合、実行はモジュールを編集する前に停止し、その旨を示します。

## プロジェクトルール

**設定 ▸ プロジェクトルール** には、プロジェクトが既に実行しているチェック（lint、型、テスト、CI）と、`CLAUDE.md` や `AGENTS.md` などに書かれた各ルールが次のように分類されて表示されます。

- **適用済み**：既にチェックで保証されています。
- **自動化可能**：チェックで保証できます。**スペックを作成** で 1 クリックでスペックにできます。
- **人による確認のみ**：誰かが確認する必要があります。各レビューページの **人の目による確認が必要** に表示されます。

Core がまだ分類できていないルール（たとえばプロジェクト追加直後、インベントリがオフラインで実行された場合）は **未分類** と表示されます。プロバイダーを設定して **インベントリを再実行** すると分類されます。

**インベントリを再実行** で一覧を更新します。プロジェクトにまだ検証コマンドがない場合、エージェントランタイム設定でこれらのチェックが最初に提案されます。
