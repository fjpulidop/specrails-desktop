# ローカルサーバーが停止したとき {#server-recovery}

Specrails はコンピューター上で小さなサーバーを動かし、プロジェクト、レール、ミッション、ターミナルを動作させています。デスクトップアプリはこのサーバーを見守り、停止したら復旧させます。

## サーバーが停止したときに起きること

- **Specrails が自動で再起動します。** サーバーは同じアドレスで復帰し、開いているウィンドウは自動で再接続します。ステータスバーには数秒間 **再接続中** と表示されます。
- **バナーで何が起きたかを説明します**: サーバーがいつ、なぜ（終了コードまたはシグナル）停止したか。その時点で実行中だった作業は中断された可能性があります。状態を確認し、必要なら再実行してください。
- **再起動は 1 分間に最大 3 回です。** サーバーが停止を繰り返す場合、問題を隠さないよう Specrails は再起動をやめ、ダイアログを表示します。**Try again** で今すぐ起動するか、Specrails を終了して開き直してください。保存済みのプロジェクトはディスクに残ります。
- **次回の起動時にも説明します。** サーバーが停止したまま Specrails を閉じた場合、次に開いたときにバナーが表示されます。

読み終えたらバナーの **閉じる** を選んでください。同じ停止について再表示されることはありません。

## 問題を報告 {#report-a-problem}

**問題を報告** は、何がうまくいかなかったかを理解する助けになる ZIP をコンピューターに保存します。アップロードは行われません。共有するかどうか、誰と共有するかはあなたが決めます。

開き方:

- バナーの **問題を報告**
- **設定 ▸ 概要 ▸ 問題を報告**
- コマンドパレット（**⌘K**）で *問題を報告* と入力

保存する前に、ウィンドウにはレポートのすべてのファイルとその内容が表示されます。ZIP には表示されたものがそのまま入ります:

| ファイル | 内容 |
| --- | --- |
| `README.txt` | レポートの説明と各ファイルの内容 |
| `system.json` | アプリと Core のバージョン、OS、メモリ |
| `settings.json` | アプリの設定（トークン、キー、パスワード、環境変数の値、ヘッダーは除外） |
| `server.log` | 起動以降の実行中サーバーの出力 |
| `sidecar-stderr.log` | 停止した以前の実行を含む、サーバーの最近のエラー出力（デスクトップアプリ） |
| `desktop.log` | サーバーの起動、停止、再起動の記録（デスクトップアプリ） |
| `crashes.json` | 予期しない停止ごとの記録と最後のエラー行 |
| `stalls.json` | サーバーが応答できなかった時間 |

トークン、API キー、パスワード、秘密鍵、URL 内の認証情報は `[REDACTED]` に置き換えられ、ホームフォルダーは `~` と表示されます。それでも共有する前にファイルを読んでください。非公開にしたいプロジェクト名やファイル名が含まれることがあります。

## 応答性 {#responsiveness}

ステータスバーの **リソース** ポップオーバーには **応答性** も表示されます。サーバーが 200 ms 以上応答できなかった回数、その最長時間、そのとき何をしていたかがわかります。長い停止が頻繁に起きる場合は、レポートを送る価値があります。
